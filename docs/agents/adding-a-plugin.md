# Adding or removing a plugin

The rules in the root `AGENTS.md` still apply; this file holds what only adding, removing or publishing a plugin needs.

- `npm run plugin:new -- <name> [description]` scaffolds from `scripts/plugin-template/` and generates the typings. Names are lowercase words joined by hyphens, 26 characters at most (so `mcp__<name>__<tool>` fits in 64). The scaffold has a sample tool, pure logic with its test and the host fake `tests/host.ts`: replace the sample, fill the texts, run the checks under "Done for a plugin change" in the root `AGENTS.md`. Template changes keep `scripts/new-plugin.test.mjs` passing.
- A plugin that ships only skills has no `hooks/` and no `tsconfig.json`: write its manifest, `skills/<name>/SKILL.md` and docs by hand. `claude plugin test` and `tsc` skip it (CI and the npm tasks), and check-consistency requires a skill instead.
- `node scripts/check-consistency.mjs` is the checklist: manifest and marketplace entry with the same description, a valid `hooks/hooks.json`, a `tsconfig.json` that extends the generated typings and sets `noEmit`, `AGENTS.md`, `README.md` and no plugin-root `CLAUDE.md`, the test files and names the plugin's `AGENTS.md` cites, the backticked `plugins/<name>/AGENTS.md` under "Where to look" in the root `AGENTS.md`, the root README table row and install line, the `ALL` list of `scripts/bootstrap.sh` (`plugin:new` updates it), the template copies of `hooks/schema.ts` and `tests/schema-types.ts`, each skill's frontmatter naming its folder, and skills' `<!-- shared: <block> -->` blocks, identical across a plugin's skills and at most 1,600 words (`SHARED_BLOCK_WORDS`), since each skill loads its copy on every call: what not every run needs goes to a file the skill links. It fails on orphans (a plugin directory with no marketplace or `unlisted.json` entry). Repository-wide, it also checks that the Claude Code CLI `package.json` pins is the version the root README says the repository is checked with, and that the chatgpt README names the default model `DEFAULT_CHOICE` picks.
- Unlisted plugins: a name in `.claude-plugin/unlisted.json` (a JSON array) keeps a plugin out of the marketplace while it is validated. check-consistency checks it like any other but requires that it have no marketplace entry, no root README row or install line and no place in the `ALL` list of `scripts/bootstrap.sh`; CI and the npm tasks still validate and test it. Load it with `--plugin-dir` or `CLAUDE_CODE_PLUGIN_DIRS`, which reads its options from `pluginConfigs["<name>@inline"]`. To publish it, move the name into the marketplace and add those three.
