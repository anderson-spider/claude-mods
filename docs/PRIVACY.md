# Privacy and permissions

What each plugin reads, saves and sends. Everything stays on your machine except where a section says otherwise.

## chatgpt

- **Sent:** the prompt, and any files you attach, go to chatgpt.com through the tab of your logged-in browser (terminal-browser). The plugin never sees your ChatGPT credentials; it drives the page you are already signed in to.
- **Saved:** answers are written to `$TMPDIR/chatgpt/` (`/tmp/chatgpt/` when `TMPDIR` is unset). Generated images are written there too, with a JPEG preview. The first line of an answer file is the chat URL.
- **Read:** `TMPDIR`, and the files you pass as attachments.
- **Kept in memory:** the list of background jobs, until a reload.

## codex-computer-use

- **Read:** the newest `~/.codex/plugins/cache/openai-bundled/unified-computer-use/<version>/.mcp.json`, to start the computer-use server. Environment values are never printed.
- **Saved by the helper** (`~/.claude/mcp/codex-cu/state/`): `approvals.json`, the apps you answered "always" for, and `helper.log`, which records the bundle id and your choice for each approval.
- **Saved by Codex:** answering "always" makes Codex save the app in its own `ComputerUseAppApprovals.json`. `/codex-cu forget` removes the app from both files; the plugin only ever removes from Codex's file.
- **Not stored:** what you see in the apps. The helper passes screen content between Claude and the computer-use server and keeps none of it.
- The helper listens on a Unix socket under `~/.claude/mcp/codex-cu/run/`, readable by your user only. Auto-approve is off by default.

## codex-models

- **Sent:** a session or subagent that uses a Codex model sends its conversation, including what its tools read from the repository, through the local proxy to OpenAI's Codex backend (`chatgpt.com`), under your ChatGPT login. Claude models go through the same proxy to `api.anthropic.com` unchanged, with your usual Claude Code login. Besides those calls, the proxy talks to OpenAI's sign-in server (`auth.openai.com`) for the ChatGPT login: once when you run `ccmproxy login codex`, and to refresh the access token with the stored refresh token when a Codex request finds it within 5 minutes of expiry. It sends one more request only when asked: `GET /__ccmproxy/status?refresh=limits` (sent by the crew's quota routing, see below) may read the unofficial `wham/usage` endpoint at `chatgpt.com`, at most once every 5 minutes, with the access token the proxy already holds (it never starts a token refresh for it) and no prompt. A plain status never calls OpenAI. The plugin's hooks never send anything off the machine: the status check at session start, and `/codex-models:status`, only probe the local proxy at its loopback address (the session's base URL when that is loopback, else the configured listen address), with the proxy's secret.
- **Listens:** the proxy binds a loopback address only, on a random port chosen at install, and refuses any other listen address. A process on your machine that knows the secret can use it.
- **Saved:** `~/.claude/codex-models/` holds the proxy binary, its config (with the proxy's secret, `auth_token`), the ChatGPT credential file the proxy writes (mode 600) and the install state. `~/.claude/settings.json` holds the same secret as an `X-Ccmproxy-Token` line in `env.ANTHROPIC_CUSTOM_HEADERS`. Each install or uninstall that changes that file leaves a backup, `~/.claude/settings.json.bak-codex-models-<timestamp>` (mode 600), which can hold the same line; the scripts never delete backups. The state file records what was in `settings.json` before, without the secret.
- **Read:** the proxy reads `~/.codex/auth.json` only when `codex.use_codex_cli_auth` is set (default off), and never writes or refreshes it. The installer reads `~/.claude/settings.json` to merge its entries, and the session start probe reads the proxy's base URL and secret from the session's environment.
- **Logged:** the proxy logs method, path, status, sizes and duration; never query strings (so `?refresh=limits` is not logged), the secret, tokens, prompts or the message text of a Codex error. An outbound error's logged text has the URL's query and userinfo cut. The log is `~/.claude/codex-models/home/log/ccmproxy.log`; at start it names the ChatGPT account (its email, or the account id) and plan, and the credential file in use. The status keeps the latest Codex rate-limit readings (percent used, window length, reset time) in memory only.
- **Removed:** `~/.claude/codex-models/uninstall.sh` takes back the `settings.json` entries and stops the LaunchAgent; `uninstall.sh --purge` also deletes `~/.claude/codex-models/` (the login, the config and the binary). `ccmproxy logout codex` removes only the proxy's own ChatGPT credentials.

## crew

Jev routing runs only when the `jevKey` option is filled in; with it empty, nothing is sent and no settings are read. The key is kept in Claude Code's secure storage (the option is marked sensitive), not in a settings file. Whether `$.config.list()` returns a sensitive value to other plugins is unverified. The key is checked once per activation (a `/reload-plugins` or an option change resolves it again), on the first request (the lead's prompt section names Jev only when there is one). The agents themselves read and send nothing.

- **Sent** (only with `jevKey` set, one request per `crew:*` Agent call that does not name a model and is not a fork or a workflow script's agent, to `https://api.typesafe.ai/v1/systemone`): the agent name, the call's description and its prompt. Secrets in common shapes, emails and absolute paths are removed first (paths under the repository become relative, your home becomes `~`; when no home can be trusted, the user's home under `/Users` or `/home` in the session's directory stands in for it), and the prompt is cut to 4000 characters.
- **Read:** the `jevKey` option, and `HOME`. The environment variables `TYPESAFE_API_KEY` and `JEV_API_KEY` and `~/.jev-router.env` are not read. A `jevKey` declared by the repository's project or local settings turns routing off entirely; a `HOME` declared there is ignored (the home is also skipped when it is not absolute), and when those settings cannot be read routing is off completely. A key that is not printable ASCII without spaces, or longer than 512 characters, is not used. The key is sent only in the `Authorization` header and is never logged. The settings of the repository are read only when a key is set, to check that it does not declare `jevKey`.
- **Shown** (only with `jevKey` set): on a routed subagent's first answered step, one transcript line with the call's description and the model and effort it ran on; like every transcript line it is also written to the debug log.
- **Saved** (only with `jevKey` set): each decision for an Agent call goes to the debug log of the session, without the prompt, and to one small JSON file in `~/.claude/crew/decisions/` (the home that was trusted for the key, never the repository's). The file holds the time, agent name, the type the lead asked for and the provider, tier, confidence, depth, default and final model, default, planned and applied effort, what the first step ran on (the model id the API reported and the effort sent), Jev model id, duration and a short non-cryptographic hash of the call description (to match cases without keeping the text; a short, common description can be guessed from it); never the prompt, the description, the key or a path. Nothing in it leaves the machine, and the plugin never prunes it (about 400 bytes of JSON, one file each (a disk block on most file systems)). To delete it: `rm -r ~/.claude/crew/decisions`.
- **Kept in memory:** the resolved key and home, the effort chosen for each routed subagent and the state of the breaker, until a reload (changing any of the plugin's options reloads it).

Quota-aware routing (the `quotaRouting` option, off by default) needs registered `-codex` twins. It reads Claude's limits from the host and, from the local proxy, `GET /__ccmproxy/status` with the `X-Ccmproxy-Token` secret taken from `ANTHROPIC_CUSTOM_HEADERS`: only when `ANTHROPIC_BASE_URL` is an `http` URL on a loopback address, and never to any other host. The request is `GET /__ccmproxy/status?refresh=limits`: only a status request with `?refresh=limits` makes the proxy read the Codex usage from OpenAI (`wham/usage`), and crew sends it only when it reads the Codex quota (the option on and twins registered). With crew off or `quotaRouting` off, nothing new goes to OpenAI. The plugin keeps the readings and the decision in the session's state (the `quota` atom, which any plugin can read) and sends nothing to Jev or anywhere else for this. On that request the proxy asks OpenAI for the Codex usage at most once every 5 minutes (only when its readings are older), with the ChatGPT login and no prompt. When the decision is Codex, the call becomes `crew:<role>-codex` and what that subagent reads and writes goes to OpenAI through the proxy, as for any twin. With a `jevKey` set, the decision record (see Saved above) then also holds the reason and both providers' usage percentages and reset times (no prompt, description or path); without a key no record is written.

The HUD (always on) sends nothing out and writes nothing to disk except the panel choice (below). It keeps the following in the session's state: the first line of each prompt (up to 300 terminal columns, secrets in common shapes removed), a summary of each tool call (the file, command or pattern, cut short, with secrets in common shapes removed), each subagent's description (up to 300 terminal columns) and, for the architect and the advisor tool, the first line of its answer (up to 160 terminal columns), denied tool calls and the permission dialogs still waiting (which agent and tool), the model, effort, context and cost figures, the active plan read from `<project root>/.crew/plans/` (each step's id, owner, dependencies, text, state and note, not cut) and a session log of the last 60 lines. It reads the plan files in the project root's `.crew/plans/`. Any plugin can read this state while the session runs. `/clear` and `/crew:panel reset` empty the agent, consult, log and loop entries, the turn counters and the open detail, and reset the main session's steps and running flag; they keep the plan, its pin and the panel choice. The only thing kept across sessions is the panel choice (shown or hidden, side or prompt, as `{v, isVisible, placement}` under the plugin's `$.store` key `panel`), which Claude Code's plugin store keeps; it holds no session content.

## tailscale

- **Read:** `TS_API_KEY`, on every call. It is never taken from tool input.
- **Sent:** requests to the Tailscale API only.
- **Filtered:** read responses drop `machineKey`, `nodeKey`, `tailnetLockKey`, `secret`, `s3SecretAccessKey` and `token`, and any field whose name ends in `Key`, `Secret` or `Token`. Write responses are not filtered, because a new key's secret comes back once.
