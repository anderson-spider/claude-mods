# chatgpt

Setup, use, privacy or live browser checks: read [README.md](README.md). Editing backend choice or registration: read `tests/backends.test.ts` and `tests/register.test.ts` for the pinned behavior. Editing prompts: `tests/prompts.test.ts` pins the send boundaries, character budget and image boundaries, and the prompt texts byte for byte; `tests/tool-schemas.test.ts` pins the tool and command wording and the input schemas. A new page script gets its fake branch in `tests/fake-page.ts` (`scriptKind`, `fakePage`).

- `scripts.ts`: page scripts/selectors, the upload script and the chatgpt.com URLs; `tab.ts`: chat URLs, `findTab` and `prepare` (open and check the plugin's tab); `chooser.ts`: first working backend and the none-works text; `terminal-browser.ts`: injected `Browser` adapter. MCP backends: `mcp-call.ts` (`mcpCallOf`: `$.mcp.call` or `$.tool.call`), `tool-text.ts` (parse a tool's text), `upload.ts` (base64 and `uploadFiles`), `page-browser.ts` (`pageBrowser`, `pollUntil`: a `Page` becomes a `Browser`), `mcp-backend.ts` (`mcpBackend(spec)`, which builds an MCP backend's `Browser` and `stays` from one spec: name, server, hint, tab-id prefix, listing tools, tab protocol); `chrome-browser.ts`, `builtin-browser.ts`: those two specs. Modules with logic have a mirror test in `tests/`, except `tab.ts` (covered through `ask`, `doctor` and `register` tests) and `pageBrowser` (through the backend tests).
- `backends.ts`: the single `BACKENDS` list (the order the plugin tries them), `OWN_CALLS` and the pure `ownCallAllowed`: what `tool.check` allows, only the plugin's own browser calls on chatgpt.com, never the model's. Every backend has a `hint`: the chooser's setup advice and the "not ready" advice (`prepare`, which takes the names injected as `backends`, since `backends.ts` imports `tab.ts` through `mcp-backend.ts`) are built from the list, never written by hand. A new MCP backend is a spec in `backends.ts` (in a module of its own when its tab protocol is long, like the two there) and its row in `tests/backends.test.ts`, which pins its hint, the allow and deny cases and the advice over the real list; `tests/register.test.ts` pins the shipped texts byte for byte (`NO_BROWSER`, `NOT_READY_ADVICE`), so they change with a new backend. `README.md` lists the backends by hand.
- `register.tsx`: MCP calls, named `$.tool.register`/`$.command.register` calls, and the literal `on('tool.check', ...)` that passes the call's origin, tool, input and the plugin's tab to `ownCallAllowed` (`tests/register.test.ts` pins that wiring). `backends.ts` takes no `$`.
- `tool-schemas.ts`: schemas/jobs/commands; `prompts.ts`: ask/image descriptions and prompt section; `ask.ts`, `image.ts`, `conversation.ts`: flows; `runner.ts`: queue/jobs; `output.ts`: `$TMPDIR/chatgpt/` files.

Checks: `claude plugin validate plugins/chatgpt`; `claude plugin test plugins/chatgpt`; `node scripts/check-consistency.mjs`.
