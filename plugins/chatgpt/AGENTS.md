# chatgpt

Setup, use, privacy or live browser checks: read [README.md](README.md). Editing backend choice or registration: read `tests/backends.test.ts` and `tests/register.test.ts` for the pinned behavior. Editing prompts: `tests/prompts.test.ts` pins the send boundaries, character budget and image boundaries, and the prompt texts byte for byte; `tests/tool-schemas.test.ts` pins the tool and command wording and the input schemas; `tests/register.test.ts` pins what the host receives. Editing a flow (ask or image, from the request to the saved file and the job record): `tests/flows.test.ts` pins the texts, calls and files of both. A new page script gets its fake branch in `tests/fake-page.ts` (`scriptKind`, `fakePage`).

- `scripts.ts`: page scripts/selectors, the upload script and the chatgpt.com URLs; `tab.ts`: chat URLs, `findTab` (a kept tab id is moved only while its tab is on chatgpt.com or OpenAI's sign-in pages, else a new tab opens: a restarted browser can reuse the id; `tests/tab.test.ts`: `findTab leaves a listed tab that is on another site where it is and opens a tab of its own`) and `prepare` (open and check the plugin's tab; a `Browser` with `signIn` gets that advice on a logged-out page, and with `notReady` on any other page that is not ready, in place of the general one, a failure marked `held`); `chooser.ts`: first working backend and the none-works text; `terminal-browser.ts`: injected `Browser` adapter; `playwright-browser.ts`: the headless Chromium's adapter (`openPlaywright`, `signIn` for `/chatgpt-login`), which speaks to the helper over `$.http.fetch` with `socketPath` and starts it with `node <plugin root>/helper/helper.mjs start --home <home>/.claude/chatgpt/playwright` when it is down or older than the plugin; a newer one is used as is (`tests/playwright-browser.test.ts`). The `headlessChromium` setting (`plugin.json` `userConfig`, read by `register`) drops this backend from the list when off (`tests/register.test.ts`: `with "Headless Chromium first" off the headless Chromium is never tried, and the texts leave it out`). MCP backends: `mcp-call.ts` (`mcpCallOf`: `$.mcp.call` or `$.tool.call`), `tool-text.ts` (parse a tool's text), `upload.ts` (base64 and `uploadFiles`), `page-browser.ts` (`pageBrowser`, `pollUntil`: a `Page` becomes a `Browser`), `mcp-backend.ts` (`mcpBackend(spec)`, which builds an MCP backend's `Browser` and `stays` from one spec: name, server, hint, tab-id prefix, listing tools, tab protocol); `chrome-browser.ts`, `builtin-browser.ts`: those two specs. Every module with runtime code has a mirror test in `tests/`: `tab.ts` in `tab.test.ts`, `pageBrowser` in `page-browser.test.ts`, `flows.ts` in `flows.test.ts`; `model.ts` holds types only.
- `backends.ts`: the single `BACKENDS` list (the order the plugin tries them, the headless Chromium first; `backendsFor` moves the built-in browser right after it when `CLAUDE_CODE_ENTRYPOINT` is `claude-desktop`, and `register.tsx` reads that variable per request), `OWN_CALLS` and the pure `ownCallAllowed`: what `tool.check` allows, only the plugin's own browser calls on chatgpt.com, never the model's. Every backend has a `hint`: the chooser's setup advice and the "not ready" advice (`prepare`, which takes the names injected as `backends`, since `backends.ts` imports `tab.ts` through `mcp-backend.ts`) are built from the list, never written by hand. A new MCP backend is a spec in `backends.ts` (in a module of its own when its tab protocol is long, like the two there) and its row in `tests/backends.test.ts`, which pins its hint, the allow and deny cases and the advice over the real list; `tests/register.test.ts` pins the shipped texts byte for byte (`NO_BROWSER`, `NOT_READY_ADVICE`), so they change with a new backend. `README.md` lists the backends by hand.
- `helper/`: the headless Chromium, Node ESM run by the user's `node` (no build step), never imported by the hooks. `helper.mjs` is the CLI (`start`, `serve`, `stop`, `login`; every command but `serve` prints one JSON line); `lib/server.mjs`: the socket daemon and its `ROUTE_TABLE` (`/health`, `/tabs`, `/open`, `/wait`, `/eval`, `/upload`, plus `/stop`), idle exit after the `idleMs` it is given (`IDLE_MS` in `helper.mjs`, ten minutes). One `serve` per home holds `run/serve.lock` (its pid; a dead holder's lock is taken over), and only the holder touches the socket. Stopping lets requests in flight finish (`DRAIN_MS`), answers `/health` with `stopping` meanwhile, then closes the browser, the socket and the lock in that order, so no `start` takes the profile while the old browser holds it (`helper/test/server.test.mjs`: `a stopping daemon lets the request in flight finish, says stopping meanwhile, then closes the browser before the socket goes`). `lib/driver.mjs`: Playwright on the persistent profile, headless on the full build (`channel: 'chromium'`) with the user agent renamed from HeadlessChrome to Chrome, no `--enable-automation` and no `--use-mock-keychain` (the login window wrote its cookies with the real keychain); tab ids are `<instance>-<n>`, new per daemon, so a session's id from a stopped daemon never reaches another session's page; a page script gives up after `EVAL_MS`. `lib/login.mjs`: the plain sign-in window (no automation flag, no debugging port), after touching `run/login`. `lib/daemon.mjs`: `start` (keeps a daemon of this version or newer, replaces an older one, and spawns none while the profile's `SingletonLock` names a live Chromium or a login began less than `LOGIN_GRACE_MS` ago), `stop` and the socket client. `lib/install.mjs`: `playwright-core` pinned by `PLAYWRIGHT_VERSION` and `install chromium --no-shell`; `missing` wants Playwright's `INSTALLATION_COMPLETE` marker too, so a cut download is installed again. `lib/paths.mjs`: the folders under `--home`, the socket length limit and `profileHolder`. The helper's version is the plugin's (`lib/version.mjs` reads `plugin.json`), so a bump replaces an older running daemon. A route change touches `ROUTE_TABLE`, `playwright-browser.ts` and both test halves (`helper/test/server.test.mjs`, `tests/playwright-browser.test.ts`). The fake host of the register tests answers the helper's routes from the same page fake (`tests/register.test.ts`: `an ask runs on the headless Chromium once it is set up: the helper is started, then every page script goes through its socket`).
- `register.tsx`: MCP calls, one named `$.tool.register`/`$.command.register` call per tool and command (description and `inputSchema` from `TOOLS`; the engine's scan needs the literal names), the literal `tool.call` and `command.run` matchers, and the literal `on('tool.check', ...)` that passes the call's origin, tool, input and the plugin's tab to `ownCallAllowed` (`tests/register.test.ts` pins that wiring). `backends.ts` takes no `$`.
- `tool-schemas.ts`: the `TOOLS` registry (name, description, `inputSchema`, request `kind`, command, `commandRequest`) and the schema/command texts; `schema.ts`: the shared `SchemaFor` and `allOf` (`enum` slots take only `allOf` of exactly the union), a byte-for-byte copy of the template's that `scripts/check-consistency.mjs` enforces, with its type cases in `tests/schema-types.ts`; each `inputSchema` satisfies `SchemaFor` of its `McpToolInputs` entry in `types/index.d.ts`, so tsc fails on drift; `prompts.ts`: ask/image descriptions and prompt section; `output.ts`: `$TMPDIR/chatgpt/` files.
- `flows.ts`: the `FLOWS` table (each row's `run` and `save`) and `Kind`; `ask.ts`, `image.ts`: the run steps of each flow; `conversation.ts`: what they share, `openRun` (the saveOnly guard and the plugin's tab), `submit` (model and effort, files, the check of both, prompt), `watch` and the reads; an ask whose own exchange shows ChatGPT's dropped-connection status (`interrupted` in `stateScript`) ends at once as timed out, so the runner saves it in the background, while saving it (`saveOnly`) waits on (`tests/flows.test.ts`: `an ask whose answer loses its connection ends at once as timed out, with the chat url and the part so far`, `saving an answer whose connection dropped keeps waiting for it`); `choiceOf` is what a run picks: the named model, else `DEFAULT_CHOICE` (GPT-6 at medium) on a new chat, nothing on a follow-up; the `model` description in `tool-schemas.ts` is built from it, and `README.md` names it by hand, which `scripts/check-consistency.mjs` compares with `DEFAULT_CHOICE`. The page scripts of the model menu only list its rows and effort, click a row, step the effort slider and close the menu; `modelRow` and the effort walk decide in `conversation.ts`, so `tests/flows.test.ts` covers them through `fakeMenu` in `tests/fake-page.ts`, since the test runtime cannot run a page script; `runner.ts`: queue, jobs and `performRequest`, which dispatches through `FLOWS`; a `held` failure (the headless page that nobody can clear, before anything was sent) runs the request once more in the first other backend that opens, its answer starting with a `note`, while a logged-out page stays where it is (`tests/flows.test.ts`: `a page nobody can clear moves the request on to the next backend before anything is sent, and the answer says so`). `register.tsx` keeps each backend's own tab while another holds the plugin's tab, so the next request goes back to it (`tests/register.test.ts`: `a headless page held by something other than a login moves the ask on to the next backend, which keeps its own tab`). A new flow: its row in `FLOWS`, its run module, its `DONE_NOTE` entry in `presentation.ts` (a `Record<Kind, string>`, so the compiler asks for it), its texts, its `TOOLS` entry and its registration below, and its `McpToolInputs` entry in `types/index.d.ts`.
- New tool: one `TOOLS` entry, its `McpToolInputs` entry in `types/index.d.ts` (the `inputSchema` must satisfy it), its literal `$.tool.register` call in `session.start` and `tool.call` hook in `register.tsx`, then the wording in `tests/tool-schemas.test.ts` and the names in `tests/register.test.ts`.

Checks: `claude plugin validate --strict plugins/chatgpt`; `claude plugin test plugins/chatgpt`; `node --test plugins/chatgpt/helper/test/*.test.mjs`; `node scripts/check-consistency.mjs`; `npm run typecheck -- chatgpt`. A live check of the headless Chromium needs `/chatgpt-login` once, then `/chatgpt-doctor`.
