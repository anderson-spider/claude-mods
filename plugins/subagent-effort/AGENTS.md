# subagent-effort

Usage/privacy: [README.md](README.md). Each module has a mirror test in `tests/`; `tests/host.ts` is the fake host (`world`, `started`, `call`, `settle`), and fake coverage is not live routing evidence.

## Modules

- `hooks/register.tsx`: every `on(...)` and `$` call. `session.start` registers the `subagent-effort-stats` command; the `tool.call` hook on `Agent` routes the effort and its `.catch` dispatches the call as it came when routing fails; `turn.complete` ends background runs; `command.run` prints the Jev access of this session and the summary. Host access stays literal here and goes only to top-level functions of this file (`io`, `files`, `observe`, `record`, `accessLine`, `warnOff`, `dispatched`). The hook rewrites the `Agent` call, not `agent.spawn`, because the spawn takes a model but no effort. `tests/register.test.ts` (`Jev sets the effort of any native agent type, shown in its description, and leaves the model alone`, `a routing failure dispatches the call once as it came and writes no record`).
- `hooks/effort.ts`: the whole policy and the assessment: `QUESTION`, `EFFORTS` (one per criterion, `max` never), `POLICY`, `CALIBRATION` (bumped with any change to those three), `JEV_INPUT_USD_PER_MTOK` and `jevCostOf`, `levelOf`, `distribution`, `clipped` (key, then `redact`, then the 4000-character cut) and `assessEffort`. `tests/effort.test.ts`: `every assessment failure picks no effort, names the reason, and a logging failure changes nothing`.
- `hooks/ledger.ts`: pure line builders (`decisionLine`, `afterAgentCall`, `afterTurn`), `createPending`, `appendLine` (one process-wide queue, rotation at `ROTATE_AT`), `parseLedger`, `summarize`, `formatSummary` and `usd` (two significant digits, so a Jev cost of a few millionths of a dollar never shows as zero). `tests/ledger.test.ts`: `a decision line projects each field and drops anything that is not a plain word or a count`.
- `hooks/jev.ts`, `hooks/key.ts`, `hooks/redact.ts`: fixed endpoint, user-environment key only, whole-text redaction before clipping, deadline, retry, gate and breaker. `key.ts` also owns `OFFS`, `isOff` and the fix text of each reason (`OFF_TEXT`). `tests/key.test.ts` (`any repository env declaration of JEV_API_KEY is refused`).

## Invariants

- Only the effort changes: the model and every other field of the call pass as they came. Jev's effort replaces one the call came with; a fork and an empty task pass untouched; Jev off or failing, and any routing failure, dispatch the call as it came, its own effort included. `tests/register.test.ts` (`Jev replaces an effort the call came with, shows the one it replaced, and leaves the model alone`, `when Jev is off or fails, an effort the call came with goes as it came and is recorded as received and applied`, `a fork or an empty task passes untouched, unrouted and unrecorded`).
- A decision line records the effort the call came with (`received`) and the one applied (`effort`); null is the agent's usual effort. Its Jev fields (`jevMs`, `jevTokens` from the response's `usage`, `jevCostUsd` from `JEV_INPUT_USD_PER_MTOK` in `hooks/effort.ts`) cover the routing call alone, apart from the subagent's duration and tokens on the outcome line. `tests/effort.test.ts`: `the estimated Jev cost charges input tokens only, at the published rate`. `tests/ledger.test.ts`: `the summary groups outcomes by model family and effort, and counts decisions per source and the explicit efforts Jev replaced`.
- The ledger is the plugin's only file (`~/.claude/subagent-effort/routes.jsonl`, one rotated generation). A decision line goes in before dispatch, an outcome line after the host result (with the call's own model when the host reports none, and its background mode when it failed: `runsInBackground` in `hooks/ledger.ts`, the call's `run_in_background` or, for the main conversation in the desktop app or VS Code, always background), none when a hook or the permission check denied the call, which never ran (`tests/ledger.test.ts`: `the Agent result becomes a foreground outcome, a background launch, or nothing for a refusal or an unknown shape`); observation never changes the host result, and its failure is one fixed debug line. `tests/register.test.ts` (`observation survives a failing ledger: the dispatch and its result are unchanged and one debug line names the miss`, `in the desktop app or VS Code, where the main conversation's agents always run in background, an error is a background outcome`); `tests/ledger.test.ts`: `a call runs in background when it asks to, or when the desktop app or VS Code runs the main conversation there`.
- A line never holds the task, a prompt, an answer, a path or the key; the brief appears only as its length. `tests/register.test.ts`: `no line ever holds the task, a prompt, an answer, a path or the key`.
- The stats texts carry no plugin-name prefix: the host adds it. `tests/register.test.ts`: `the stats command checks Jev access the way routing does, summarizes the records and never prints the key`.
