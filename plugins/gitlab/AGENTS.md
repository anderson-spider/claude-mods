# gitlab

Usage/privacy: [README.md](README.md).
- `hooks/register.tsx`: each tool's literal `session.start` registration (`inputSchema ... satisfies SchemaFor<McpToolInputs[...]>`) and `tool.call` hook (with a `.catch` that answers an error), all sharing the top-level `run($, tool, input, option)`: remote (an SSH alias resolved through `ssh -G`), token, `project` (same host only), API, then the tool. `hooks/schema.ts`: the shared `SchemaFor` and `allOf` (`enum` slots take only `allOf` of exactly the union), a byte-for-byte copy of the template's that `scripts/check-consistency.mjs` enforces, with its type cases in `tests/schema-types.ts`; numbers are written as `integer` here. Action unions live in `types/index.d.ts`.
- `hooks/remote.ts`: `parseRemote`, `locate` (origin, else the first remote), `currentBranch`, `projectPath`, `sshHostname`, over injected git and ssh. `hooks/tokens.ts`: the `tokens` option as `host=token` pairs, `resolveToken` and the refusal texts. `hooks/api.ts`: `gitlab(fetch, host, project, token)`; every path is built from checked ids and the encoded project, never from the model; `page`/`rootPage` read `X-Next-Page`. `hooks/context.ts`: `Ctx` (`makeCtx`: the injected `clock`, `me` read once, `foreign` when `project` names another project), input checks, `paging` (`perPage` at most 100), `mrIid` (the current branch's open MR without an iid; never for a foreign project), `writable` (the guard below), `userIds` and `username` (`@me`), `clip`. `hooks/errors.ts`: the refusal text with what to do per status.
- Tools, one module each: `hooks/mr.ts`, `hooks/comments.ts`, `hooks/pipelines.ts`, `hooks/joblog.ts`, `hooks/labels.ts`, `hooks/users.ts` (`gitlab_user`: the token owner or a username). There is no generic API tool: a new need gets its own action or tool. Deleting comments, labels, branches or MRs is not offered: no tool has a delete action (merge's `removeSourceBranch` aside), and `tests/register.test.ts` (`session start registers the six tools, with a guarded merge and no generic API tool`) pins the tool set.
- Waiting: `gitlab_pipeline` `wait` polls every `POLL_MS` (15 s) for at most `minutes` (30 at most) through `ctx.clock`, whose `sleep` is a host `sleep` process so the hook spends none of its own time (`register.tsx`), and answers the failed jobs with `failureSnippet` (`joblog.ts`) for the first five (`tests/pipelines.test.ts` (`wait polls the latest pipeline every 15 seconds until it ends, then answers each failed job with an excerpt of its log, blocking ones first`, `wait stops at its time limit with the pipeline still running, and refuses more than 30 minutes before any call`, `wait reads the logs of the first five failed jobs and lists the rest for gitlab_job_log`); `tests/register.test.ts` (`wait sleeps through a host process between polls, so the hook spends none of its own time`)). `gitlab_mr_comment` `unresolved` reads up to twenty pages and answers only open threads in brief (`tests/comments.test.ts` (`unresolved reads every page and answers each open thread with its place, author, ask and last reply`, `unresolved stops after twenty pages and says where to go on, and cuts long bodies`)).
- Draft notes: `gitlab_mr_comment` with `draft: true` sends `comment`, `reply` (`in_reply_to_discussion_id`), `line` (the same position) and `edit` to `/draft_notes`, `draft` on any other action is refused, `drafts` lists them and `publish` posts one (`PUT .../publish`) or all (`bulk_publish`); drafts and publish are writes under the guard below (`tests/comments.test.ts` (`draft makes comment, reply, line and edit draft notes, drafts lists them and publish posts one or all`, `draft on an action that is not a comment write is refused before any request`)).
- Others' MRs: every write on an MR (`update`, `approve`, `unapprove`, `rebase`, `merge`, comment writes, an MR pipeline `run`) reads it first and is refused when its author is not the token's user, unless `allowOthers: true` (`tests/comments.test.ts` (`every write on someone else's MR is refused without allowOthers, and goes through with it`); `tests/mr.test.ts` (`update, approve, unapprove and rebase on someone else's MR are refused without allowOthers`, `merge refuses someone else's MR without allowOthers and merges it with allowOthers`); `tests/pipelines.test.ts` (`run of a merge request pipeline on someone else's MR needs allowOthers`)).
- Merge is guarded: an explicit `iid` and the full head `sha` (sent to GitLab, and compared first); refused for a draft, conflicts, blocking discussions or a closed MR whatever the flags; a `release*` target, or any protected one (`GET /repository/branches/:name`, refused when unreadable) other than main, master or develop, needs `allowProtectedTarget: true` (`tests/mr.test.ts` (`merge needs an explicit iid and the full head sha, and refuses a head that moved`, `merge refuses a draft, conflicts, blocking discussions or a closed MR, whatever the allow flags`, `merge into a release or protected branch needs allowProtectedTarget; main, master, develop and unprotected targets do not`, `merge is refused when GitLab will not say whether the target is protected`)).
- Labels an MR is about to get must exist: a missing one is refused by name unless `createMissingLabels: true` creates it first, so GitLab never makes one silently (`tests/mr.test.ts` (`create and update refuse labels the project lacks, naming them, unless createMissingLabels creates them first`)).
- Token: one per host, sent only to the remote's host (or the real host of its SSH alias) in `PRIVATE-TOKEN` and masked as `[token]` in any answer that echoes it; refused when the repository's settings declare `tokens` or cannot be read; never in an output; `project` is a path on that host, never a URL (`tests/register.test.ts` (`the token goes only in the PRIVATE-TOKEN header, and writes send JSON`, `without the option, outside a GitLab repository, with repository-declared tokens or unreadable settings, nothing is sent`, `project switches to another project on the same host with the same token, and a URL or another host is refused unsent`)). A remote URL is never echoed (`tests/remote.test.ts` (`locate uses origin, else the first remote, and never echoes an unreadable remote URL`)).
- Tests mirror modules; `tests/fake-api.ts` is the fake API for tool tests (`paged` for a next page, `ME` the token's user, `THEIRS` an MR by someone else) and `tests/host.ts` the host fake (`world`, `started`).
- Checks: [root commands](../../AGENTS.md#commands); type-check with `npm run typecheck -- gitlab`.
