# gitlab

Usage/privacy: [README.md](README.md).
- `hooks/register.tsx`: each tool's literal `session.start` registration (`inputSchema ... satisfies SchemaFor<McpToolInputs[...]>`) and `tool.call` hook (with a `.catch` that answers an error), all sharing the top-level `run($, tool, input, option)`: remote (an SSH alias resolved through `ssh -G`), token, `project` (same host only), API, then the tool. `hooks/schema.ts`: the shared `SchemaFor` and `allOf` (`enum` slots take only `allOf` of exactly the union), a byte-for-byte copy of the template's that `scripts/check-consistency.mjs` enforces, with its type cases in `tests/schema-types.ts`; numbers are written as `integer` here. Action unions live in `types/index.d.ts`.
- `hooks/remote.ts`: `parseRemote`, `locate` (origin, else the first remote), `currentBranch`, `projectPath`, `sshHostname`, over injected git and ssh. `hooks/tokens.ts`: the `tokens` option as `host=token` pairs, `resolveToken` and the refusal texts. `hooks/api.ts`: `gitlab(fetch, host, project, token)`; every path is built from checked ids and the encoded project, never from the model,; `page`/`rootPage` read `X-Next-Page`. `hooks/context.ts`: `Ctx` (`makeCtx`: the injected `clock`, `me` read once, `foreign` when `project` names another project), input checks, `paging` (`perPage` at most 100), `mrIid` (the current branch's open MR without an iid; never for a foreign project), `writable` (the guard below), `userIds` and `username` (`@me`), `clip`. `hooks/errors.ts`: the refusal text with what to do per status.
- Tools, one module each: `hooks/mr.ts`, `hooks/comments.ts`, `hooks/pipelines.ts`, `hooks/joblog.ts`, `hooks/labels.ts`, `hooks/users.ts` (`gitlab_user`: the token owner or a username). There is no generic API tool: a new need gets its own action or tool. Deleting comments, labels, branches or MRs is not offered (`tests/register.test.ts`).
- Waiting: `gitlab_pipeline` `wait` polls every `POLL_MS` (15 s) for at most `minutes` (30 at most) through `ctx.clock`, whose `sleep` is a host `sleep` process so the hook spends none of its own time (`register.tsx`), and answers the failed jobs with `failureSnippet` (`joblog.ts`) for the first five (`tests/pipelines.test.ts`; `tests/register.test.ts`). `gitlab_mr_comment` `unresolved` reads up to twenty pages and answers only open threads in brief (`tests/comments.test.ts`).
- Others' MRs: every write on an MR (`update`, `approve`, `unapprove`, `rebase`, `merge`, comment writes, an MR pipeline `run`) reads it first and is refused when its author is not the token's user, unless `allowOthers: true` (`tests/comments.test.ts`; `tests/mr.test.ts`).
- Merge is guarded: an explicit `iid` and the full head `sha` (sent to GitLab, and compared first); refused for a draft, conflicts, blocking discussions or a closed MR whatever the flags; a `release*` target, or any protected one (`GET /repository/branches/:name`, refused when unreadable) other than main, master or develop, needs `allowProtectedTarget: true` (`tests/mr.test.ts`).
- Labels an MR is about to get must exist: a missing one is refused by name unless `createMissingLabels: true` creates it first, so GitLab never makes one silently (`tests/mr.test.ts`).
- Token: one per host, sent only to the remote's host (or the real host of its SSH alias) in `PRIVATE-TOKEN` and masked as `[token]` in any answer that echoes it; refused when the repository's settings declare `tokens` or cannot be read; never in an output; `project` is a path on that host, never a URL (`tests/register.test.ts`). A remote URL is never echoed (`tests/remote.test.ts`).
- Tests mirror modules; `tests/fake-api.ts` is the fake API for tool tests (`paged` for a next page, `ME` the token's user, `THEIRS` an MR by someone else) and `tests/host.ts` the host fake (`world`, `started`).
- Checks: [root commands](../../AGENTS.md#commands); type-check with `mise exec -- tsc -p plugins/gitlab/tsconfig.json`.
