# session-hud

A card above the prompt, laid out the same way in a terminal, on the desktop app and on any other surface:

1. A dot, green between turns and yellow with the running turn's time (`working 12s`) while one runs; the model and its effort; where the session works, by name only (`spider-claude-mods/plugins · ⎇ main · worktree`): the repository (the main checkout's name inside a linked worktree), the folder within it (`…/hooks` when deeper than one), the branch (none on a detached head) and `worktree` in a linked worktree, or just the folder's name outside a repository, read from git when the session starts, after each of your turns, every 30 seconds and when the session's directory changes; at the right, the subagents and teammates running a turn now, grouped by the agent type they were spawned as, their model and the effort of their last request (`3 agents: codex:codex-rescue Opus 5.5 · high ×2, Explore Haiku 4.5 · medium`; `?` for a model not yet reported, a part the host has not reported left out), left out when none runs; after them, the tokens every subagent and teammate request processed since the plugin loaded (`agents used 1.2M tokens`: input, cache read and written, and output, summed over requests), shown once one reports usage and kept after the agents end.
2. The context bar with its tokens (`47%  236k / 500k`), measured against the window the session compacts at (an `autoCompactWindow` smaller than the model's limit counts); from 85% of that window the bar and its percent turn red, a cue to run `/compact` yourself before the automatic one; at the right, the last turn in figures (`+14k sent · ▲ +94k in turn · 36k out`): what was sent at its start on top of where the turn before it ended (your message, reminders, results delivered between turns), what the turn itself added (tool results and output) and the output of all its requests. What was sent is left out when it is not known: for the first turn the card sees, after a compaction, and when a turn starts below where the one before it ended.
3. The share of the input read from the prompt cache and how long ago a request read or wrote it (`cache 96% · used 40s ago`); with a known lifetime, also what is left of it (`1h TTL, 59m left`, or `expired`). The host names the lifetime only on a model switch; the `cacheTtl` option names it before that.
4. The five-hour and seven-day windows on one line, each with a bar lit to the percent used and a tick at the time passed, `▲N` for the points above an even pace, the time left and where the pace ends (`~85% at reset`, or `100% in 2d 7h` when it runs out first).
5. The last turn's duration, the turns so far, and the main session's edits (successful `Write`, `Edit` and `NotebookEdit` calls) and errors (failed tool calls). The card shows no money.
6. With the `nextSteps` option on, next steps under a dashed line: up to four prompts you are likely to send next, as checkboxes. Press a digit from an empty prompt box (or click) to tick one, `p` to put the ticked ones in the prompt box (several numbered) for you to edit and send, `0` to dismiss; the first also shows as the prompt box's dim ghost text, so Tab takes it. A step that runs one of the session's skills or slash commands (`/code-review high`) is drawn in blue. They are hidden while a turn runs and cleared when the next one starts.

The bars keep a fixed size whatever the card's width: 96 pixels drawn as SVG on the desktop, twelve cells of text in a terminal. A narrow card wraps between the parts of a line, never inside one; in a terminal, a part wider than the whole card is cut at the edge.

```text
/plugin install session-hud --marketplace anderson-spider/claude-mods
```

Options (`/plugin` → session-hud, or `pluginConfigs` in settings): `nextSteps` (default off) turns on the next steps. After each main-session turn that ends in an answer of 80 characters or more, a fork of the session (the same model, sharing its prompt cache, so about one short reply) is asked for the likely next prompts, with the session's skills and slash commands listed so a step can be one of them; a step naming a command the session does not have is dropped. Nothing is added to your prompts or to the conversation, and nothing is sent for you. To keep it off in one project while it is on, disable session-hud there with `enabledPlugins` in that project's settings. `cacheTtl` (`off`, `5m`, `1h`; default `off`) is the prompt-cache lifetime your sessions write, which the host does not report until a model switch. Set, the card shows what is left of the cache from the first turn. A model switch's lifetime replaces the option's. A wrong value shows a wrong countdown, so set the lifetime your plan or settings actually write.

The next steps are adapted from [next-steps](https://github.com/anthropics/claude-plugins-community) by Thariq Shihipar (the fork, the text cleaning and the skill list) and [inline-next-steps](https://github.com/shijieli708-ship-it/claude-mods/tree/main/plugins/inline-next-steps) by Shijie Li (ticking several steps), both MIT ([`hooks/LICENSE.next-steps.txt`](hooks/LICENSE.next-steps.txt)).

Under a dark or automatic theme the card uses the design's colours; under a light or ANSI theme it keeps the theme's. A survey takes the band while it is open. Another plugin that draws in the same band, such as one that shows suggestions, shows under the card.

## Privacy

Everything comes from the session itself: the host's usage figures and token counts, the model that answered, the cache lifetime a model switch reports, the main session's tool results (only whether an edit succeeded or a call failed), the ids, agent types, models, efforts and token counts of the agents the session starts and the host's agent list (whether each one is still running, and its type), and what two read-only git commands (`rev-parse` and `branch --show-current`) answer for the session's directory. The task description an agent was given never reaches the card. No prompt, answer or tool input reaches the screen; of the session's directory only the repository's and folders' names and the branch do, never a whole path. Nothing is sent anywhere, except with `nextSteps` on: then the fork sends the session's own conversation, with the question and the session's skill and command names and descriptions, to the session's model as one more request, and the steps it writes back (model text, stripped of escapes and hidden characters) are the only text of the conversation the card shows.

## Tests

Pure tests call `hooks/usage.ts`, `hooks/card.ts`, `hooks/view.ts`, `hooks/layout.ts`, `hooks/palette.ts`, `hooks/workspace.ts` and `hooks/steps.ts` directly; host tests run the plugin against a fake host (`tests/host.ts`, git included) with no network.
