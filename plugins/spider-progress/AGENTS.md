# spider-progress

Usage/privacy: [README.md](README.md).

- `hooks/register.tsx`: every `on(...)` and `$` call. `session.start` registers the `progress` and `step` tools (`inputSchema ... satisfies SchemaFor<McpToolInputs[...]>`; `tasks` and `task` are objects, typed `unknown` and checked in `hooks/state.ts`) and the `spider-agents` command, reads the language and starts the 1 s clock that moves only while an agent runs; `session.end` clears the state; `agent.spawn` appends the step brief to a tier worker's prompt and tracks every agent; `turn.step` and `turn.complete` record usage and endings; `ui.render` draws the band (`AbovePrompt`, above what draws beneath it) and the pane.
- Pure modules: `hooks/state.ts` (run and tasks, the transition table, `applyProgress`), `hooks/agents.ts` (agents by `agentId`), `hooks/tiers.ts` (tier names, `spider-task:` lines, the step brief), `hooks/metrics.ts` and `hooks/prices.ts` (usage, a dated price table, estimated cost), `hooks/config.ts`, `hooks/i18n.ts`, `hooks/text.ts`, `hooks/band.ts`, `hooks/pane.ts`. `hooks/schema.ts` is the template's byte-for-byte copy, with its type cases in `tests/schema-types.ts`.
- Rules:
  - Only Main changes the run: `progress` refuses a call that carries `agentId`, and `step` refuses one that does not. `tests/register.test.ts` (`progress from a subagent is refused; step from the main session is refused`).
  - Calls are idempotent and applied whole: a repeat changes nothing, an invalid transition or a cycle is refused with the reason, and tasks are matched by id, never by title. `tests/state.test.ts` (`repeating the same call changes nothing`, `an invalid transition is refused with the reason`, `junk input is bounded, unknown deps dropped and a cycle refused`).
  - A title that differs from the open run's starts a new run, so a new task never inherits an old one's progress; a call for a closed run that starts none is ignored with `ok`. `tests/state.test.ts` (`a different title on an open run starts a new run and leaves the old tasks behind`, `finished closes the run and later calls for it are ignored with ok`).
  - A task a replan drops, or Main cancels, leaves the total; a task the run's cancellation closes keeps `cancelledWithRun`, stays in the total and in the pane. `tests/state.test.ts`: `tasks a cancelled run leaves open stay in the count, unlike tasks a replan dropped`.
  - The band counts only the run's agents: those started while it was open and the workers its tasks list; the pane lists the run's agents first and the session's others under their own label. `tests/agents.test.ts`: `the run counts agents started while it was open and workers its tasks list, never older or later ones`; `tests/register.test.ts`: `the band counts only the agents of the current run`. `tests/pane.test.ts`: `the run's agents come first and the session's other agents follow under their own label`.
  - Host events move a task only to observed states: a bound worker's spawn starts it and its answer sends it to review; only Main accepts, fails or cancels. `tests/register.test.ts` (`a spawned spider worker gets the step brief and binds its task, which moves to running then reviewing`).
  - A worker moves only a task that lists its `agentId`, and a resumed worker (`resume` on `agent.spawn`) keeps its prompt and runs again. `tests/state.test.ts`: `a worker that the task does not list moves nothing`; `tests/register.test.ts`: `a resumed worker keeps its prompt, runs again and sends its task back to review`.
  - Only observed figures are drawn: an unknown model has no cost and an unknown window no percent. `tests/metrics.test.ts` (`an unknown model has no cost, never a default price`), `tests/pane.test.ts` (`the expanded pane lists agents with model, planned → actual effort, steps, tokens, context, cost and duration; unknowns read N/A`).
  - A tool never throws to the model. `tests/register.test.ts` (`a tool failure returns text and never throws`, `an exception inside a tool returns text`).
  - The pane opens on its own once per run (`team`) or per wave of agents (`any`), so a pane the person closed stays closed. `tests/register.test.ts` (`autoOpen team opens on a new run only, so a closed pane stays closed for its workers`, `autoOpen any opens when a subagent starts with none running, and a closed pane stays closed while they run`).
- The band lands under the session-hud card when this plugin comes after session-hud in `enabledPlugins` (earlier is outer); a fresh install is appended, so it does.
- Checks: [root commands](../../AGENTS.md#commands).
