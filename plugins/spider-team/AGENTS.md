# spider-team

Usage: [README.md](README.md).

- `skills/{brainstorm,team-on}/SKILL.md`: one skill per mode, each a short header (the backlog settled in rounds of numbered questions with a recommended answer that "yes" accepts, waiting for go; or team mode's rules) over the same `<!-- shared: core -->` block, which `node scripts/check-consistency.mjs` keeps identical and within 1,600 words: edit it in one skill and copy it to the other. The core holds only what every run needs: the run Main owns and implements (seven phases, each ending on its exit; Main writes the code by default, delegates implementation only to parallel workers on disjoint files, at most `max_workers` at once, calls the planner and researcher by value and the reviewer by risk, and always the reviewer on the whole diff before creating a PR or MR, reviews every delegated diff and verifies the integrated result; only Main runs Git writes; Understand reads `GLOSSARY.md` and `docs/adr/` when present and Complete updates the glossary, offering an ADR only for a hard-to-reverse, surprising, traded-off decision; Plan cuts verifiable vertical slices that fit one context, prefactors first, expand–contract for wide changes with a shared branch when batches cannot stay green; skills of other plugins change none of these rules), the role table, the task contract (`spider-task`, Goal, Scope, Out of scope, Interfaces, Done when, Deliver; briefs point at files instead of restating them) and the `progress` calls in short. `skills/team-off/SKILL.md` closes team mode (open tasks, Verify, Complete) without the core, which team-on already loaded. Every skill is user-invoked only (`disable-model-invocation: true`).
- `skills/brainstorm/{bugs,review,design,new-project}.md`: the steps for one case, linked from the core as `../brainstorm/<file>.md` so both copies resolve them, read only when the case comes up and passed to a delegate by absolute path: a bug (feedback loop, minimise, ranked hypotheses, tagged debug logs, regression test at a correct seam, mutation proof, redaction), Main's review checklist with the reviewer's brief and smell list with fixes, a user interface (visual decisions, mockups, accepting only what Main saw), and a new project from an empty directory (spec, plan, `AGENTS.md`, `filemap.md`, approval before delegating). A rule every run needs stays in the core; one that only a case needs goes to its file. Each guide's rule that must not be skipped (no bug fix before a red command; a mockup before code for a new or ambiguous screen; a UI accepted only on what Main saw) also stays in the core in one line, and Plan names `bugs.md` or `design.md` in a bug or UI task's criteria: these hold when the session never opens the file, so they are not duplicates to remove.
- Team mode keeps one progress run open across messages: appending is a replan with the whole list, and a different `title` would start a new run, so Main sends the title only at `team-on`.
- `agents/spider-{planner,worker,researcher,reviewer}.md`: frontmatter `model` as a full ID (`claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5`), so a provider without it fails loudly rather than resolving an alias to an older model; the skill passes no `model`, since the call's `model` would override it. Tools enforce what they can: planner and reviewer `Read, Grep, Glob` (no edit, shell or agent), researcher adds `WebSearch, WebFetch, Write, Edit` (no shell), worker `disallowedTools: Agent`; each lists `ToolSearch` and `mcp__spider-team__step`. Scope and docs-path limits are prompt rules only: tool lists cannot scope `Bash` or `Write`, and plugin agents ignore `permissionMode` and `hooks`. Git writes are also refused by the plugin's own `tool.call` hook on `Bash` (Agents pane, below). The reviewer reports on two axes kept apart, Spec and Standards, each finding must-fix or optional, and flags tests that pass by construction; code smells, from the list in `review.md` its brief names, are optional Standards findings with their fix, and a project rule overrides them. The worker writes tests through the public interface, mocks only at system boundaries and literal expected values, and follows a guide file its brief points at.
- `userConfig` in `plugin.json`: `max_workers` and one effort per role, substituted into the skills as `${user_config.KEY}`. An unset option stays a literal placeholder in Claude Code 2.1.301 (its `default` is not substituted), so the skill names the fallback beside each one; never repeat the placeholder token in that fallback text, or it is substituted too. The effort travels in each Agent call, so subagent-effort's Jev can replace it; the agents set no `effort`.
- Contracts between the skill and the hooks, which `hooks/tiers.ts` and `hooks/state.ts` read:
  - Agents are called namespaced, `spider-team:spider-<role>`; the bare name does not resolve for a plugin agent.
  - A brief has a line `spider-task: T<n>` (the skill writes it first; `taskIdOf` in `hooks/tiers.ts` matches it on any line); it binds the worker to its task.
  - Task ids are `T` plus up to three digits; owners are `main`, `planner`, `worker`, `researcher` or `reviewer`.
  - Changing a role, its model or its default effort means changing `TIERS` in `hooks/tiers.ts` too.
- The skill skips reporting when the `progress` tool is missing; host tests cover the hooks, and a real session that loads the plugin is the only proof of the skill's behaviour.

## Agents pane

- `hooks/register.tsx`: every `on(...)` and `$` call. `session.start` registers the `progress` and `step` tools (`inputSchema ... satisfies SchemaFor<McpToolInputs[...]>`; `tasks` and `task` are objects, typed `unknown` and checked in `hooks/state.ts`) and the `spider-agents` command, reads the language and starts the 1 s clock that moves only while an agent runs or Main's turn does. It fires again on a reload of the plugin's code, whose state the host keeps (the atoms and the saved run carry `STATE_SHAPE` from `hooks/saved.ts`: bump it when a stored type changes, and both drop what older code wrote), so it never resets: it brings back the session's saved run when memory has none and ends the running agents `$.agent.list()` no longer lists as running (`tests/register.test.ts`: `a settings read that fails at start still starts the clock, and a reload keeps the run and ends agents the host no longer lists`). `session.end` clears the state. The open run is written to `$.store` under `run:<session id>` after each change and removed once closed, and comes back on `session.start` or, after a resume in this process, on Main's next turn end (`tests/register.test.ts`: `the open run is kept in the store under the session and comes back after the state is lost; a closed run leaves it`, `a resume in this process brings back the resumed session's run on Main's first turn end, and another session's run stays out`). `/spider-agents clear` forgets the run, the agents and Main's usage and removes the saved run (`tests/register.test.ts`: `/spider-agents clear forgets the run, the agents and their usage, and removes the saved run; the pane stays open`); `agent.spawn` appends the step brief to a role agent's prompt and tracks only role agents (`spawned` in `hooks/agents.ts` skips any other type, since the host reports no ending for some of them and their rows stayed running; a reload drops those an older version tracked with `roleAgents`, and an untracked agent's ending is ignored, never held for a spawn; `tests/register.test.ts`: `the pane lists only spider-team role agents, never a generic one that ends without a report`, `a reload drops the generic agents an older version tracked, without ending the role agents`); `tool.call` (all tools, after `next`) counts a subagent's tool calls and failures; `tool.call` on `Bash` refuses a spider-team agent's call that names `git`, `gh` or `glab` outside their read-only forms before it runs (`refusedIn` from `hooks/git-guard.ts`; the agent's type from the tracked spawn, else `$.agent.list()`; its `.catch` refuses any subagent's write when that lookup throws, since a guard that fails lets the tool run), and the counter above sees the refusal as a failed call (`tests/register.test.ts`: `a spider-team agent's Git write is refused before it runs; its reads, Main's writes and other agents' pass`, `a spider-team agent the plugin no longer tracks is found in the host's list, and its Git write is still refused`); `turn.step` and `turn.complete` record usage and endings; `ui.render` draws the pane (no `AbovePrompt` band: the plugin leaves the area above the prompt to others; `tests/register.test.ts`: `the plugin draws no band above the prompt, with or without a run`) from `paneModel`, sized to `bodyColumns` and to `scroll.bodyRows`: on the terminal, `terminalLines` as one `mono` `Text` per line (borders and rails included); on a surface with `Svg` (the desktop), the header and footer as `mono` `Text` around one `Svg` of the cards from `svgOf`, interactive only while its rail moves. Titles are bold through `weight` (`bold` reads as semibold), and a piece's `tone` replaces its style's colour. The pane has no buttons (`tests/register.test.ts`: `the terminal draws the cards as monospaced lines with the title bold in the border, the desktop as one SVG, neither with buttons`). `turn.step` and `turn.complete` on Main keep when its turn started and its ended turns of the last 15 minutes, for the session card and the timeline.
- Tool inputs: `progress` takes `title`, `phase`, `tasks` (each `id`, `title`, `owner`, `after`, `criteria`), `task` (`id`, `state`, `evidence`, `error`), `finished` and `cancelled`; `step` takes `done`, `total` and `note`. `types/index.d.ts` holds the `McpToolInputs` entries they must match.
- Pure modules: `hooks/state.ts` (run and tasks, the transition table, `applyProgress`), `hooks/agents.ts` (agents by `agentId`, `missedEndings` for a reload), `hooks/saved.ts` (the saved run: its key and shape, what is saved and restored, pruning past 7 days, another shape or 20 sessions; saves run one at a time in register.tsx, so a late one never reopens a closed run), `hooks/tiers.ts` (role names, `spider-task:` lines, the step brief), `hooks/git-guard.ts` (an allowlist of the read-only forms of `git`, `gh` and `glab`, checked on the line with quotes dropped and split at separators; a line that names them beside a substitution, `eval`, a heredoc or an inline script is refused whole. It is not a parser on purpose: a hand-written shell parser kept leaking, and this errs on refusing a harmless read instead; `tests/git-guard.test.ts`), `hooks/metrics.ts` and `hooks/prices.ts` (usage, a dated price table, estimated cost), `hooks/config.ts`, `hooks/i18n.ts`, `hooks/text.ts`, `hooks/pane.ts` (`paneModel`: a header, the cards (session, plan, agents running, finished and planned, the timeline by role), a footer and whether the rail moves; each task's title and its evidence or error wrapped to two lines by `wrap` in `hooks/text.ts`, owner and state on a line of their own; short of rows it first folds the accepted tasks into one line (`idRanges`), then drops the timeline, then the finished and the planned agents; `paneLines` flattens it for tests; `tests/pane.test.ts`: `a long title wraps to two lines under itself and then is cut, its owner and state on a line of their own`, `short of rows the accepted tasks fold into one line with their ids as ranges, before any card is dropped`), `hooks/cards.ts` (the terminal's borders and rails) and `hooks/svg.ts` (the desktop's plates on the same grid of cells, light and dark colours by `prefers-color-scheme`). `hooks/schema.ts` is the template's byte-for-byte copy, with its type cases in `tests/schema-types.ts`.
- Rules:
  - Only Main changes the run: `progress` refuses a call that carries `agentId`, and `step` refuses one that does not. `tests/register.test.ts` (`progress from a subagent is refused; step from the main session is refused`).
  - Calls are idempotent and applied whole: a repeat changes nothing, an invalid transition or a cycle is refused with the reason, and tasks are matched by id, never by title. `tests/state.test.ts` (`repeating the same call changes nothing`, `an invalid transition is refused with the reason`, `junk input is bounded, unknown deps dropped and a cycle refused`).
  - A title that differs from the open run's starts a new run, so a new task never inherits an old one's progress; a call for a closed run that starts none is ignored with `ok`. `tests/state.test.ts` (`a different title on an open run starts a new run and leaves the old tasks behind`, `finished closes the run and later calls for it are ignored with ok`).
  - A task a replan drops, or Main cancels, leaves the total; a task the run's cancellation closes keeps `cancelledWithRun`, stays in the total and in the pane, where it counts in the total and shows as cancelled. `tests/state.test.ts`: `tasks a cancelled run leaves open stay in the count, unlike tasks a replan dropped`; `tests/pane.test.ts`: `tasks the run cancelled stay in the plan counts`.
  - The pane header counts only the run's agents: those started while it was open and the workers its tasks list; the agent cards list every role agent of the session. `tests/agents.test.ts`: `the run counts agents started while it was open and workers its tasks list, never older or later ones`; `tests/register.test.ts`: `the pane header counts only the agents of the current run`.
  - Host events move a task only to observed states: a bound worker's spawn starts it and its answer sends it to review; only Main accepts, fails or cancels. `tests/register.test.ts` (`a spawned spider worker gets the step brief and binds its task, which moves to running then reviewing`).
  - A worker moves only a task that lists its `agentId`, and a resumed worker (`resume` on `agent.spawn`) keeps its prompt and runs again. `tests/state.test.ts`: `a worker that the task does not list moves nothing`; `tests/register.test.ts`: `a resumed worker keeps its prompt, runs again and sends its task back to review`.
  - Only observed figures are drawn: an unknown model has no cost and an unknown window no percent. `tests/metrics.test.ts` (`an unknown model has no cost, never a default price`), `tests/pane.test.ts` (`a running agent has a row in its role tone with model, an attempt block and time, then its activity and figures`, `the session card shows Main's model, effort and state, its context gauge and tokens, then the costs and the run's time`).
  - Activity is observation: the `tool.call` hook returns the host's answer unchanged and counts only a running subagent's calls, never this plugin's own tools. `tests/register.test.ts`: `a subagent's tool calls are its activity, failures counted; Main's calls and the answers pass through unchanged`; `tests/agents.test.ts`: `the plugin's own tools are not activity, and an MCP tool reads by its own name`.
  - A tool never throws to the model. `tests/register.test.ts` (`a tool failure returns text and never throws`, `an exception inside a tool returns text`).
  - The pane opens on its own once per run (`team`) or per wave of agents (`any`), so a pane the person closed stays closed. `tests/register.test.ts` (`autoOpen team opens on a new run only, so a closed pane stays closed for its workers`, `autoOpen any opens when a spider-team agent starts with none running, and a closed pane stays closed while they run`).

- Limits (`hooks/state.ts`, `hooks/agents.ts`, `hooks/saved.ts`): a title 120 characters; a list of 100 tasks, where a longer one keeps its first 100 and says so; criteria, evidence and each error 500 characters, the last five errors kept; 20 `after` ids per task; three attempts per task (the first try and two returns from review); a step's `total` at most 1000 and its note 200 characters; a saved run kept 7 days after its last change, for at most 20 sessions.
- Checks: [root commands](../../AGENTS.md#commands).
