# spider-team

Usage/privacy: [README.md](README.md). Lead workflow: `skills/using-spider-team/SKILL.md` (pick the simplest path, purposeful briefs, at most two agents at once by default, verify answers, review on risk, two attempts then change approach, observable budget, delivery with the validation performed).

- `hooks/register.tsx`: the three literal `$.agent.register` calls and the `$.command.register` of `spider-team-stats` in `session.start`, the `tool.call` hook on `Agent`, the `turn.complete` hook and the `command.run` hook of the stats command. It routes only the three exact Spider types, `analyst`, `planner` and `reviewer`, and lets the retired `developer` and `architect` types pass untouched (Jev through the router table and the role floor, else the role default; the call's own `model` and `effort` are always overwritten, never refused), refuses empty tasks, and when routing fails before dispatch its `.catch` dispatches the role default pair (pure, no host calls; `next.called` replays an already dispatched call instead). Host access stays literal here and is passed only to top-level functions of this file (`io`, `files`, `observe`, `record`, `judged`). Routing rewrites the `Agent` call, not `agent.spawn`: the spawn takes a model but no effort, so effort would need a second hook on each of the agent's `turn.step`s, and the outcome comes from the call's result. The one user option is `judgeEvery` (`judgeEvery` and `createSampler` in `hooks/judge.ts`: 0 off, 1 every completed run, N the first and then one in N; anything not a finite number is 1). No other hooks, tools, user options or files. `tests/register.test.ts` (`session start registers the three native agents and the stats command, and no tools`, `Jev picks the pair for a Spider role, shown in its description, and other agents pass untouched`, `a model or effort from the lead is overwritten by the Jev pair, or by the role default without a key`, `Jev is asked both questions and bang and at-sign words reach it as written`, `a default spawn of every role from a marketplace install runs natively with its role default`, `empty tasks are refused before dispatch, and the retired developer and architect pass untouched`, `a routing failure dispatches the role default once, never the lead model and effort, and writes no record`).
- Local ledger: the plugin's only file, `~/.claude/spider-team/routes.jsonl` (one rotated generation, `routes.1.jsonl`), JSON lines written from `register.tsx` through `$.fs`. A decision line goes in before dispatch; an outcome line after a foreground `Agent` result, or, for an `async_launched` result, from the `turn.complete` of that `agentId` (an in-memory map of at most 200 entries, dropped on reload). Observation returns the host result unchanged and a failure of its own is one fixed debug line (`spider-team: decision not recorded`, `spider-team: outcome not recorded`); an unreadable ledger is never overwritten. Before the outcome line is written, `judged` asks the outcome judge about a completed run's non-empty answer and adds `judge` (null for error/refused/aborted runs, an empty answer or any judge failure; the line is written either way, and the judge's own failure is one fixed `spider-team: judge off (<reason>)` debug line). A line never holds the task, prompt, answer, path, branch name or key, and the answer, its redacted form and Jev's reply never reach a line or the debug log (`tests/register.test.ts`: `foreground and background outcomes carry the judge of the answer, and the host result passes on as it came`, `a judge failure still writes the outcome with judge null, unfinished runs are not judged, and no line or log holds the answer`, `a decision line and a foreground outcome line are written, and the host result passes on as it came`, `a background launch is written when its turn completes, with the verdict from the final text`, `an aborted background agent is an aborted outcome`, `no line ever holds the task, a prompt, an answer, a path, a branch or the key`, `observation survives a failing ledger: the dispatch and its result are unchanged and one debug line names the miss`, `a refused or failed Agent result writes no outcome and passes on`). The stats command reads both files and prints `formatSummary` (`tests/register.test.ts`: `the stats command summarizes the local ledger, and says so when there is none or it cannot be read`).
- `hooks/ledger.ts`: pure record builders (`decisionLine`, which tags the line with the router's `calibration`; `afterAgentCall`, `afterTurn`, each field projected one by one and returning the line with the answer to judge, empty unless the run completed; `withJudge` and `judgeOf`: the judge's three flags only, each finite in 0..1 and rounded to two decimals, else null, and only on a completed run), `verdictOf`, `costOf` (from `PRICES`), the bounded `createPending`, `appendLine` (one process-wide queue, whole-file read then write, rotation at `ROTATE_AT`), `parseLedger` (lines of the retired `developer` and `architect` roles still parse and keep their own groups, after the current roles), `summarize` and `formatSummary`. Failures are error/aborted/refusal runs and reviewer CHANGES or BLOCKED; each role and pair row also counts `judged` runs and `short` ones (`judgedShort`, the judge re-projected from the file), printed as `short=<pct> judged=<n>`, `-` when none was judged; `summarize` joins each current-calibration decision's predicted duration level 0..3 to its outcome and reports the count and median real agent duration per level (`byPredictedTime`; `formatSummary` labels the levels with the duration criteria). `vsDefault` prices each current role's runs with usage at the routed model and at the role default's model on the same tokens, and counts them below, at or above the default rung; an effort change alone prices as no difference, and retired roles are left out. The Jev confidence and that section use only decisions of the current `CALIBRATION` (a line without the field is calibration 1), and the summary names how many older ones they left out (no line when none); role/pair groups and fallbacks count every line. A decision line carries each dimension's full distribution as `dist` (only the question's level keys, finite probabilities rounded to two decimals; null without Jev). The stats texts carry no plugin-name prefix: the host adds it. `tests/ledger.test.ts` (`the judge projects its three flags only, each a finite probability rounded to two decimals, and only a completed run keeps one`, `a run is judged short when not finished or a failing check or a block fires, and each row shows the short share of judged runs`, `a decision line projects only the allowed fields and rounds the probabilities to two decimals`, `a decision line keeps each full distribution with only its level keys and finite probabilities`, `only the verdict word of a reviewer answer is extracted`, `the estimated cost follows the list prices of the resolved model family`, `a finished foreground run becomes one outcome line with usage, cost and a reviewer verdict, and nothing else of the result`, `a tool error is an error outcome, a background launch is awaited, and a refusal or unknown shape writes nothing`, `a background end becomes an outcome line from its turn: duration, usage, reason, abort and the reviewer verdict`, `the background map is bounded, drops the oldest and gives each agent once`, `appends are serialized so concurrent lines all survive in order, and one failed append does not stop the next`, `a ledger that cannot be read is never overwritten, and a full one moves to its rotated generation`, `parsing skips malformed and foreign lines, counts a repeated line once and keeps the retired developer and architect lines`, `the summary counts runs, failures, medians, tokens, cost, fallbacks, confidence and the real time per predicted level`, `each predicted human-time level takes the median real duration of its outcomes, ignoring runs without a duration`, `the formatted summary is compact and names every part, and an empty ledger says so`, `the Jev confidence and the real time per predicted level use only current-calibration decisions, and a line without one is calibration 1`, `the routed pairs are priced against the role default on the same tokens, per current role and in total`).
- `hooks/roles.ts`: the role table (`SPECS`: prompt and tools; model and effort come from `defaultOf` in `hooks/router.ts`), `RETIRED_ROLES` (developer, architect: only the ledger reads them) and `MODELS` (haiku, sonnet, opus; no fable)/`EFFORTS`, the only lists the router is typed against. Routing changes only model and effort. The session is the only writer: no role has Write, Edit or NotebookEdit, none runs in a worktree, and only the reviewer has Bash, limited by its prompt to read-only git (status, log, diff, show, merge-base, ls-files). The planner answers with one Markdown plan (goal and scope, ordered steps with their files, invariants, an acceptance checklist of commands and expected results, assumptions or blockers) and writes no file. The reviewer reviews the lead's checkout from the merge base with the target branch to HEAD plus staged, unstaged and untracked files (`git ls-files --others --exclude-standard`), judges the complete diff and answers BLOCKED when it cannot inspect any of them. Every role stays in the brief's scope, says when the brief is unclear, and hands back the outcome, file:line evidence, limitations, checks and next steps without narrative. `tests/roles.test.ts` (`three read-only roles keep exact fallbacks and permissions, and none writes or runs in a worktree`, `every role stays in the brief's scope and hands back the outcome, evidence, limitations, checks and next steps without narrative`, `the planner answers with one Markdown plan of steps, files, invariants and acceptance checks, and writes nothing`, `the reviewer judges the lead checkout from the merge base, with uncommitted and untracked files, and blocks what it cannot see`, `only exact role names are recognized, and the retired developer and architect are not Spider roles`).
- `hooks/router.ts`: the whole routing policy, pure data and no host access: the two Jev questions (`QUESTIONS`: difficulty, judged on the work and not the brief's length; duration as the time an experienced engineer who knows the codebase needs, the SWE-bench Verified buckets: under 15 minutes, 15 minutes to 1 hour, 1 to 4 hours, over 4 hours), the penalty weights (`POLICY`: under-capacity 1, over-capacity 1.25, so a split judgment goes to the cheaper level), `CALIBRATION` (the number each decision line carries, bumped with any change to `QUESTIONS`, `POLICY`, the table or the role floors), the difficulty labels, the duration groups, the capacity `LADDER` (one ordered list of rungs; `ROUTES`, `ROLE_POLICY` floors and defaults are typed as rungs, so tsc fails on anything else), `routeOf` (cell, then the floor: the stronger of the two on the ladder), the outcome judge (`JUDGE_QUESTIONS`: three Nouls over `report.text`, `finished`, `failingChecks`, `blocked`, one flaw each; `JUDGE_FIRE` 0.5; `judgedShort`: finished below it or either flaw above it; they do not route and leave `CALIBRATION` alone) and `PRICES` (list prices, USD per million tokens). Defaults need not be table cells. It imports only types from `roles.ts`, so there is no runtime cycle. A new model is an edit of `MODELS`, the ladder and the cells. `tests/router.test.ts` (`the judge asks three yes/no questions about report.text, one flaw each, and a run is short below 0.5 finished or above 0.5 on a flaw`, `the table holds every difficulty and duration group cell by cell`, `the capacity ladder is the one ordered list every cell, floor and default belongs to`, `no pair is below its role floor for any cell, Haiku never runs at low and Fable is out`, `duration levels 0 and 1 are short, 2 medium and 3 long, and the floor lifts a weaker cell`, `role floors and defaults are fixed and the registered definitions carry the defaults`, `the questions judge the work itself and ask for human-expert time, not the length of the brief`, `the questions match the levels and the prices are the October 2026 list prices`, `the calibration that tags each decision line is 5`).
- `hooks/effort.ts`: carries out the router's policy: `levelOf` (expected penalty with the router's weights, ties low) and `assessRoute` (always asks both questions with the redacted task as written, no local decision or partial question; returns the raw cell, the floor-adjusted pair, whether the floor applied, the levels, the top probability and normalized distribution per dimension, the source, the Jev reason and latency; any assessment failure keeps the exact role default) and `clipped` (key, then `redact` over the whole text, then the 4000-character cut), shared with the judge. `tests/effort.test.ts` (`two questions carry the difficulty and duration criteria and nothing else`, `the level minimizes expected penalty with over-capacity weighted 1.25 and ties going lower`, `Jev levels select the pair from the table, grouping duration after the level is chosen`, `the choice carries the raw cell, the floor result, the levels, the top probability and full distribution of each dimension and the Jev latency`, `every assessment failure keeps the exact role fallback and logging failure changes nothing`, `assessment masks the whole task before clipping and sends only redacted task state`).
- `hooks/judge.ts`: `judgeAnswer`, the outcome judge: same key resolution, `clipped` answer as the only state (`{ report: { text } }`), the shared Jev client with its own breaker and gate (a failing judge never turns routing off), `JUDGE_QUESTIONS`, and `nouls` over the reply; never throws, any failure is null with one fixed log line naming the reason code. `tests/judge.test.ts` (`the judge asks the three questions with the redacted answer as the only state and returns the three probabilities`, `the judge masks the whole answer before clipping it to 4000 characters`, `every judge failure is null with one fixed log line, never an error, and a logging failure changes nothing`, `a Noul that is missing, not a number or outside 0..1 makes the whole judge null`); `tests/register.test.ts`: `a failing judge opens only its own breaker: routing still asks Jev afterwards`). Sampling: `tests/judge.test.ts` (`judgeEvery reads 0 as off, N as one in N, and anything not a number as every run`), `tests/register.test.ts` (`by default the judge asks about every completed run`, `judgeEvery 2 judges the first run and every second one after it`, `judgeEvery 0 sends no judge request and writes every outcome with judge null`).
- `hooks/jev.ts`, `hooks/key.ts`, `hooks/redact.ts`: fixed endpoint, user-environment key only, whole-text redaction before clipping, deadline/retry/gate/breaker; `nouls` reads each requested Noul probability, checked one by one. `tests/jev.test.ts` (`one deadline covers the call: a fetch that never answers fails with timeout`, `Noul probabilities are read id by id, and one missing, non-finite or out-of-range value is malformed`), `tests/key.test.ts` (`any repository env declaration of JEV_API_KEY is refused`), `tests/redact.test.ts` (`long quoted and bare secret values are consumed completely, including truncated values`).
- `tests/host.ts`: fake ports and host (`ports`, `world`, `started`, `call`; `world` also fakes `$.fs` and the command registration). The default fake answers serve both the routing questions and the judge's Nouls. Fake coverage is not live routing or judging evidence.
- Checks: [root commands](../../AGENTS.md#commands); type-check with `mise exec -- tsc -p plugins/spider-team/tsconfig.json`.
