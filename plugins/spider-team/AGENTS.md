# spider-team

Usage/privacy: [README.md](README.md). Lead workflow: `skills/using-spider-team/SKILL.md` (simplest path, purposeful briefs, at most two agents at once by default, `SendMessage` for a follow-up, verify answers, review on risk, two attempts then change approach, observable budget, delivery with the validation performed). Each module has a mirror test in `tests/`; the citations below are one reference test per rule, not the full list.

## Modules

- `hooks/register.tsx`: every `on(...)` and `$` call. `session.start` registers the three agents and the `spider-team-stats` command; the `tool.call` hook on `Agent` routes only `spider-team:analyst|planner|reviewer` (the call's `model` and `effort` always overwritten, empty tasks refused, the retired `developer` and `architect` passed untouched) and its `.catch` dispatches the role default when routing fails; the `tool.call` hook on `Bash` is the read-only git guard; `turn.complete` ends background runs; `command.run` prints the stats. Host access stays literal here and goes only to top-level functions of this file (`io`, `files`, `observe`, `record`, `judged`, `roleOfAgent`). Routing rewrites the `Agent` call, not `agent.spawn`, because the spawn takes a model but no effort. The one user option is `judgeEvery`. `tests/register.test.ts` (`a model or effort from the lead is overwritten by the Jev pair, or by the role default without a key`).
- `hooks/roles.ts`: `SPECS` (prompt and tools per role; model and effort from `defaultOf`), `RETIRED_ROLES`, `MODELS` (haiku, sonnet, opus) and `EFFORTS`. No role has Write, Edit or NotebookEdit or delegates, none runs in a worktree; analyst and reviewer have Bash, planner does not. `tests/roles.test.ts` (`three read-only roles keep exact fallbacks and permissions, and none writes or runs in a worktree`).
- `hooks/guard.ts`: pure `shellWords` and `readOnlyGit` (`GIT_READS`, `-C <dir>` and `--no-pager` only as global options, `--output` and `--ext-diff` and their prefixes refused), `refusal`, `UNCHECKED` and the bounded `createRoleCache`. `tests/guard.test.ts`: `anything else is refused: other programs and subcommands, chains, redirection, substitution, unquoted globs and braces, writing options`.
- `hooks/router.ts`: the whole routing policy as pure data: the two Jev questions (`QUESTIONS`), `POLICY` weights, `CALIBRATION` (bumped with any change to the questions, weights, table or floors), the capacity `LADDER` that every cell, floor and default is typed against, `routeOf`, the outcome judge's questions (`JUDGE_QUESTIONS`, `JUDGE_FIRE`, `judgedShort`; they leave `CALIBRATION` alone) and `PRICES`. It imports only types from `roles.ts`. A new model is an edit of `MODELS`, the ladder and the cells. `tests/router.test.ts`: `the table holds every difficulty and duration group cell by cell`.
- `hooks/effort.ts`: `levelOf`, `assessRoute` (both questions with the redacted task, any failure keeps the exact role default) and `clipped` (key, then `redact`, then the 4000-character cut). `tests/effort.test.ts`: `every assessment failure keeps the exact role fallback and logging failure changes nothing`.
- `hooks/judge.ts`: `judgeAnswer` (the clipped answer as `report.text`, its own breaker and gate, never throws), `judgeEvery` and `createSampler`. `tests/judge.test.ts`: `every judge failure is null with one fixed log line, never an error, and a logging failure changes nothing`.
- `hooks/ledger.ts`: pure record builders (`decisionLine`, `afterAgentCall`, `afterTurn`, `withJudge`, `judgeOf`), `verdictOf`, `costOf`, `createPending`, `appendLine` (one process-wide queue, rotation at `ROTATE_AT`), `parseLedger`, `summarize` and `formatSummary`. `tests/ledger.test.ts`: `the summary counts runs, failures, medians, tokens, cost, fallbacks, confidence and the real time per predicted level`.
- `hooks/jev.ts`, `hooks/key.ts`, `hooks/redact.ts`: fixed endpoint, user-environment key only, whole-text redaction before clipping, deadline, retry, gate and breaker; `nouls` checks each probability. `tests/key.test.ts`: `any repository env declaration of JEV_API_KEY is refused`.
- `tests/host.ts`: the fake host (`world`, `started`, `call`, `settle`, `listed`); its default Jev answers serve both routing and the judge. Fake coverage is not live routing or judging evidence.

## Invariants

- Bash from a Spider agent's loop runs only as one read-only git command; the agent's type comes from `$.agent.list()` once per id, and a failed lookup refuses the command. The main loop and other agents pass untouched. `tests/register.test.ts` (`a Spider agent runs only read-only git through Bash; the main loop and other agents pass untouched`, `an agent the list does not name yet is asked about again, and a list that fails refuses the command`).
- The ledger is the plugin's only file (`~/.claude/spider-team/routes.jsonl`, one rotated generation). A decision line goes in before dispatch; an outcome line after the host result has passed on, judged in the background, so the judge never delays the lead. Observation never changes the host result, and its failure is one fixed debug line. `tests/register.test.ts` (`a foreground result goes back before the judge answers, and its outcome is written once the judge does`, `observation survives a failing ledger: the dispatch and its result are unchanged and one debug line names the miss`).
- A line never holds the task, a prompt, an answer, a path, a branch name or a key; the brief and the answer appear only as lengths (`briefChars`, `answerChars`), and the answer, its redacted form and Jev's reply never reach a line or the debug log. `tests/register.test.ts` (`no line ever holds the task, a prompt, an answer, a path, a branch or the key`, `a decision line counts the brief and an outcome line the answer, in characters and never as text`).
- The Jev confidence and the real time per predicted level use only current-calibration decisions; role and pair groups, fallbacks and sizes count every line. `tests/ledger.test.ts` (`the Jev confidence and the real time per predicted level use only current-calibration decisions, and a line without one is calibration 1`, `the brief and answer lengths per role are a median and p90 in characters, and lines without them count in neither`).
- The stats texts carry no plugin-name prefix: the host adds it. `tests/ledger.test.ts`: `the formatted summary is compact and names every part, and an empty ledger says so`.
