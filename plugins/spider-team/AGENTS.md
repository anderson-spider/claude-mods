# spider-team

Usage/privacy: [README.md](README.md). Lead workflow: `skills/using-spider-team/SKILL.md`.

- `hooks/register.tsx`: the four literal `$.agent.register` calls in `session.start` and the one `tool.call` hook on `Agent`. It routes only the four exact Spider types (Jev through the router table, else the role default; the call's own `model` and `effort` are always overwritten, never refused), refuses empty tasks and a developer without merged `worktree.baseRef: "head"`, and on any other failure its `.catch` dispatches the call unchanged. No other hooks, tools, state or files, and no user options. `tests/register.test.ts` (`session start registers the four native agents and no tools`, `Jev picks the pair for a Spider role, shown in its description, and other agents pass untouched`, `a model or effort from the lead is overwritten by the Jev pair, or by the role default without a key`, `Jev is asked both questions and bang and at-sign words reach it as written`, `a default spawn of every role from a marketplace install runs natively with its role default`, `empty tasks and a developer without baseRef head are refused before dispatch`, `a routing failure dispatches the call unchanged once`).
- `hooks/roles.ts`: the role table (`SPECS`: prompt, tools, developer `isolation: "worktree"`; model and effort come from `defaultOf` in `hooks/router.ts`) and `MODELS`/`EFFORTS`, the only lists the router is typed against. Routing changes only model and effort. Readers have no Write/Edit; reviewer's Bash is limited by its prompt to read-only git. `tests/roles.test.ts` (`four roles keep exact fallbacks permissions and isolation`, `only exact role names are recognized`).
- `hooks/router.ts`: the whole routing policy, pure data and no host access: the two Jev questions (`QUESTIONS`: difficulty, duration), the penalty weights (`POLICY`), the difficulty labels, the duration groups, `ROUTES` (difficulty x duration group to a pair, typed so tsc fails on an unknown model or effort or a missing cell) and `ROLE_CELLS` (each role's default is a cell). It imports only types from `roles.ts`, so there is no runtime cycle. A new model is an edit of `MODELS` and the cells. `tests/router.test.ts` (`the table holds every difficulty and duration group cell by cell`, `every cell is a known model and effort and the levels match the questions`, `duration levels 0 and 1 are short, 2 medium and 3 long when routing by level`, `role defaults are table cells and the registered definitions carry them`).
- `hooks/effort.ts`: carries out the router's policy: `levelOf` (expected penalty with the router's weights, ties low) and `assessRoute` (always asks both questions with the redacted task as written, no local decision or partial question; any assessment failure keeps the exact role default). `tests/effort.test.ts` (`two questions carry the difficulty and duration criteria and nothing else`, `the level minimizes expected penalty with under-capacity weighted twice and ties going lower`, `Jev levels select the pair from the table, grouping duration after the level is chosen`, `every assessment failure keeps the exact role fallback and logging failure changes nothing`, `assessment masks the whole task before clipping and sends only redacted task state`).
- `hooks/jev.ts`, `hooks/key.ts`, `hooks/redact.ts`: fixed endpoint, user-environment key only, whole-text redaction before clipping, deadline/retry/gate/breaker. `tests/jev.test.ts` (`one deadline covers the call: a fetch that never answers fails with timeout`), `tests/key.test.ts` (`any repository env declaration of JEV_API_KEY is refused`), `tests/redact.test.ts` (`long quoted and bare secret values are consumed completely, including truncated values`).
- `tests/host.ts`: fake ports and host (`ports`, `world`, `started`, `call`). Fake coverage is not live routing evidence.
- Checks: [root commands](../../AGENTS.md#commands); type-check with `mise exec -- tsc -p plugins/spider-team/tsconfig.json`.
