# spider-team

Usage/privacy: [README.md](README.md). Lead workflow: `skills/using-spider-team/SKILL.md`.

- `hooks/register.tsx`: the four literal `$.agent.register` calls and the `$.command.register` of `spider-team-stats` in `session.start`, the `tool.call` hook on `Agent`, the `turn.complete` hook and the `command.run` hook of the stats command. It routes only the four exact Spider types (Jev through the router table and the role floor, else the role default; the call's own `model` and `effort` are always overwritten, never refused), refuses empty tasks and a developer without merged `worktree.baseRef: "head"`, and when routing fails before dispatch its `.catch` dispatches the role default pair (pure, no host calls; `next.called` replays an already dispatched call instead). Host access stays literal here and is passed only to top-level functions of this file (`io`, `files`, `observe`, `record`). No other hooks, tools, user options or files. `tests/register.test.ts` (`session start registers the four native agents and the stats command, and no tools`, `Jev picks the pair for a Spider role, shown in its description, and other agents pass untouched`, `a model or effort from the lead is overwritten by the Jev pair, or by the role default without a key`, `Jev is asked both questions and bang and at-sign words reach it as written`, `a default spawn of every role from a marketplace install runs natively with its role default`, `empty tasks and a developer without baseRef head are refused before dispatch`, `a routing failure dispatches the role default once, never the lead model and effort, and writes no record`).
- Local ledger: the plugin's only file, `~/.claude/spider-team/routes.jsonl` (one rotated generation, `routes.1.jsonl`), JSON lines written from `register.tsx` through `$.fs`. A decision line goes in before dispatch; an outcome line after a foreground `Agent` result, or, for an `async_launched` result, from the `turn.complete` of that `agentId` (an in-memory map of at most 200 entries, dropped on reload). Observation returns the host result unchanged and a failure of its own is one fixed debug line (`spider-team: decision not recorded`, `spider-team: outcome not recorded`); an unreadable ledger is never overwritten. A line never holds the task, prompt, answer, path, branch name or key (`tests/register.test.ts`: `a decision line and a foreground outcome line are written, and the host result passes on as it came`, `a background launch is written when its turn completes, with the verdict from the final text`, `an aborted background agent is an aborted outcome`, `no line ever holds the task, a prompt, an answer, a path, a branch or the key`, `observation survives a failing ledger: the dispatch and its result are unchanged and one debug line names the miss`, `a refused or failed Agent result writes no outcome and passes on`). The stats command reads both files and prints `formatSummary` (`tests/register.test.ts`: `the stats command summarizes the local ledger, and says so when there is none or it cannot be read`).
- `hooks/ledger.ts`: pure record builders (`decisionLine`, which tags the line with the router's `calibration`; `afterAgentCall`, `afterTurn`, each field projected one by one), `verdictOf`, `costOf` (from `PRICES`), the bounded `createPending`, `appendLine` (one process-wide queue, whole-file read then write, rotation at `ROTATE_AT`), `parseLedger`, `summarize` and `formatSummary`. Failures are error/aborted/refusal runs and reviewer CHANGES or BLOCKED; the duration check joins a decision's predicted group to the real bucket (under 10 min short, 10 to 30 medium, over 30 long). The Jev confidence and the duration check use only decisions of the current `CALIBRATION` (a line without the field is calibration 1), and the summary names how many older ones they left out (no line when none); role/pair groups and fallbacks count every line. A decision line carries each dimension's full distribution as `dist` (only the question's level keys, finite probabilities rounded to two decimals; null without Jev). The stats texts carry no plugin-name prefix: the host adds it. `tests/ledger.test.ts` (`a decision line projects only the allowed fields and rounds the probabilities to two decimals`, `a decision line keeps each full distribution with only its level keys and finite probabilities`, `only the verdict word of a reviewer answer is extracted`, `the estimated cost follows the list prices of the resolved model family`, `a finished foreground run becomes one outcome line with usage, cost and a reviewer verdict, and nothing else of the result`, `a tool error is an error outcome, a background launch is awaited, and a refusal or unknown shape writes nothing`, `a background end becomes an outcome line from its turn: duration, usage, reason, abort and the reviewer verdict`, `the background map is bounded, drops the oldest and gives each agent once`, `appends are serialized so concurrent lines all survive in order, and one failed append does not stop the next`, `a ledger that cannot be read is never overwritten, and a full one moves to its rotated generation`, `parsing skips malformed and foreign lines and counts a repeated line once`, `the summary counts runs, failures, medians, tokens, cost, fallbacks, confidence and the duration check`, `the formatted summary is compact and names every part, and an empty ledger says so`, `the Jev confidence and the duration check use only current-calibration decisions, and a line without one is calibration 1`).
- `hooks/roles.ts`: the role table (`SPECS`: prompt, tools, developer `isolation: "worktree"`; model and effort come from `defaultOf` in `hooks/router.ts`) and `MODELS` (haiku, sonnet, opus; no fable)/`EFFORTS`, the only lists the router is typed against. Routing changes only model and effort. Readers have no Write/Edit; the reviewer's Bash is limited by its prompt to read-only git over the `base..HEAD` range and uncommitted changes; the developer commits locally in its worktree (Conventional Commits in English, no AI attribution), never pushes, never commits on main, master, develop or a release branch, and reports worktree path, branch, base and commit SHAs. `tests/roles.test.ts` (`four roles keep exact fallbacks permissions and isolation`, `the developer commits locally with Conventional Commits, never pushes or commits on a protected branch, and reports its commits`, `the reviewer compares the base..HEAD commits and uncommitted changes with read-only git commands only`, `only exact role names are recognized`).
- `hooks/router.ts`: the whole routing policy, pure data and no host access: the two Jev questions (`QUESTIONS`: difficulty, judged on the work and not the brief's length; duration on a coding agent's scale, under 3, 3 to 10, 10 to 30, over 30 minutes), the penalty weights (`POLICY`: under-capacity 1.25, over-capacity 1), `CALIBRATION` (the number each decision line carries, bumped with any change to `QUESTIONS`, `POLICY` or the table), the difficulty labels, the duration groups, the capacity `LADDER` (one ordered list of rungs; `ROUTES`, `ROLE_POLICY` floors and defaults are typed as rungs, so tsc fails on anything else), `routeOf` (cell, then the floor: the stronger of the two on the ladder) and `PRICES` (list prices, USD per million tokens). Defaults need not be table cells. It imports only types from `roles.ts`, so there is no runtime cycle. A new model is an edit of `MODELS`, the ladder and the cells. `tests/router.test.ts` (`the table holds every difficulty and duration group cell by cell`, `the capacity ladder is the one ordered list every cell, floor and default belongs to`, `no pair is below its role floor for any cell, Haiku never runs at low and Fable is out`, `duration levels 0 and 1 are short, 2 medium and 3 long, and the floor lifts a weaker cell`, `role floors and defaults are fixed and the registered definitions carry the defaults`, `the questions judge the work itself on a coding agent's time scale, not the length of the brief`, `the questions match the levels and the prices are the October 2026 list prices`, `the calibration that tags each decision line is 2`).
- `hooks/effort.ts`: carries out the router's policy: `levelOf` (expected penalty with the router's weights, ties low) and `assessRoute` (always asks both questions with the redacted task as written, no local decision or partial question; returns the raw cell, the floor-adjusted pair, whether the floor applied, the levels, the top probability and normalized distribution per dimension, the source, the Jev reason and latency; any assessment failure keeps the exact role default). `tests/effort.test.ts` (`two questions carry the difficulty and duration criteria and nothing else`, `the level minimizes expected penalty with under-capacity weighted 1.25 and ties going lower`, `Jev levels select the pair from the table, grouping duration after the level is chosen`, `the choice carries the raw cell, the floor result, the levels, the top probability and full distribution of each dimension and the Jev latency`, `every assessment failure keeps the exact role fallback and logging failure changes nothing`, `assessment masks the whole task before clipping and sends only redacted task state`).
- `hooks/jev.ts`, `hooks/key.ts`, `hooks/redact.ts`: fixed endpoint, user-environment key only, whole-text redaction before clipping, deadline/retry/gate/breaker. `tests/jev.test.ts` (`one deadline covers the call: a fetch that never answers fails with timeout`), `tests/key.test.ts` (`any repository env declaration of JEV_API_KEY is refused`), `tests/redact.test.ts` (`long quoted and bare secret values are consumed completely, including truncated values`).
- `tests/host.ts`: fake ports and host (`ports`, `world`, `started`, `call`; `world` also fakes `$.fs` and the command registration). Fake coverage is not live routing evidence.
- Checks: [root commands](../../AGENTS.md#commands); type-check with `mise exec -- tsc -p plugins/spider-team/tsconfig.json`.
