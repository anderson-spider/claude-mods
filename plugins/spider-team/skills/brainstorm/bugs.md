# Bugs

A bug is fixed against one command that goes red on it. Main follows these steps. A worker given a bug gets this file's path in its brief, with the red command when it exists and the regression test to write; what a step shows the user or puts in a commit or PR (the hypotheses, a request for access, the confirmed cause), the worker puts in its report for Main instead.

1. **Feedback loop.** Build one command that drives the bug's code path and asserts the user's exact symptom, not "runs without error". In rough order of preference: a failing test at a seam that reaches the bug, a curl or CLI script against a fixture, a headless browser script, a captured payload replayed through the code path, a throwaway harness, a property loop for "sometimes wrong", a `git bisect run` script between a good and a bad state, the same input through two versions. Make it fast and deterministic (pin time, seed randomness, isolate the filesystem); for a flaky bug, raise the reproduction rate (loop it, add stress) until it fails often enough to debug. Run it and show the command and its red output before reading code for a theory. When no command can reproduce it, stop, say what you tried, and ask the user for access to where it happens, a captured artifact or permission to instrument.
2. **Minimise.** Check that the red is the user's symptom, not a nearby failure. Cut inputs, callers, config and steps one at a time, rerunning after each cut, until removing any remaining element turns it green.
3. **Hypothesise.** Write 3 to 5 ranked hypotheses before testing any, each with the prediction that would falsify it: "if X is the cause, changing Y makes the bug go away". Show the list to the user without waiting for an answer.
4. **Instrument.** One probe per prediction, one variable at a time, a debugger before logs. Tag every debug log `[DEBUG-<four hex digits>]`. For a performance regression, measure a baseline first, then bisect.
5. **Fix.** Turn the minimised repro into a test at a seam that exercises the bug's real call pattern. When the only seam is too shallow to reach it, write no test there: report the missing seam as a finding and say how the fix was verified instead. Watch the test fail; when you forced the red by changing code or a fixture, diff against the pristine file to prove the change landed. Fix, watch it pass, then rerun the original command.
6. **Clean up.** Grep the debug tag and remove every hit, delete throwaway harnesses, and state the confirmed cause in the commit or PR.

Redact secrets in every command, output and artifact you show, brief or note: `<REDACTED>` in place of keys, tokens, cookies and auth headers. Build commands on environment variables, so the secret stays out of what you show.
