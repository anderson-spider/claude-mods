# codex-computer-use

Setup, use, privacy or live desktop checks: read [README.md](README.md). MCP app-approval elicitation belongs to the helper; the plugin cannot answer it.

## Map and safety

- `hooks/register.tsx`: registration/routing; `bridge.ts`: call/approval rounds; `question.ts`: queued question with injected clock/wait/band; `routing.ts`: bridge name, own-tool test, lease and approval limit; `presentation.ts`: pure reply, command, bridge and approval-band text; `prompts.ts`: prompt, tool schema and `denyOwn`, the model guidance that steers to the bridge (kept beside `PROMPT`, not in `presentation.ts`); `helper.ts`: socket link, with `postStarting` (start-on-demand, injected probe); `commands.ts`: the `/codex-cu` table; `model.ts`: wire types.
- `/codex-cu` commands: `commands.ts` `COMMANDS` is the only list; parse, `HELP` and the registered description come from its rows, whose help lines and synopses are `COMMAND_TEXT` in `presentation.ts`. A new subcommand is one row, its `COMMAND_TEXT` entry and a handler in `register.tsx` (the `Handlers` type fails until it exists). Pinned by `tests/command-table.test.ts` (`parse: every subcommand, its case and spacing, and what falls back to help`, `HELP is the fixed six-line text and every unknown or malformed input answers it`, `session start registers /codex-cu with the one-line command synopsis`) and `tests/command-rows.test.ts`.
- `postStarting` starts the helper through launchd once and polls twenty times with `sleep 0.25` through `process.run` (waiting in `$.clock.sleep` would spend the hook's time); a start that fails returns the first reply and a rejecting probe rejects. `session.end` does not use it: one `post` release, no kickstart or retry (the hook's budget is shared and 1.5 s), any failure swallowed (`tests/session-end.test.ts`). The own-desktop-tool guard has a `.catch` (`holdOwnDesktop`) that re-checks `isOwnDesktopTool`, so a failed hook still refuses the plugin's own tools. `tests/helper.test.ts` (`postStarting returns the reply of poll N after N polls of sleep 0.25`, `postStarting gives up after twenty polls and returns the first reply; the count can be set`).
- `helper/helper.mjs`: Unix-socket entry point, one `ROUTE_TABLE` entry per route (`helper/test/routes.test.mjs` pins the check order and every status and body); `helper/lib/hub.mjs`: sessions/ownership/approvals, with what each approval decision does (slot, claim, stop, answer) in one `DECISION_EFFECTS` row (`helper/test/hub-effects.test.mjs` pins every row, unlisted decisions and teardown order); `approvals.mjs`: policy (`decide`); `codex-approvals.mjs`: saved list; `apps.mjs`: app names and bundle ids; `owners.mjs`: per-app holder; `mcp-client.mjs`: stdio MCP client; `version.mjs`: helper version; `config.mjs` and `helper/launch.mjs`: connection.
- Helper is Node ESM, run by the ChatGPT app's `node`; `helper/install.sh` installs LaunchAgent `com.anderson-spider.codex-cu` in `~/.claude/mcp/codex-cu`.
- Socket `run/helper.sock` and approvals `state/approvals.json` are fixed beside installed `helper.mjs`. Neither installer nor uninstaller edits Claude settings; uninstall retains code/approvals/logs. Install accepts only `--check` or no arguments; uninstall takes none (`helper/test/config.test.mjs`).
- Shared contract: routes, choices, reply key sets (`replies`), lease and LaunchAgent label are written once per side and pinned by `helper/test/contract.mjs`, which both test halves compare (`tests/contract.test.ts`, `helper/test/contract.test.mjs`); hooks never import helper modules at runtime. Update together: `contract.mjs`; `hooks/model.ts` (`ROUTES`, `CHOICES`, `RouteReplies`, the only reply-shape source), `routing.ts` (`LEASE_MINUTES`), `helper.ts` (`LABEL`); `helper.mjs` (`ROUTES` and its `ROUTE_TABLE` entry), `lib/approvals.mjs` (`CHOICES`), `lib/hub.mjs` (`LEASE_MS` and the reply keys); `install.sh` and `uninstall.sh` (`LABEL=`). The tool input is typed in `types/index.d.ts`; its keys match `prompts.ts` `INPUT_SCHEMA` at compile time, and the `tool.call` matcher in `register.tsx` is the literal tool name (equal to `routing.ts` `TOOL`).
- Bump `helper/lib/version.mjs` when helper behavior changes; users rerun `install.sh` to load it.
- App approvals expire five minutes from **before entering the queue**; clock/poll failure must never approve. Coverage: `tests/question.test.ts`; Claude desktop-tool refusal while on: `tests/register.test.ts`.

## Checks

- `claude plugin validate plugins/codex-computer-use`; `claude plugin test plugins/codex-computer-use`; `node scripts/check-consistency.mjs`.
- `/Applications/ChatGPT.app/Contents/Resources/cua_node/bin/node --test plugins/codex-computer-use/helper/test/*.test.mjs`.
- `helper/test/contract.mjs` is the shared caller, socket, route, choice, lease and label evidence. Host timeout tests inject `clock.now` and release held polls; helper tests use injected fakes or an isolated copied installation, never installed run/state directories.
