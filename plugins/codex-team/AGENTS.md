# codex-team

Usage/privacy: [README.md](README.md). Activation and the lead's workflow: `skills/using-codex-team/SKILL.md`.

- `hooks/register.tsx`: the literal `session.start` registrations of `dispatch` and `finish` (`inputSchema ... satisfies SchemaFor<McpToolInputs[...]>`) and their `tool.call` hooks; `teamIo` and `dagrIo` hold injected I/O with literal host calls in the entry module (each `$.env.get` takes a literal name). `hooks/schema.ts`: the type-only `SchemaFor`.
- Bash observation: after `next(e)`, main-session and subagent calls compare the newest regular plan's path, mtime and size with the publisher's last successful publication. Fingerprint checks share the per-root publication queue; unchanged plans need one listing and no reads or processes. Missing directories require an existence check only after the listing fails; failed publications leave the previous fingerprint for retry (`tests/publish.test.ts`: `an unchanged published plan needs only one listing with no reads, stats or processes`, `path, mtime and size changes publish once through the same queue and only successful publications advance the fingerprint`, `fingerprints are independent per root and plan observation skips absent directories and nonregular plans`, `changed plan observation publishes nothing when dagr is unavailable or outside Herdr`). Commands are never parsed, and Bash results pass through even after partial shell failures. Observation/publication failures log one debug line and retain the old run (`tests/register.test.ts`: `Bash plan edits in the main session and subagents publish once after the result without inspecting the command`, `Bash with an unchanged plan returns the result with one listing and no reads or publication`, `Bash observation and publication failures preserve its result and the old run with one debug line`, `a debug logging failure cannot throw into the observed Bash result`).
- `hooks/roles.ts`: the role table (`SPECS`: model, effort, whether it writes, instructions), logical role names and `codexArgs`. `hooks/names.ts`: lossless workspace tokens and logical/effective Herdr name mapping. `hooks/report.ts`: the brief and report path `reports/<repository>/<workspace-token>/<slug>-<role>.md`, using the token from `hooks/names.ts`. All role replies/briefs and the reviewer’s developer report use the same workspace namespace (`tests/team.test.ts`: `equal roots and slugs in different workspaces get distinct report paths in every reply and brief`). `hooks/herdr.ts`: `deliver` over an injected runner (task/shared-role tab or split, safe retirement, one writer per directory, start, prompt and delivery status). `hooks/finish.ts`: safe pane closure and post-exit archival. `hooks/team.ts`: queued `dispatch`/`finish`, the Herdr check, input checks, the developer’s worktree, the small per-workspace/root/slug store record and the decision record. `hooks/decisions.ts`: record shape, path and write.
- Reviewer: required slug and optional extra focus; recorded developer cwd/original task/report drive its generated review brief, which is also the task text assessed by Jev. Use `architect-<slug>`, `SPECS.reviewer` instructions and report-only cwd/roots. Jev and all pins apply exactly as for other roles; default is Sol/high, with the Astra cap applied to any selected pair. Every dispatch starts fresh after safe retirement. Refuse undispatched slugs and working/blocked developers before mutation; deliver rechecks the developer on its fresh listings (`tests/team.test.ts`: `reviewer refuses an undispatched slug or a working or blocked developer before any effect`, `reviewer builds its recorded review brief and applies pinned effort with report-only permissions`, `reviewer followup falls back to its role default after safe retirement and honors the Astra cap`, `reviewer profile and structured pins apply with dimensional pins ignored only for explicit pairs`, `reviewer dimension pins score locally or ask Jev only remaining questions using the redacted review brief`, `reviewer rechecks done to working or blocked on the delivery listing before pane, startup or prompt effects`; `tests/register.test.ts`: `reviewer routes its generated review brief through host Jev and accepts profile pins`; `tests/roles.test.ts`: `reviewer role default is Sol high and keeps report-only instructions`). Report fields in `hooks/report.ts`: verdict, risk, findings, checks.
- Developer context: preserve the first task/cwd across followups; another cwd needs another slug. Every followup starts a fresh session in the same persistent worktree and its brief remains self-contained. For a previously dispatched developer, include the fixed reminder to read its previous report and worktree git diff (`tests/report.test.ts`: `developer followup briefs recover context from the previous report and persistent worktree diff`). A refused first delivery leaves no context; unknown retains it (`tests/team.test.ts`: `developer followups keep the original task and cannot move the recorded slug to another worktree`, `a developer prompt refused before delivery does not authorize reviewer while an unknown delivery keeps its record`). All dispatch and finish calls use one in-module promise queue, including listing, tab creation, startup, prompt and context access. A failed delivery deletes only the context that call created; a failed call releases the queue (`tests/team.test.ts`: `concurrent developer and fallback analyst dispatches create one task tab without interleaving`, `concurrent shared analyst and architect dispatches create separate current task tabs`, `a concurrent not_sent preserves the first developer task record and only the creator cleans up a refused prompt`, `a failed dispatch does not poison the global queue for a later call`). Decision records still contain only the task hash.
- Names/tabs: logical names stay `analyst`, `architect`, `dev-<slug>`, `analyst-<slug>` and `architect-<slug>`; slug has at most 22 characters, never truncate (`tests/roles.test.ts`: `task slugs stop at 22 characters without truncation and reviewers use the architect name`). Effective names use a role letter (`n`, `a`, `d`), a workspace token and optional complete `-<slug>`. Encode case-sensitive `w` + base-62 digits losslessly to base-36 with a sentinel preserving leading zeroes; refuse unsupported IDs or tokens above eight characters before effects (`tests/names.test.ts`: `workspace tokens preserve case and leading zeroes without hashing or collisions`, `all effective roles retain the full longest slug within the Herdr charset and 32 characters`, `unsupported workspace ids and invalid logical names fail closed without truncation`). Dispatch answers and records keep both identities; CLI wait/get hints use the effective name and finish takes the logical one (`tests/team.test.ts`: `unknown delivery hints use the effective Herdr name while finish accepts only the logical name`).
- Workspace isolation: busy/retirement, reviewer/developer, cwd, one-writer and anchor checks use only this workspace's namespaced agents. Legacy unnamespaced agents are not adopted. A foreign shared analyst does not trigger fallback; a busy/blocked local analyst still uses `analyst-<slug>`. An actual effective-name collision anywhere in the global listing or a startup refusal fails closed (`tests/herdr.test.ts`: `a foreign shared analyst does not block dispatch or trigger the local fallback`, `equal logical names in distinct workspaces start distinct global Herdr agents`, `foreign developers do not affect writer cwd reviewer or fallback pane checks`, `a real effective name collision fails closed before retirement or startup including analyst fallback names`, `a name collision discovered at startup never sends a prompt`; `tests/team.test.ts`: `foreign shared roles and equal developer or reviewer names do not block local dispatch`, `workspace-specific developer context and decision paths do not cross with equal roots slugs and timestamps`, `unsupported workspace ids refuse dispatch and finish before any IO effect`). Developer context includes workspace/root/slug; decision filenames use effective names.
- Task tabs: named task agents share `codex - <slug>`, anchored to a live peer of the same slug in this workspace. Every tab uses exactly `codex - <slug>`, the main task represented by the dispatch slug. One-shot shared analyst/architect create separate tabs with their current dispatch slug, so no persistent label registry or relabeling is needed. Never use focus to find an anchor; create/split with `--no-focus`. The lead finishes task agents when their task closes; worktrees are retained (`tests/herdr.test.ts`: `task tabs anchor only to live agents of the same slug and shared roles get labelled tabs`, `a shared role gets its own current task tab even with another shared role live`, `a task without live peers creates its own tab even when other team agents are live`, `a busy shared analyst fallback retires its settled task analyst before a fresh session`, `task and shared tabs anchor only inside the dispatch workspace`, `every shared and named agent tab uses exactly codex dash and the main task slug`; `tests/team.test.ts`: `concurrent shared analyst and architect dispatches create separate current task tabs`).
- Pane label: after a successful start, deliver renames the pane to `<logical name> (<model>/<effort>)` from the start argv (`paneLabel`); display only, a refused rename changes nothing (`tests/herdr.test.ts`: `the pane shows the logical name with the started model and effort, and a refused rename changes nothing`).
- Plan projection: `hooks/plan.ts` parses only Steps, headings with work become T1/T2 in order, and validates owners, states, IDs, all dependencies and cycles. A code fence closes only on the same marker with at least the opening length and no trailing text (`tests/plan.test.ts`: `Steps headings with work become ordered deliverables and keep every cross-project dependency and note`, `unknown dependencies, duplicates, cycles, malformed steps, owners and states are validation errors`, `nested and mixed fences close only with the opening marker and enough characters`, `Dispatches and every other section outside Steps are ignored even when they contain step-shaped lines`). `hooks/dagr.ts` builds v3: blocked keeps its note as unblocker, verified/committed use reported receipts, first-seen times survive in times.json under keys containing plan id, step id and state, main/git-master use the orchestrator pane, and Codex workers get only their own live agent pane. Publication filters to HERDR_WORKSPACE_ID and maps effective names to logical owners (`tests/publish.test.ts`: `publication maps effective names to logical owners only in the dispatch workspace`). Implementing without a locator projects as blocked with the owner named in the unblocker and no attempt, keeping dependencies and notes (`tests/dagr.test.ts`: `Dagr keeps dependencies, blocked unblockers, reported receipts and only live worker locators`, `first-seen timestamps survive repeated projections and plan state changes without mutating the input times`, `plans sharing a step id keep independent first-seen times and reuse only their own observations`, `implementing main and git-master use the orchestrator pane while Codex agents use their own pane`, `implementing without a locator becomes blocked with an owner unblocker, preserving dependencies and notes`). One attempt for implementing with a locator or done; no attempt histories or gates.
- Publishing: `hooks/publish.ts` selects the newest regular plan, serializes per-root candidates, writes run.json.tmp with fs, accepts only strict validator exit 0 and complete [], then mv. Any failure retains the old run and logs one line; a missing dagr logs once per module load. Resolve literal DAGR_BIN, PATH, then the first usable HOME/.config/herdr/plugins/github/herdr-dagr-*/bin/dagr match through injected I/O; environment names and host calls stay literal in register.tsx (`tests/publish.test.ts`: `publishing selects the newest plan, writes a temp file and validates strictly before moving it`, `publication admits implementing lead and git-master and blocks absent workers under the strict locator rule`, `nonzero, empty, malformed, truncated or nonempty validator output never publishes and preserves the old run`, `missing dagr logs once when override, PATH and installed plugin discovery all fail`, `an explicit DAGR_BIN with spaces is passed as one argv element before PATH or discovery`, `dagr installed outside PATH is discovered under HOME without a fixed hash and paths with spaces stay one argument`, `unknown dependency errors are reported and write, list, times or rename failures preserve the previous run`, `publication serializes candidates per root and retains first observations on the next dispatch`). Dispatch publishes after delivery; successful plan Write/Edit hooks await next and return its result unchanged (`tests/team.test.ts`: `dispatch publishes the plan after delivery and uses the actual fallback analyst in its decision`; `tests/register.test.ts`: `successful plan Write and Edit publish after the result and return the host result unchanged`, `failed plan writes and successful unrelated writes do not publish and preserve the result`).
- `hooks/jev.ts` and `hooks/redact.ts`: injected HTTP/timer/clock, deadline, retry, breaker, gate and redaction, without cross-plugin runtime imports. Only requested answer dimensions are admitted before assessment validation; choice criteria are a map and probabilities remain distributions (`tests/jev.test.ts`: `choice criteria pass through retries and requested answers discard hostile extra dimensions`). `hooks/key.ts`: printable key check and project/local env refusal. `hooks/effort.ts`: one profile table for every role, four questions, validated pins, normalization and expected asymmetric penalty implemented from the described formula. Points, rank and affinities are policy priors; `astra-high` uses difficulty/duration/scope 4/2.2/3, rank 7 and Sol affinities, with no `astra-xhigh`. Filter disallowed candidates before scoring, including fully pinned dimensions. Weights D/d/S/task_type = 1/1/0.5/0.25; round dimensions and total to four places; ties use rank then original order (`tests/effort.test.ts`: `one profile table reaches all seven profiles regardless of role`, `penalty integrates distribution tails and rounds each dimension and total to four places`, `choice penalty uses exact affinity then wildcard then default one`, `equal penalties prefer rank then original order`, `four questions carry score criteria and a choice criteria map`, `probabilities normalize omitted entries and absent choice uses a uniform prior`).
- `hooks/model-policy.ts`: effective `allowAstra` true permits Astra (manifest default true); project/local declarations under `codex-team` or `codex-team@...`, wrong types and unreadable settings fail closed independently of Jev. Options and readers are injected from literal host calls in register.tsx. Model/profile and effort-only inherited Astra pins refuse immediately after parsing; revalidate the selected pair before codexArgs, outside the evaluation catch. A typed lazy refusal becomes not_sent before pane/start/prompt, with all applied/started flags false; decision v3 stays unchanged (`tests/model-policy.test.ts`: `only effective true allows Astra and absent settings files keep it allowed`, `own repository declarations refuse Astra for both sources and plugin aliases regardless of value`, `other plugins and configs without an own allowAstra declaration are ignored`, `read rejection and malformed pluginConfigs turn Astra off without disabling other models`; `tests/team.test.ts`: `disallowed Astra model profile and inherited effort pins refuse before any mutation or Jev`, `lazy Astra refusal becomes not_sent with no pane prompt context or applied flags`, `Astra off keeps Jev enabled and filters expert automatic and fully pinned local candidates`, `authorized Astra Jev local and explicit pairs agree in startup answer and decision for every role`, `Astra followup pins recheck permission before retiring developer or reviewer predecessors`, `Jev Astra selection is capped defensively and revoked permission refuses before pane creation`; `tests/herdr.test.ts`: `a typed startup refusal returns not_sent before any pane start or prompt`; `tests/register.test.ts`: `manifest default allowAstra permits Astra through the host`, `host unreadable settings refuse an Astra pin with the fixed message`; `tests/effort.test.ts`: `Astra permission filters before scoring and preserves the six existing policy profiles`, `Astra model and astra-high profile pins are accepted without an astra-xhigh profile`).
- Profile/privacy: literal `$.env.get('JEV_API_KEY')` stays in register.tsx, no userConfig key. A project/local declaration or unreadable settings disables Jev (`tests/key.test.ts`: `settings that cannot be read turn Jev off`, `any repository env declaration of JEV_API_KEY is refused`; `tests/team.test.ts`: `project and local key declarations both refuse Jev without any request`). Structured model/effort and profile pins bypass Jev and key settings; Astra permission checks still apply; missing structured fields use SPECS. Explicit pairs override dimensions; all dimensions pinned score locally, partial pins ask only remaining questions. All roles accept pins; malformed pins still refuse before effects (`tests/team.test.ts`: `model effort and profile pins bypass Jev key settings and dimensional pins are ignored for explicit pairs`, `all dimension pins score locally and partial pins ask only remaining questions after cleaning`, `invalid pins and directive-only tasks refuse before effects with fixed messages`). Any access/assessment failure uses the exact SPECS pair, subject to cap, and marks dimension pins unused (`tests/team.test.ts`: `every Jev failure falls back to the role default with only a fixed reason`, `malformed choice falls back to the exact role pair and does not use dimension pins`).
- Assessment: role stays fixed and owns instructions, writes and roots; profiles change only model/effort flags (`tests/roles.test.ts`: `profile pairs change only model and effort flags while the role keeps instructions sandbox and roots`). Tokens are whitespace-delimited outside quotes, inline code and matching fences; escapes preserve literal markers. Remove recognized directives without rebuilding task text before redaction, brief, context and hash; unknown profiles, invalid pins and contradictions produce one fixed error (`tests/effort.test.ts`: `directives respect escapes quotes inline code and matching fences without rebuilding the task`, `unknown profiles invalid pins and contradictions use one fixed error without echoing text`). Only cleaned task text reaches Jev, redacted before the 4000-character cut, key only in Authorization (`tests/team.test.ts`: `the request contains only redacted cut task text and the key only in Authorization`). Dispatch v3 has selection or null, modelApplied/effortApplied, assessment metadata, normalized task_type, validated pins and usage, task hash and delivery metadata; no task text, raw directives, paths, keys, bodies or startup store. Finish remains v2 with its own filename. Nested metadata is explicitly projected (`tests/decisions.test.ts`: `dispatch v3 projection and finish v2 retain only allowed metadata and distinct filenames`; `tests/team.test.ts`: `Jev profile choices reach every role start flag answer and v3 record`).
- Redaction: scan complete named values in linear time, handling quoted/encoded escapes and EOF truncation before the 4000-character cap; preserve neighboring fields and idempotence. Recognize flag-attached absolute and UNC paths regardless of context (`tests/redact.test.ts`: `long quoted and bare secret values are consumed completely, including truncated values`, `flag-attached absolute paths and UNC paths are redacted without a home or root context`; `tests/team.test.ts`: `fake HTTP receives no long or truncated secret value and no flag-attached or UNC absolute path`). Keep the existing hostile-input performance check.
- Path recognition: separate short option names (`-I`, `-L`, `-isystem`) from their glued arguments and long options at `=`; relative arguments stay intact. UNC needs a host/share shape, not just a backslash run: quoted regex/string escapes survive while real unfinished UNC paths stay masked with linear scanning (`tests/redact.test.ts`: `relative flag paths and quoted escapes stay intact while absolute arguments remain masked`, `unfinished quoted UNC paths are consumed in linear time without leaking their tail`; `tests/team.test.ts`: `fake HTTP preserves relative flag paths and quoted escapes while masking absolute and truncated UNC paths`).
- Application: every dispatch starts a fresh Codex session. deliver retires every idle/done predecessor through the same safe finish callback, then lists again and rechecks writer/reviewer guards before startArgs and pane creation. Working/blocked, unknown, foreign, unavailable/failed retirement and reappearing targets refuse without selection or prompt (`tests/herdr.test.ts`: `every idle or done team agent is retired before a fresh pane session and prompt`, `startup selection is lazy once after guards and shared finish with the actual fallback name`, `startup selection never runs for busy foreign writer conflicts or unavailable or failed finish`, `retirement failures and a reappearing name refuse every role without selection or a new prompt`, `post-retirement listing rechecks writer exclusivity and reviewer developer state before selection`). Eligible followups apply fresh pins and choose again; no reuse branch or reply. Both applied flags equal delivery.started; duration includes lazy assessment (`tests/team.test.ts`: `developer reviewer and task analyst followups retire prior sessions and apply fresh startup pins`, `settled sessions choose fresh pairs only after archive and dispatch duration includes assessment`, `refused deliveries and failed shared finish never read settings or ask Jev`, `an agent that failed to start never records its chosen effort as applied`, `working and blocked live agents refuse before profile selection`, `working and blocked named predecessors refuse without retirement settings or Jev`; `tests/herdr.test.ts`: `beforeSend records the fresh start after retiring a named predecessor`).
- Fast: every model starts with `-c service_tier="priority"`, including Luna, Sol and Astra (`tests/roles.test.ts`: `every role and model starts with the priority service tier including luna, sol and astra`).
- Astra effort: any model id containing astra caps xhigh to high after explicit/default/Jev selection. Permitted automatic profiles include Astra/high alongside Sol/Luna. startEffort is shared by decision and defensive flags, using the selected model; answers explain the cap (`tests/roles.test.ts`: `astra caps xhigh at high with priority and other models retain their effort`; `tests/team.test.ts`: `authorized Astra dispatch caps pinned and default pairs and permits expert automatic selection`, `reviewer followup falls back to its role default after safe retirement and honors the Astra cap`).
- Invariants: outside Herdr nothing runs and nothing is written (`tests/team.test.ts`: `outside Herdr the tool says it cannot be used and runs nothing, writes nothing`); an `unknown` prompt is never sent again (`tests/herdr.test.ts`: `a prompt the agent was seen taking is confirmed; refused before writing is not_sent; anything else is unknown and never resent`); one writer per directory (`tests/herdr.test.ts`: `one writer per directory: a second developer in the same worktree is refused, and a developer is not moved to another`); the developer never runs in the repository itself and never gets the git directory as a writable root (`tests/team.test.ts`: `the developer is refused without a worktree of its own`, `the developer works in its worktree and may write only there and in the reports, never in the git directory`); a decision record never holds the task text (`tests/team.test.ts`: `the decision is logged as unknown before the prompt and with the outcome after, never with the task text`); errors keep only a Herdr code (`tests/herdr.test.ts`: `errors keep only a Herdr code, never the message text`).
- Finish: accept only logical team names, resolved to effective names in the dispatch workspace with idle/done state and a `herdr:codex` id UUID. Recheck the exact name/pane/workspace and settled state before `herdr pane close <pane>`; protect `HERDR_PANE_ID`. Closing the last task or shared-role pane removes its tab through Herdr, preserving siblings. Ownership and exit checks are workspace-local; a real effective-name collision refuses closure (`tests/finish.test.ts`: `finish resolves logical names and touches only this workspace agent and session`, `finish refuses a real effective name collision even when the local agent is listed first`, `finishing a shared role closes its last current task tab through pane closure`). Poll exit at most ten times with bounded commands and 250 ms pauses; archive only after name and pane disappear. Archive failures keep only an exit code or fixed reason (`tests/finish.test.ts`: `finish refuses working, blocked, unknown, foreign and non-team agents without closing or archiving`, `finish protects the lead pane and requires a verified Codex session uuid`, `finish rechecks exact pane ownership and settled state before any close`, `finish closes only the agent pane and its last task tab, waits for exit, then archives the uuid in order`, `finish preserves sibling panes and reports no tab closure when the task tab has another pane`, `finish reports archive failure without retaining stdout, stderr or thrown text`, `finish bounds exit polling and never archives while the agent or its pane remains live`).
- Session lifecycle: every idle/done predecessor finishes through the tool’s same path before a fresh start; failed finish refuses dispatch. Working/blocked analyst retains its task fallback, architect remains not_sent. Explicit and automatic finish records contain action, logical and effective agent names, UUID, closed, archived and a fixed reason, never task text; use a distinct finish filename so dispatch records cannot overwrite them (`tests/team.test.ts`: `shared idle or done analyst and architect are finished before a fresh start with this dispatch effort`, `a shared finish failure refuses dispatch without starting or prompting a replacement`, `shared working or blocked analyst keeps its task fallback and architect remains busy`, `finish shares the dispatch queue and logs closed and archived without task text`; `tests/register.test.ts`: `session start registers dispatch and finish with their typed input schemas`, `finish closes and archives through the host and logs only lifecycle metadata`).
