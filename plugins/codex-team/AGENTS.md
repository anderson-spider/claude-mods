# codex-team

Usage/privacy: [README.md](README.md). Activation and the lead's workflow: `skills/using-codex-team/SKILL.md`.

- `hooks/register.tsx`: the literal `session.start` registration of `dispatch` (`inputSchema ... satisfies SchemaFor<McpToolInputs[...]>`) and its `tool.call` hook; `teamIo` and `dagrIo` hold injected I/O with literal host calls in the entry module (each `$.env.get` takes a literal name). `hooks/schema.ts`: the type-only `SchemaFor`.
- `hooks/roles.ts`: the role table (`SPECS`: model, effort, whether it writes, instructions), agent names and `codexArgs`. `hooks/report.ts`: the brief and the report path. `hooks/herdr.ts`: `deliver` over an injected runner (task/home tab or split, reuse, one writer per directory, start, prompt and delivery status). `hooks/team.ts`: `dispatch`, the Herdr check, input checks, the developer’s worktree, the small per-root/slug store record and the decision record. `hooks/decisions.ts`: record shape, path and write.
- Reviewer: `role: reviewer`, required slug and optional task focus; recorded developer cwd/original task/report drive the brief. Refuse undispatched slugs and working/blocked developers before mutation; deliver rechecks the developer on its own fresh listing before pane/start/prompt effects. Use `architect-<slug>`, the current `SPECS.architect.model`, fixed xhigh with the existing Astra cap, no Jev/settings, report-only cwd/roots; reuse preserves startup effort (`tests/team.test.ts`: `reviewer refuses an undispatched slug or a working or blocked developer before any effect`, `reviewer builds its brief from the recorded developer task and always uses architect model with xhigh without Jev`, `reviewer without extra task keeps the existing Astra cap and reused startup effort`, `reviewer rechecks done to working or blocked on the delivery listing before pane, startup or prompt effects`). Report fields in `hooks/report.ts`: verdict, risk, findings, checks.
- Developer context: preserve the first task/cwd across followups; another cwd needs another slug. A refused first delivery leaves no context; unknown retains it (`tests/team.test.ts`: `developer followups keep the original task and cannot move the recorded slug to another worktree`, `a developer prompt refused before delivery does not authorize reviewer while an unknown delivery keeps its record`). All dispatch calls use one in-module promise queue, including listing, tab creation, startup, prompt and context access. A failed delivery deletes only the context that call created; a failed call releases the queue (`tests/team.test.ts`: `concurrent developer and fallback analyst dispatches create one task tab without interleaving`, `concurrent shared analyst and architect dispatches create one home tab`, `a concurrent not_sent preserves the first developer task record and only the creator cleans up a refused prompt`, `a failed dispatch does not poison the global queue for a later call`). Decision records still contain only the task hash.
- Names/tabs: slug has at most 22 characters, never truncate (`tests/roles.test.ts`: `task slugs stop at 22 characters without truncation and reviewers use the architect name`). Task agents share `codex · <slug>`, anchored only to a live peer of that slug; shared analyst/architect stay in `codex team`. A busy/blocked shared analyst falls back to analyst-<slug>; no flag. Anchors and reuse require matching workspace_id; a target name live elsewhere is refused without startup or prompt. Never use focus to find an anchor (`tests/herdr.test.ts`: `task tabs anchor only to live agents of the same slug and shared roles stay in the home tab`, `a task without live peers creates its own tab even when other team agents are live`, `a busy or blocked shared analyst falls back to the task analyst and reuses its live pane`, `task and home tabs anchor only inside the dispatch workspace`, `a target name live in another workspace is refused without reuse or startup including analyst fallback names`). Closing stays with the lead’s skill/CLI after user OK, with no plugin close tool.
- Plan projection: `hooks/plan.ts` parses only Steps, headings with work become T1/T2 in order, and validates owners, states, IDs, all dependencies and cycles. A code fence closes only on the same marker with at least the opening length and no trailing text (`tests/plan.test.ts`: `Steps headings with work become ordered deliverables and keep every cross-project dependency and note`, `unknown dependencies, duplicates, cycles, malformed steps, owners and states are validation errors`, `nested and mixed fences close only with the opening marker and enough characters`, `Dispatches and every other section outside Steps are ignored even when they contain step-shaped lines`). `hooks/dagr.ts` builds v3: blocked keeps its note as unblocker, verified/committed use reported receipts, first-seen times survive in times.json under keys containing plan id, step id and state, main/git-master use the orchestrator pane, and Codex workers get only their own live agent pane. Implementing without a locator projects as blocked with the owner named in the unblocker and no attempt, keeping dependencies and notes (`tests/dagr.test.ts`: `Dagr keeps dependencies, blocked unblockers, reported receipts and only live worker locators`, `first-seen timestamps survive repeated projections and plan state changes without mutating the input times`, `plans sharing a step id keep independent first-seen times and reuse only their own observations`, `implementing main and git-master use the orchestrator pane while Codex agents use their own pane`, `implementing without a locator becomes blocked with an owner unblocker, preserving dependencies and notes`). One attempt for implementing with a locator or done; no attempt histories or gates.
- Publishing: `hooks/publish.ts` selects the newest regular plan, serializes per-root candidates, writes run.json.tmp with fs, accepts only strict validator exit 0 and complete [], then mv. Any failure retains the old run and logs one line; a missing dagr logs once per module load. Resolve literal DAGR_BIN, PATH, then the first usable HOME/.config/herdr/plugins/github/herdr-dagr-*/bin/dagr match through injected I/O; environment names and host calls stay literal in register.tsx (`tests/publish.test.ts`: `publishing selects the newest plan, writes a temp file and validates strictly before moving it`, `publication admits implementing lead and git-master and blocks absent workers under the strict locator rule`, `nonzero, empty, malformed, truncated or nonempty validator output never publishes and preserves the old run`, `missing dagr logs once when override, PATH and installed plugin discovery all fail`, `an explicit DAGR_BIN with spaces is passed as one argv element before PATH or discovery`, `dagr installed outside PATH is discovered under HOME without a fixed hash and paths with spaces stay one argument`, `unknown dependency errors are reported and write, list, times or rename failures preserve the previous run`, `publication serializes candidates per root and retains first observations on the next dispatch`). Dispatch publishes after delivery; successful plan Write/Edit hooks await next and return its result unchanged (`tests/team.test.ts`: `dispatch publishes the plan after delivery and uses the actual fallback analyst in its decision`; `tests/register.test.ts`: `successful plan Write and Edit publish after the result and return the host result unchanged`, `failed plan writes and successful unrelated writes do not publish and preserve the result`).
- `hooks/jev.ts` and `hooks/redact.ts`: adapted copies from crew, with injected HTTP/timer/clock, deadline, retry, breaker, concurrency gate and locally hardened redaction; no cross-plugin imports. `hooks/key.ts`: printable key check and project/local `env` declaration refusal. `hooks/effort.ts`: pinned Jev model, concrete score criteria, the single points/weights table, normalized distributions and expected asymmetric penalty (herdr-router's policy and scorer; Sol scope targets are an explicit adaptation). Breaker and gate live across dispatches in `register.tsx`; settings are checked for each unpinned dispatch with a valid key.
- Effort/privacy: literal `$.env.get('JEV_API_KEY')` stays in `register.tsx`; no userConfig key. A project/local declaration or unreadable settings disables Jev (`tests/key.test.ts`: `settings that cannot be read turn Jev off`, `any repository env declaration of JEV_API_KEY is refused`; `tests/team.test.ts`: `project and local key declarations both refuse Jev without any request`). Pinned effort skips Jev and settings (`tests/team.test.ts`: `pinned effort skips Jev and repository settings entirely`). All failures use the role default and a fixed logged reason (`tests/team.test.ts`: `every Jev failure falls back to the role default with only a fixed reason`).
- Assessment: only task text is sent, redacted before the 4000-character cut, key only in Authorization; version-2 records contain the pinned model and rounded expected levels, never task text, key, paths or response bodies (`tests/team.test.ts`: `the request contains only redacted cut task text and the key only in Authorization`, `Jev effort choices reach each role start flag, answer and v2 records`). Score the whole distributions, with cheaper effort winning ties (`tests/effort.test.ts`: `penalty integrates probabilities with asymmetric weights and tolerance, rounding like herdr-router`, `equal penalties keep the cheaper effort`, `probabilities are normalized and malformed dimensions are refused`). Effort flags configure newly started agents; reused live agents keep their startup settings.
- Redaction: scan complete named values in linear time, handling quoted/encoded escapes and EOF truncation before the 4000-character cap; preserve neighboring fields and idempotence. Recognize flag-attached absolute and UNC paths regardless of context (`tests/redact.test.ts`: `long quoted and bare secret values are consumed completely, including truncated values`, `flag-attached absolute paths and UNC paths are redacted without a home or root context`; `tests/team.test.ts`: `fake HTTP receives no long or truncated secret value and no flag-attached or UNC absolute path`). Keep the existing hostile-input performance check.
- Path recognition: separate short option names (`-I`, `-L`, `-isystem`) from their glued arguments and long options at `=`; relative arguments stay intact. UNC needs a host/share shape, not just a backslash run: quoted regex/string escapes survive while real unfinished UNC paths stay masked with linear scanning (`tests/redact.test.ts`: `relative flag paths and quoted escapes stay intact while absolute arguments remain masked`, `unfinished quoted UNC paths are consumed in linear time without leaking their tail`; `tests/team.test.ts`: `fake HTTP preserves relative flag paths and quoted escapes while masking absolute and truncated UNC paths`).
- Application: agents are never restarted to change effort. `effortApplied` is true only when this dispatch started the agent; `beforeSend` receives the actual start state for the pre-prompt record. `Delivery.existed` reports an already-live agent even in refusals; its role line says the chosen effort was not applied (`tests/team.test.ts`: `effortApplied and the role line distinguish newly started and reused agents for every effort source`, `an agent that failed to start never records its chosen effort as applied`, `working and blocked live agents disclose unapplied effort even when dispatch is refused`; `tests/herdr.test.ts`: `beforeSend reports a reused agent as not started before the prompt`, `a busy or blocked agent is not sent anything`).
- Fast: `hooks/roles.ts` owns the model allowlist and explicit Astra exclusion. `gpt-6-luna` and `gpt-6.1-sol` start with `-c service_tier="priority"`; any id containing `astra` and all unlisted models keep their default tier (`tests/roles.test.ts`: `every fast-capable role starts with the priority service tier`, `no role on an astra model receives a service tier`, `a model outside the fast allowlist keeps its default service tier`).
- Astra effort: any model id containing `astra` is capped at `high` after pinned/Jev/default selection. `startEffort` in `hooks/roles.ts` is shared by startup flags and dispatch; the answer explains a cap and records keep the capped effort (`tests/roles.test.ts`: `astra caps xhigh at high without a service tier and other models retain their effort`; `tests/team.test.ts`: `astra dispatch caps pinned, Jev and default efforts in start flags, answers and decision records`). The current role table stays on Luna/Sol.
- Invariants: outside Herdr nothing runs and nothing is written (`tests/team.test.ts`: `outside Herdr the tool says it cannot be used and runs nothing, writes nothing`); an `unknown` prompt is never sent again (`tests/herdr.test.ts`: `a prompt the agent was seen taking is confirmed; refused before writing is not_sent; anything else is unknown and never resent`); one writer per directory (`tests/herdr.test.ts`: `one writer per directory: a second developer in the same worktree is refused, and a developer is not moved to another`); the developer never runs in the repository itself and never gets the git directory as a writable root (`tests/team.test.ts`: `the developer is refused without a worktree of its own`, `the developer works in its worktree and may write only there and in the reports, never in the git directory`); a decision record never holds the task text (`tests/team.test.ts`: `the decision is logged as unknown before the prompt and with the outcome after, never with the task text`); errors keep only a Herdr code (`tests/herdr.test.ts`: `errors keep only a Herdr code, never the message text`).
- Tests mirror modules; `tests/fake-run.ts` scripts `herdr` and `git`, `tests/host.ts` is the host fake.
