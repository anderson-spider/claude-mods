# crew

The main session implements; crew registers three optional read-only helpers (`planner`, `challenger`, `digger`) and their Codex twins. Prompts: `hooks/agents.ts`. Planning workflow: `skills/brainstorm/SKILL.md`. Installation, options and user-visible routing: [README.md](README.md).

## Module map

- `hooks/register.tsx`: host hooks, helper/twin registration, crew mode (`/crew-mode`, type rewrite), Jev routing, effort binding, confirmation and the Write/Edit guard. Keep every `$` call here, in top-level functions; pure modules take injected host access.
- `hooks/agents.ts`: the helpers (`SPECIALISTS`), `CREW_TYPES` and `specialistOf`, tool allowlists, effort floor, the main session's and the twins' prompt sections, gateway gate. `hooks/native.ts`: fixed Codex model map.
- `hooks/guard.ts`: every crew type's Write/Edit is refused (all helpers are read-only); unknown `crew:` types too.
- `hooks/routing.ts`: eligible targets, Jev answers, tags and notices. `hooks/questions.ts`: pinned Jev model/questions and policy thresholds. `hooks/jev.ts`: client, deadline, retry, breaker and in-flight slots.
- `hooks/key.ts`: key validation, settings trust and trusted home. `hooks/redact.ts`: outbound text redaction.
- `hooks/effort.ts`: Claude pending/bound effort book. `hooks/confirm.ts`: requested versus observed model/effort. `hooks/decisions.ts`: v4 record, description hash and injected write.
- `hooks/spawn.ts`: a routed spawn's request (tagged description, twin suffix, apply policy) and the applied effort it resolves to. `hooks/bounded.ts`: capped insertion-order records for the effort book and confirmations.
- `hooks/codex.ts`: Responses API request body, headers and the streamed answer as step chunks. `hooks/codex-login.ts`: the Codex CLI login, read only. `hooks/codex-tools.ts`: the tool schemas crew can send (`Read`, `Glob`, `Grep`: the planner and challenger twins).
- `hooks/appserver.ts`: the link to the crew Codex helper over an injected `Probe` (`post`, `postStarting`, `helperReady`, `runTurn`, `lastUserText`); `register.tsx` builds the probe (`probeOf`), registers the digger twin on the login only when the helper is ready (`reachableNative`, `native.helped`) and keeps `askHelper`, the step of such a twin.
- `helper/`: the helper (Node ESM, LaunchAgent `com.anderson-spider.crew-codex` in `~/.claude/mcp/crew-codex`). `helper.mjs`: socket entry, one `ROUTE_TABLE` entry per route; `lib/engine.mjs`: one `codex app-server`, a thread per agent, start/poll/interrupt/reset, turn limit and time limit; `lib/lanes.mjs`: the role table (`LANES`), the fixed thread and read-only sandbox settings and `refusalFor`; `lib/paths.mjs`: `resolveLane`, the real directory of a lane or the reason it is refused; `lib/rpc.mjs`: JSON-RPC over stdio; `lib/collector.mjs`: what one turn did; `lib/codex-bin.mjs`: the `codex` binary, the isolated home and the server's flags; `lib/version.mjs`.
- `hooks/hud/plan.ts`: pure plan parsing, deliverable grouping and selection. `hooks/hud/view.ts`: pure, width-aware, sanitized band rows from one snapshot (plans, agents, clock, width), built by a `SECTIONS` table with one entry per row kind.
- `hooks/hud/agents.ts`: agent observation (job identity, queued observations, reconcile) over injected `AgentIo`. `hooks/hud/files.ts`: plan file discovery, validation and the single read flight (`missingPlan`) over injected `PlanIo`. `register.tsx` builds both io objects (`agentIo`, `planIo`) and keeps every `on(...)`, atom and `$` call; tests mirror them (`tests/hud-agents.test.ts`, `tests/hud-files.test.ts`).
- `types/index.d.ts`: the `crew.mode` and HUD session state contract.

## Invariants

- The main session implements, tests, reviews its own diff, commits and opens PRs; every helper is optional, read-only and answers only the main session (no `Write`, `Edit` or `Agent` in its tools). There is no developer, architect, auditor or QA role and no required review step. `tests/agents.test.ts` (`no removed role is registered: no developer, architect, auditor, QA, designer, research or code reader`, `every helper is read-only and cannot delegate: no Write, Edit, NotebookEdit or Agent`, `the main session implements and delegation is optional, with no required review step`).
- Models: planner and challenger on Opus, digger on Haiku, all at high effort; twins on fixed ids (`gpt-6-astra` for planner and challenger, `gpt-6-luna` for digger). `tests/agents.test.ts` (`the three helpers run on their models at high effort: planner and challenger on Opus, digger on Haiku`), `tests/native.test.ts` (`the fixed map assigns exactly the three helper roles to their Codex models`).
- Prompt sections are stable per activation and restricted to main-session requests with `Agent`; they read the same in either crew mode; the main section asks for the step id and immediate `state:` updates for the HUD. `tests/agents.test.ts` (`the main section names the step id and updates plan step states immediately for the HUD with static wording`, `the main section never names Codex, and the native section names the codex mode in one fixed sentence`); `tests/register-sections.test.ts` (`the main section reads the same on every request, so the prompt cache holds`); `tests/register-hud.test.ts` (`HUD keeps the prompt sections byte-identical after observation and plan refresh`).
- The crew mode moves only a plain helper call with a registered twin; a call naming a model, a fork, a teammate, a workflow agent and a twin the main session named never move. The session's mode is the `crew.mode` state: the `mode` option at `session.start`, switched by `/crew-mode`, `claude` when unreadable or before any start. A repository-declared `mode`, or unreadable settings, starts the session in claude. `tests/register.test.ts` (`a codex mode that the repository settings declare, or settings that cannot be read, start the session in claude`).
- The HUD groups plan steps under deliverables; `queued`/`blocked` are left, `implementing` runs, `verified`/`committed`/`skipped` are done, any other state is left with `?`. Owners are `main` and the crew types; any other is `?`. It never writes `crew.mode` or the status line. Render reads prepared atoms only; observation of agents is separate from routing, effort and confirmation records and never alters a spawn, step (including the `codexLogin` answer) or tool result. The post-result Write/Edit plan observer is separate from the fail-closed guard and refreshes only successful writes under `.crew/plans/`. `tests/hud-plan.test.ts` (`each known state is counted and skipped is done; running steps retain only id and owner`, `selection orders by file name and hides fully closed and empty plans`), `tests/hud-view.test.ts` (`width-sensitive rows include every running step and agent without truncation`), `tests/register-hud.test.ts` (`HUD observes bypass, routed and twin spawns separately from decision records`, `HUD refreshes plans after successful in-scope Write and never for denies, errors or foreign paths`, `HUD render reads atoms only and yields the band during a survey`).
- Jev sizes effort only, between medium and high; role models and fixed twin models stay unchanged. Any Jev request or config failure explicitly requests the role default (high); an agent past its first sent step keeps its existing effort. Thresholds and literal tag matching: `tests/routing.test.ts` (`the fallback is the role default: high for every helper, medium for a medium-default role`); fallback and config failures: `tests/register-routing.test.ts`.
- Claude effort stays fixed after a sent step to avoid invalidating the host's prompt cache; reload/eviction and the unmatched-running-agent exception remain possible. Identical concurrent spawns with different efforts or apply policies are ambiguous and keep host effort. `tests/effort.test.ts` (`an agent that is not listed at its first step keeps the default: its effort does not change mid-run`, `documented exception: with nothing pending a step is not recorded, so an agent alike with no entry can take a later entry on its next step`).
- Host fetch cannot be aborted: an in-flight Jev slot outlives its deadline. `tests/jev.test.ts` (`a slot is held until the request settles, so a burst against a hanging Jev never exceeds four real calls`).
- V4 `effortApplied` is known request configuration or `null` when a first step prevented binding and configuration is unknown; `applied.effort` flags a change only for known configuration. `tests/decisions.test.ts` (`unknown applied configuration is null and not a claimed change from the default`).
- A twin's suffix is request configuration, not observed execution. Outgoing evidence alone populates `ran.effort`: `tests/confirm.test.ts` (`outgoing model suffix evidence wins over the host effort, without inferring effort from a plan`, `unobserved suffix effort confirms only the model and does not invent an effort mismatch`).
- Twin registration checks the URL (any http/https base other than `api.anthropic.com`), not gateway identity or model availability; unavailable fixed models fail at the call and are never replaced. Reload alone has no `session.start`, leaving the registered set empty. `tests/register.test.ts` (`a fresh activation has no -codex section before session.start`).

## Security and privacy

- Write/Edit guard: every crew helper and twin is read-only, so `deniedWrite` refuses each of their writes, `.crew/` included, and unknown `crew:` types (removed roles included). The role is read from the name after the last colon. Keep `holdUnchecked` fail-closed, never pass through its catch. `tests/guard.test.ts` (`every crew helper and its twin is read-only: each Write/Edit path is refused, .crew/ included`, `unknown crew types, including removed roles and their twins, are denied on every path`), `tests/register-guard.test.ts`.
- Enforcement boundary: Bash is unscreened; the digger's "commands that change nothing" is prompt-level on Claude and enforced by the read-only sandbox on the helper. An agent id absent from the host list is untouched. Browser/MCP access is limited to explicitly named, connected tools; the digger's browser tools read pages only.
- Codex login (`codexLogin`): crew answers a login twin's `turn.step` without `next`, so nothing of it reaches Anthropic. Every failure is the step's answer, never a throw: a skipped hook would send the request itself. Read `~/.codex/auth.json` under the trusted home only; never refresh, write or log it; send the access token only in `Authorization` to `CODEX_URL`. A repository that sets the option or declares `HOME`, or unreadable settings, turn it off. `tests/register.test.ts` (`a step of the twin on the login is answered by crew: nothing goes to the API, the backend gets the conversation and the token in its header only`, `a repository that sets codexLogin, or declares HOME, keeps the twin off the login: without a gateway none registers`), `tests/key.test.ts`, `tests/codex-login.test.ts`.
- Crew Codex helper (the digger twin, `codexLogin` on): the lane is Codex's sandbox, not a prompt. The thread's cwd is the repository and the sandbox is `readOnly` with no network for commands; the settings are fixed in `lib/lanes.mjs` (`approvalPolicy: "never"`, read-only, no network, ephemeral threads) and an approval request that still arrives is refused (`refusalFor`). The cwd is resolved on every start (`lib/paths.mjs` `resolveLane`: real path of an existing directory, never the filesystem root, the home or a parent of it, nor inside or containing `~/.codex`, `~/.claude` or the helper's own directory). A role with no row in `LANES` is refused by the helper and by `HELPER_ROLES`; both lists are pinned to `helper/test/contract.mjs`. The server runs with its own `CODEX_HOME` holding only a link to `~/.codex/auth.json` (`prepareHome` replaces only a link, never a file) and `--disable apps plugins hooks computer_use browser_use` with web search off, on an allowlisted environment (`serverEnv`), so the user's MCP servers and hooks never load. The one exception is the fixed `MCP_SERVERS` table in `lib/codex-bin.mjs` (Context7 by URL, CodeGraph by program), declared with `-c mcp_servers.<name>...` and never read from the user's config; a program that is not found leaves its server out. The Context7 tool is the lane's one network egress (it sends the model's library name and question to `mcp.context7.com`, anonymous: the user's OAuth credentials are not in the isolated home) and CodeGraph runs outside the sandbox, as the user, like the project-config case below. Crew reads and writes no login material on this path, and the helper never logs a prompt or an answer. A repository with a `.codex/config.toml` in or above the lane (up to the home) is refused, because Codex would run its MCP servers outside the sandbox; commands run non-login with the core environment. A failure is the step's answer, never a throw, and where the agent has `SubagentHandback` (in the tool list, or named in the host's own `<system-reminder>`: `handbackOffered`) a final answer, a failure included, is returned as that call. A step the host asks for after that call's result, with no new text, returns the handed-back message and runs nothing (`handedBackMessage`). Replies carry statuses and command names, never command output. Bump `helper/lib/version.mjs` when helper behavior changes; users rerun `install.sh`. `helper/test/lanes.test.mjs` (`the thread never escalates: approvalPolicy never, a read-only sandbox, no network`, `the digger works in the repository; any other role has no lane`), `helper/test/codex-bin.test.mjs` (`the fixed MCP servers are Context7 by URL and CodeGraph by program, and nothing else`, `each resolved server is declared with -c after the shell settings and before the server, and none is the default`), `helper/test/paths.test.mjs` (`the filesystem root, the home and its parents are refused; a directory under the home is fine`, `a repository with a project Codex config, or under a directory that has one, is refused; the home's own is not a project`), `helper/test/engine.test.mjs` (`an interrupt the server never confirms ends the turn after the grace period and drops the thread, so the slot frees`, `a second start for a running caller is busy, and a start past the limit is full`), `tests/register-appserver.test.ts` (`with the helper ready, digger-codex registers on the login beside the planner and challenger twins, with no gateway`, `a step of the digger twin is one turn on the helper: the request, the polls, the text; nothing goes to the API or the backend`, `where the host runs the agent as a subagent the answer goes through SubagentHandback, not as plain text`), `tests/contract.test.ts` (`ROUTES, the roles and the label are the ones the shared contract names`) with `helper/test/contract.test.mjs`.
- Jev key: the sensitive `jevKey` option only, sent only in `Authorization`. Keep errors/logs to status or reason, without key, response body or prompt. `tests/key.test.ts` (`a jevKey that the repository settings declare turns routing off`, `a HOME that the repository settings declare, or a relative one, is not trusted; the key still counts`); `tests/jev.test.ts` (`failures carry a status or a reason and never the key or the response body`).
- Redact secrets, emails and absolute paths before sending descriptions/prompts to Jev; cap the prompt at 4000 characters. With no trusted home, derive redaction's home from the session directory, not repository-supplied `HOME`. `tests/redact.test.ts` and `tests/register-routing.test.ts` (`the prompt reaches Jev redacted and cut: no token, no home path`).
- Decision files store only a description hash, never raw description, prompt, key or path; use the key's trusted home only. FNV-1a is not cryptographic. The host has no delete/append, so files are not pruned. `tests/register-confirm.test.ts` (`the record holds no prompt, description, key or path`); `tests/decisions.test.ts` (`the record is fixed in shape, has an empty outcome and never the description`).
- HUD screen data is allowlisted: only grammar-valid step IDs, allowed owners and roles, allowed model IDs, sanitized plan basenames and headings reach the band; never prompts, descriptions, answers, secrets, paths, URLs or agent IDs. `tests/hud-plan.test.ts` (`hostile file names and headings are redacted, ASCII-only and bounded`, `scheme URLs, hostnames and paths never survive in names or headings`), `tests/hud-view.test.ts` (`untrusted projection and models never reach display`).

## Checks

Run the plugin validation/test and repository consistency checks required by the root AGENTS.md; type-check with `mise exec -- tsc -p plugins/crew/tsconfig.json`. Helper tests: `/Applications/ChatGPT.app/Contents/Resources/cua_node/bin/node --test plugins/crew/helper/test/*.test.mjs`, against a fake `codex app-server` (`helper/test/fake-server.mjs`), never the installed run/state directories or a real Codex. Tests mirror pure modules; `tests/register*.test.ts` exercise host hooks with fake `http.fetch`, without network calls. A new host test imports its world from `tests/host.ts` instead of declaring another; `nativeWorld`, `loginWorld` and the mode and login tests stay in `tests/register.test.ts`; the `agents` fixture the register files share is in `tests/register-world.ts`, and a new register test goes to the file for its concern. For live validation, read [verification and live limits](README.md#verification): fakes do not establish real-account behavior or backend execution.
