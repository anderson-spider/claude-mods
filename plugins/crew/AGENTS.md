# crew

Registers five subagent types in `session.start`, each `crew:<name>` with a default model and effort and a tool allowlist. A `prompt.compose` section (`crew:lead`, from `leadSection` in `agents.ts`) makes the main session the lead that delegates to them in waves (every independent piece in one message, unblocked work relaunched unasked, one line per update on what runs and waits) and counts a step done only after an independent `crew:architect` audit, optionally rerunning tests. The developer self-checks and reports exact commands/output; a failure goes back to the same developer for a fix and another architect audit. The lead section is added only to a request whose tools include `Agent`, which no crew agent has, and it mentions Jev only when routing is on with a valid key. With the `jevKey` option filled in (it is the only switch), Jev (TypeSafe) may move a call's model one step (the architect stays on Opus) and raise its effort to high. With an HTTP loopback `ANTHROPIC_BASE_URL`, each role also gets a fixed-model `crew:<role>-codex` twin (see Native Codex twins). Whenever twins are registered, calls may be routed automatically to OpenAI through the local proxy when Codex has more weekly headroom, with or without Jev (see Quota routing). `jevKey` is the only configurable option.

| Agent | Default model | Tools | Role |
| --- | --- | --- | --- |
| `code-reader` | haiku | Read, Grep, Glob | finds and explains code; returns `path:line` summaries |
| `research` | haiku | Read, Grep, Glob, Edit, Write, WebSearch, WebFetch, Context7, terminal-browser and Claude in Chrome tools | researches docs and the web, browses pages, writes findings and docs |
| `designer` | sonnet | Read, Grep, Glob, Edit, Write, WebSearch, WebFetch, Context7, terminal-browser and Claude in Chrome tools | specifies the UI and edits styles and layout |
| `developer` | sonnet | Read, Grep, Glob, Edit, Write, Bash | implements a spec, runs its tests and reports exact commands/output for the independent architect audit |
| `architect` | opus | Read, Grep, Glob, Write, Bash | plans and reviews; answers with a one-line verdict then the path; writes `.crew/**/*.md` only, never code |

A twin is its base row with a Codex model id and a one-line description; prompt, tools and effort are the base's.

## Layout

```
plugins/crew/
  .claude-plugin/plugin.json
  hooks/hooks.json            points to register.tsx
  hooks/register.tsx          $.agent.register in session.start (the five, then the registered twins: `Native`, `registerNative`), the quota atom and its refresh, the type rewrite of quota routing, the lead's prompt.compose sections (`crew:lead`, and `crew:native-codex` for the registered twins), the Write/Edit guard, the agent.spawn and turn.step hooks of Jev routing
  hooks/quota.ts              pure: Claude and Codex readings, the proxy status request and its secret header, `decide`, `settle`, the `Quota` type
  hooks/agents.ts             SPECIALISTS: name, description, prompt, model, effort, tools; MODEL_FLOORS; EFFORT_FLOOR; leadSection; `Agent<M>` (a specialist is `Agent<Model>`), NATIVE_SUFFIX, isLoopbackBase, nativeCodexSpecs, nativeCodexSection
  hooks/guard.ts              deniedWrite(type, path): the lane of each agent; `laneRole` maps a `-codex` twin to its base role
  hooks/native.ts             `CODEX_MODELS`: the fixed role-to-model map
  hooks/jev.ts                Jev client: one 3 s deadline, one retry, breaker, cap of 4 calls in flight
  hooks/questions.ts          the two questions (tier, reasoning_depth), the pinned Jev model and the thresholds
  hooks/routing.ts            which calls are routable (`Target`: a specialist, or a registered twin with `base`), state for Jev, answers to model and effort, what moved and the notice text
  hooks/effort.ts             pending and bound effort per subagent id; `bind` returns what happened to the effort
  hooks/confirm.ts            first-step check of a routed subagent: what ran (API model id, effort sent) against its tag; `normalizeModel`
  hooks/decisions.ts          decision log: the record (model fields are strings), its file name, FNV-1a hash of the description; the write is injected
  hooks/key.ts                the `jevKey` check and `resolveAccess`: key, trusted home and why routing is off
  hooks/redact.ts             secrets, emails and paths removed from text before it is sent
  skills/brainstorm/SKILL.md  how to plan with the agents
  types/index.d.ts            the quota state under `crew` (named in plugin.json `types`)
  tests/                      a test file per module (`questions.test.ts` only checks the constants), `native.test.ts` for the fixed model map, `quota.test.ts` for `hooks/quota.ts`, and the register tests through the host
```

In the project where the agents run, everything they write lives in an unversioned folder, which the brainstorm skill adds to `.gitignore`:

```
<repo>/.crew/
  plans/<name>.md       the plan the user approves (brainstorm, step 5)
  reviews/<name>.md     the architect's independent reviews
  research/<name>.md    the research agent's findings
```

## Brainstorm flow

`.crew/` ignored (step 0) -> frame -> `code-reader` and `research` in parallel -> options (`designer` first for UI) -> `architect` challenges the leading option -> plan in `.crew/plans/` (each step with its owner, dependencies, files and state, ending in waves of steps that can run together), approved by the user -> recommendation of `/goal` (verifiable end), `/loop` (repeating or waiting work) or direct execution, never started by the skill -> `developer` implements and runs the relevant tests, reporting exact commands/output; `architect` independently audits acceptance (and may rerun tests), run by waves. A failure goes back to the same developer, then the architect reaudits. No edits happen before the approval.

## Jev routing

Off until the `jevKey` option is filled in; no Jev request or trust-settings read is made without it. Twin registration and automatic quota routing do not depend on Jev. On an `agent.spawn` of a `crew:<name>` type from `SPECIALISTS` (or a registered twin, for its effort only), Jev answers one request with a `tier` choice (haiku, sonnet, opus) and a `reasoning_depth` score; the plugin rewrites Claude `model` and, on Claude subagents' `turn.step`s, `effort`. Routed twins instead encode bounded effort in an internal spawn model suffix.

- Jev never rewrites the agent type: each agent keeps its lane and tools. The one rewrite of the type is quota routing's, to the same role's twin (see Quota routing).
- Untouched, with no request: another type, a fork, a workflow script's agent (a hook can only refuse that spawn, so a rewritten model would be ignored: no model, no effort), a call that already names a model (except a Codex twin's defined in the fixed map, which the `agent.spawn` hook denies), no `jevKey` (`enabled` is false from `register` on, so no settings are read), a `jevKey` that is not a valid key (a debug line says so once), a repository that declares `jevKey` in its project or local settings (a debug log line says so once), and repository settings that cannot be read.
- Twins: routable only when registered this activation (`Native.registered`, not the fixed definitions), and then for effort only: the decision's model is the twin's own id and `moved().model` is undefined, so the canonical model never moves whatever the tier answer says. `routeSpawn` internally sends `<registered fixed id>:<bounded effort>`; the suffix does not count as a model-family move. Jev is asked about the base role (`stateOf` sends `base`), and effort follows the base role's rule and thresholds.
- Tier: applied from confidence 0.5, else the default. Model and effort are clamped to the default one step either way; the architect is never below opus (`MODEL_FLOORS`, so its model stays `opus`) and no agent's effort is below medium (`EFFORT_FLOOR`). Effort: depth from 3.0 is high, below it medium, then raised to the floor (so below 3.0 keeps `medium` and only a high depth moves it, to `high`); a depth within 0.01 of 3.0 keeps the default. The thresholds are a declared policy, not a fit: 3.0 on Jev's 0-4 scale keeps `high` for the top band (about 30% of the 126 decisions logged when it was set, against about half at 2.5: a snapshot), and the tier applies from confidence 0.5. The decision log and the debug log are where to revisit them.
- Fail open: no key leaves an explicit twin untouched. An error status, malformed body, timeout, open breaker or fifth concurrent Jev call leaves a Claude call as it came; an explicit twin whose Jev request fails is suffix-configured on its bounded medium default, tagged, announced and recorded (with no Jev answer fields). A quota-switched twin also uses medium when Jev is absent or fails. One 3 s deadline covers both attempts; a retry (429, 5xx, dropped connection) needs one second left.
- Key: the `jevKey` option only, and it is the switch (`checkKey`: a string, trimmed, `/^[\x21-\x7e]{1,512}$/`; empty is off silently, anything else invalid is off with one debug line that never shows the value). `enabled` is computed in `register` from the option, so with no key no settings are read: `prompt.compose` adds the lead section without Jev, `turn.step` rewrites no effort and never awaits the settings, and `agent.spawn` returns at once when no twin is registered. With a twin registered, a keyless `agent.spawn` of a call that may move still reads the quota (up to 1.5 s), may switch the type to the twin, tags the description and confirms the run (see Quota routing). With a key, `resolveAccess` reads the project and local settings once (`$.settings.read`) and turns routing off when they cannot be read or declare `jevKey` under `crew` or `crew@*`. `HOME` (`$.env.get`) is trusted only when those settings do not declare it and it is absolute (redaction applies the same rule to the `~` it strips); when none is trusted, redaction takes `/Users/<name>` or `/home/<name>` from the session's directory (never the repository's `HOME`) so the username and the dashed home still go. A change to `jevKey` reloads the plugin, so the key and the lead section are resolved once per activation, and the effort book, the pending confirmations and the breaker start empty after one: a routed subagent's later steps run on the host's effort until it ends. The key goes only in the `Authorization` header; errors and logs carry a status or a reason, never a body, a key or a prompt.
- Sent: the agent name, the call description and the prompt, with secrets, emails and paths removed, the prompt cut to 4000 characters, to `https://api.typesafe.ai/v1/systemone` with the model `jev-1.13.0`.
- Claude effort book (twins use the suffix and have no entry): every routable Claude call has an entry under its type, description and spawning loop before the spawn continues, holding the default effort when Jev changed nothing or failed, so two calls alike with different efforts leave both on their defaults instead of trading them. A default entry only counts in that rule: it is never applied to a step, so a call that Jev changed nothing on or failed on keeps whatever `effort` the host sends. An unknown `agentId` on `turn.step` reads `$.agent.list()` once and matches it (an entry that names a parent matches only an agent of that parent, when the list gives one). The id is bound when the spawn resolves. Entries stay (64 at most) so a resumed subagent keeps its effort. The step is left alone when `e.effort` is absent. An id's effort never changes once a step has gone out (one exception, below), because a top-level `effort` change between requests invalidates the cached message blocks ([effort](https://platform.claude.com/docs/en/build-with-claude/effort), [prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching); a per-message effort keeps the cache, and the plugin cannot see which way the host sends it); only three cases still change a running subagent's effort and restart its cache: an option change that reloads the plugin (later steps run on the host's effort), the exception below, and a resumed subagent whose entry was evicted after 64. A bind that runs while the list is being read is honored by the step that was waiting. An id that stepped before its effort was known (not listed yet, the list failing, every entry already taken, or ambiguous) keeps its default for its run, while an id stepping with nothing pending is not recorded at all (the one exception to that rule: an already-running agent of the same type and description with no entry of its own, such as one spawned with an explicit model or before `/reload-plugins`, can take a pending entry on its next step), and a bind that finds the id already on the entry's effort reports it as matched; a bind that finds its entry already matched by another agent's step leaves that agent as it is and gives the routed id the effort only if it has not stepped. Ids and entries are bounded by recency: a hit refreshes its place. Ids no list names (a workflow's agents, forks) are never kept in the book beyond the entries that are pending. Verified live: subagents ran on the routed model and on an `effort` above the default (their transcripts carry both).
- Rate limit: the cap of 4 counts requests, not deadlines. `$.http.fetch` cannot be aborted, so a slot stays held until its fetch settles even after the call failed open at the deadline, and for 60 s at most: a fetch that never settles frees its slot then (`SLOT_HOLD_MS`). The Jev model id in the log is kept only when it matches `[\w.:-]{1,64}`.
- Visibility: a routed call's `description` is rewritten to `<description> · <model>/<effort>` (Jev's decision, kept or moved; a Claude call Jev failed on keeps its own; a routed twin falls back to its fixed id/medium; a trailing tag already in the description is stripped first (only a tag the plugin could have written: an alias, or the id of a registered twin, matched literally, so `docs · v2/high` stays), so it is neither sent nor doubled; a kept Claude model is shown although no `model` is passed, the agent's own default being that model; a twin shows its canonical Codex id and requested suffix effort), so the task list shows the choice; the effort book matches that rewritten description, and the decision log hashes the original. An effort that did not take still shows the planned one there; the notice says it was not applied. Once the spawn resolves with an agent id (a refused spawn announces nothing), a `$.ui.notice` per decision and a debug log line with tier, confidence, depth, the effort that was applied (or the default), Jev model id and duration (never the prompt). An effort that was not applied (its entry lost the race to the first step, or was ambiguous) shows the default in the notice with "effort <x> not applied" and gets its own debug line with the outcome.
- Confirmation: the first `turn.step` of a routed subagent that the API answered (`usage` present; a failed step leaves the check for the next) and that ends after its spawn resolved compares the model id the API reported (`usage.model`) and the effort sent with the tag (an alias matches the Claude id that contains it; any other id must equal the planned one after `normalizeModel`, or be its dated release, `-YYYY-MM-DD` or `-YYYYMMDD`, so `gpt-6` does not accept `gpt-6-mini`), and logs one transcript line (`$.ui.log` `to: 'transcript'`; `$.ui.notice` is closed by then): `jev: <description>: confirmed <model> · <effort>` (the host shows it after `crew:`) or `ran <model> · <effort>, not <model>/<effort>`. For a suffix-configured twin, effort comes only from outgoing evidence: its outgoing model suffix takes precedence over the step effort, never the planned suffix or an API-reported suffix. Without outgoing model/effort evidence the line confirms only the model (or reports a genuine model mismatch), says `suffix <effort> requested, effort unobserved`, and keeps `ran.effort: null`. A fallback explicit twin is labeled `crew`, not `jev`; a quota-only switch is labeled `quota`. It then rewrites the decision file with `ran: { model, effort }`, after the spawn's own write, waiting for both about 1 s at most (`settleDecision`) so a hung write cannot hold the step. The line carries the call's description, and like every `$.ui.log` line it also goes to the debug log. Pending checks are kept for 64 agents at most.
- Decision log: with a key set (no option of its own), one JSON file per routed decision in `<trusted home>/.claude/crew/decisions/`, named `<ISO ts with ':' as '-'>-<agent id>.json`, written with `$.fs.write` where the notice is emitted, also when nothing changed (so keeps show), and not for a refused spawn, nor for an untouched call (a quota-switched twin or an explicit twin whose Jev request failed gets a record on its default suffix). The home is the one resolved with the key (`access.home`), never the repository's `HOME`; without one nothing is written and one debug line says so. The record (`v: 2`) has `ts`, `agent`, `requested` (the type the lead asked for), `provider`, `reason` (null unless quota routing decided), `quota` (both providers' readings, or nulls), `tier`, `confidence`, `depth` (these and `jevModel` are null when Jev gave no answer), `defaultModel`, `model` (strings: an alias, or a twin's canonical fixed id without suffix), `defaultEffort`, `effortPlanned`, `effortApplied` (applied request configuration, not observed execution), `bind` (Claude's effort-book outcome or `suffix` only after a twin spawn succeeds with an agent id, default medium included), `jevModel`, `durationMs`, `descriptionHash` (FNV-1a of the description: a non-cryptographic hash that a short, common description can be guessed from), `applied`, `ran` (null until the confirmation rewrites it) and `outcome: null` for hand annotation; never the prompt, the description, the key or a path. For a twin, `applied.model` is false; `applied.effort` is true only when the requested suffix effort differs from its default. `ran.model` is the API-reported id verbatim and `ran.effort` is outgoing evidence or null. The write starts before the notice and is awaited for about 1 s (`$.clock.after`, cancelled when it settles) before the spawn's result returns; it never rejects (a failure is one debug line), and one still pending then is one debug line, "decision write slow", and keeps running, so it cannot change the result or hold it. The host has no delete or append (`$.fs` has read, write, list, exists, stat), so the folder is not pruned: about 400 bytes of JSON, one file each (a disk block on most file systems). Verified live: `$.fs.write` is allowed under the home, outside the project (records are written there); an `fs.*` hook of another plugin may still refuse it, and the failure is only the debug line.

## Native Codex twins

At `session.start`, an HTTP loopback `ANTHROPIC_BASE_URL` enables all five fixed-model twins. A twin is `crew:<role>-codex` (`nativeCodexSpecs`): the base role's prompt, tools and effort on its fixed model id, a one-line description, run by the host as an ordinary subagent through the local proxy. What a twin reads and writes goes to OpenAI through it, including when quota routing chooses the twin automatically without Jev.

| Base role | Fixed Codex model |
| --- | --- |
| code-reader, research | `gpt-6-luna` |
| designer, developer | `gpt-6.1-sol` |
| architect | `gpt-6-astra` |

There is no startup status request, model filtering or secret read. The URL gate does not establish proxy identity or model availability: the proxy must serve these ids; an unavailable model fails at the call rather than being replaced by another model.

- Gate: `session.start` registers the twins only when `$.env.get('ANTHROPIC_BASE_URL')` is an `http:` URL whose host `isLoopbackBase` accepts (127.0.0.0/8, `::1`, `localhost`, in the forms `new URL` normalizes to them; not `https:`, `0.0.0.0`, `::ffff:` forms, a trailing dot or a lookalike name). Otherwise none is registered and one debug line says so. One refused registration leaves the others; its own `try` keeps the session starting.
- Registered set: `Native.registered` is cleared before every `session.start`, then filled by successful registrations. Routing and the `crew:native-codex` section read this set, not the fixed definitions (the `model` refusal below reads the definitions). A twin never registered gets no Jev request and no section. Registration failures use fixed debug phrases, never exception text.
- Section: `crew:native-codex` (`nativeCodexSection`) is its own `prompt.compose` section, under the same `Agent` rule as the lead's; the lead section mentions automatic quota routing while twins are registered. It lists the registered twins, says they are ordinary Agent calls with the base role's tools and write lane (never pass `model` to one), requires an independent architect or registered architect-twin audit for acceptance, and sends failures back to the same developer, including a developer twin.
- Lanes: `laneRole` strips `-codex` when what is left names a specialist, so a twin has its base's lane (`crew:architect-codex` writes Markdown under `.crew/` only). A `crew:` type that is neither a current specialist nor its exact twin has no lane: Write/Edit are held, including stale removed-role types. Another plugin's `<x>:architect-codex` gets the architect lane too; unknown non-crew types remain untouched.
- Jev: effort only, never a model-family change (see Jev routing); crew adds the bounded effort suffix internally to the registered fixed id. Confirmation reads the id the proxy reports with `normalizeModel`: lower case, without `[1m]` or a trailing `-low|medium|high|xhigh` or `:effort`, then equal to the planned id or its dated release.
- Model: the `agent.spawn` hook denies a call to a twin the fixed map defines (`Native.specs`, not the registered set) that passes `model` (the parameter would win over the twin's definition and run it on Claude, untagged and unconfirmed), with a message to call again without it; the section tells the lead the same. It does not depend on registration: a later `session.start` where the env read or a registration fails empties `Native.registered` while the host keeps the types, and an unregistered type is rejected by the host anyway. A base role with `model` is untouched.
- Effective effort: the internal spawn model suffix pins medium or high independently of Claude's effort book and first-step binding. Caller-supplied suffixes are refused. Verified by a real-host spike against a local fake: `gpt-6-luna:medium` and `:high` reached the outgoing subagent request unchanged while `output_config.effort` stayed medium; the host warned about the model but completed the call. The codex-models proxy gives the suffix precedence. Unverified live: multiple turns through the actual crew router and proxy/backend translation; confirmation only claims effort it observes on the outgoing step.
- Reload gap: `/reload-plugins` alone (or a `jevKey` change) reloads crew without establishing twins. `Native.registered` starts empty: quota routing is inactive and the twin section is absent until a new session runs `session.start`.
- The twins are ordinary subagents run by the host; they need no Codex CLI and have no sandbox of their own.

## Quota routing

Automatic whenever twins are registered (`asksCodex`: `Native.registered` not empty), with or without Jev. No twins means no quota refresh. `hooks/quota.ts` is pure (readings, status parsing, `decide`, `settle`); the `$` calls (`refreshQuota`, `noteClaude`, `chooseProvider`) are in `hooks/register.tsx`.

- Readings: Claude's 5-hour and 7-day windows come from `$.session.usage()` and `session.measure` (an empty reading keeps the last non-empty one). Codex's come from `GET /__ccmproxy/status?refresh=limits` (`STATUS_PATH`), sent only when `ANTHROPIC_BASE_URL` is `http:` on a loopback host (`proxyAccess`), with the `X-Ccmproxy-Token` line of `ANTHROPIC_CUSTOM_HEADERS` as the secret, under a 1.5 s deadline. Only that query makes the proxy read the Codex usage from OpenAI (`wham/usage`), and crew sends it only for an eligible spawn with a registered twin, so otherwise nothing new goes to OpenAI. A `codexLimits` absent, empty, malformed or without a 5-hour or 7-day window is `unknown`; a window whose `observedAt` is missing, older than 15 minutes or in the future makes the reading `stale`. A result, failures included, is reused for 60 s; a reading fetched more than 15 minutes ago is `stale`. The first read happens on the first eligible spawn, never at session start. Concurrent callers share one refresh. The host fetch has no no-redirect option; this quota request does not establish redirect safety.
- Decision (`decide`, first match wins; anything uncertain is Claude): not eligible, Codex not fresh, Claude without limits, Codex without a live 7-day window, the 5-hour veto at 90% (a Claude veto sends to Codex only while Codex's 7-day is below 90), then Codex only with its 7-day used at least 10 points below Claude's. A window whose reset has passed counts as unknown. The `reason` has no provider prefix.
- Type rewrite: this is the one place the agent type changes. On a routable call (a specialist, no `model`, no fork, no workflow agent, not a teammate's) whose role has a registered twin (`twinFor`), a `codex` decision rewrites `subagentType` to `crew:<role>-codex`. It comes first in `routeSpawn`: the routable check, Jev's answers, the effort book, the tag and the confirmation read the rewritten type, and Jev (asked about the base role, in parallel with the quota read) sets effort only. A twin the lead named is never moved. A call that stays on Claude logs one debug line with the reason.
- Everything fails open to Claude: no proxy access, a failing or slow status, a malformed body, a Codex reading that is not fresh.
- The `quota` atom (`crew`) holds both readings, `codexState`, the fetch and observation times and the decision. The decision record is `v: 2`: `requested` (the type the lead asked for), `provider`, `reason` and the two readings (`quota`).
- The lead and `crew:native-codex` sections mention quota routing only when it is on with twins registered.
- With a Codex decision the call's work goes to OpenAI through the proxy. The status request initially addresses only the validated loopback proxy; redirect handling belongs to the host.
- Unverified live: the Codex 5-hour veto and the stale-reading rule (the live run, against a local fake Codex, switched and stayed on the 7-day rule only).

## Notes

- `hooks/hooks.json` points only to `hooks/register.tsx`. Every function that takes `$` is declared at the top of that same file; pure modules take host access as injected functions.
- The architect opens its answer with `Approve`, `Fixes` or `Reject` and a one-line reason, so the lead can triage reviews before reading the path and summary.

- `effort` is set on purpose: every agent defaults to `medium` (Opus 5.5 and Haiku 5.5 default to `medium`, Sonnet 5.5 to `high`), and routing may raise it to `high` but never lower it below `medium` (`EFFORT_FLOOR`).
- Prompts say what to do and why, not lists of prohibitions; keep new ones short and test a removal before adding a line.
- `hooks/agents.ts` is pure (`SPECIALISTS`, `MODEL_FLOORS` and the `leadSection` text); `hooks/register.tsx` holds the two `$.agent.register` calls (the five specialists, the twins) and every other `$` call, which it passes to pure modules as injected functions.
- Models are aliases (`haiku`, `sonnet`, `opus`), so they follow the newest model of each family. Routing moves a call between them and never to `fable` or a full id; a twin's Codex id is the one exception to aliases, and routing never moves it.
- `tests/agents.test.ts` checks the table; `tests/register.test.ts` runs `session.start` through the test host.
- Browser and MCP tool names are listed explicitly (no wildcard); one a session does not have connected is unavailable to the agent.
- `hooks/guard.ts` holds the write rules and `register.tsx` enforces them in a `tool.call` hook on `Write` and `Edit`: the architect may write Markdown under `.crew/` only (plans and reviews, unversioned; the brainstorm skill adds `.crew/` to the root `.gitignore` when it is not ignored), and a path with a `..` segment is refused. Unknown `crew:` types have no lane and their Write/Edit calls are held. The hook finds the caller through `e.agentId` and `$.agent.list()`, never blocks the main loop, and holds a subagent whose write it could not check. Its `holdUnchecked` catch is fail-closed; never replace it with a pass-through catch.
- Not enforced, prompt only: the designer leaves logic and tests alone, and `Bash` is not screened for writes, including on stale host definitions of removed roles. An agent id that the list does not name is left untouched, as before.
- `skills/brainstorm/SKILL.md` tells Claude how to plan with these agents (frame, gather in parallel, diverge, challenge with `architect`, plan); keep its agent names in step with `hooks/agents.ts`.
