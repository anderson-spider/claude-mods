# crew

Agent prompts and delegation: `hooks/agents.ts`. Planning workflow: read `skills/brainstorm/SKILL.md` when changing planning or executing a plan. Installation, options and user-visible routing: [README.md](README.md).

## Module map

- `hooks/register.tsx`: host hooks, specialist/twin registration, crew mode (`/crew-mode`, type rewrite), Jev routing, effort binding, confirmation and Write/Edit guard. Keep every `$` call here, in top-level functions; pure modules take injected host access.
- `hooks/agents.ts`: specialists, their `LANES`, `CREW_TYPES` and `specialistOf`, tool allowlists, effort floor, lead and twin prompt sections, gateway gate. `hooks/native.ts`: fixed Codex model map.
- `hooks/routing.ts`: eligible targets, Jev answers, tags and notices. `hooks/questions.ts`: pinned Jev model/questions and policy thresholds. `hooks/jev.ts`: client, deadline, retry, breaker and in-flight slots.
- `hooks/key.ts`: key validation, settings trust and trusted home. `hooks/redact.ts`: outbound text redaction.
- `hooks/effort.ts`: Claude pending/bound effort book. `hooks/confirm.ts`: requested versus observed model/effort. `hooks/decisions.ts`: v4 record, description hash and injected write.
- `hooks/codex.ts`: Responses API request body, headers and the streamed answer as step chunks. `hooks/codex-login.ts`: the Codex CLI login, read only. `hooks/codex-tools.ts`: the tool schemas crew can send.
- `hooks/hud/plan.ts`: pure plan parsing, deliverable grouping and selection. `hooks/hud/view.ts`: pure, width-aware, sanitized band rows from plan, agents and clock snapshots.
- `types/index.d.ts`: the `crew.mode` and HUD session state contract.

## Invariants

- Preserve the architect's first-word verdict (`Approve`, `Fixes`, `Reject`) for review triage. Prompt contracts, role defaults and tool lanes: `tests/agents.test.ts` (`the architect opens with a verdict word and the lead asks for the step id in descriptions`, `independent acceptance is the architect audit, not the developer self-check or a different family`).
- Prompt sections are stable per activation and restricted to lead requests with `Agent`; they read the same in either crew mode; the lead tells the plan owner to update `state:` immediately for the HUD (`tests/agents.test.ts`: `the lead updates plan step states immediately for the HUD with static wording`). Conditional Jev wording and successful registrations: `tests/register.test.ts` (`the lead section reads the same on every request, so the prompt cache holds`, `HUD keeps the prompt sections byte-identical after observation and plan refresh`); the fixed codex-mode sentence: `tests/agents.test.ts` (`the lead section never names Codex, and the native section names the codex mode in one fixed sentence`).
- The crew mode moves only a plain specialist call with a registered twin; a call naming a model, a fork, a teammate, a workflow agent and a twin the lead named never move. The session's mode is the `crew.mode` state: the `mode` option at `session.start`, switched by `/crew-mode`, `claude` when unreadable or before any start. A repository-declared `mode`, or unreadable settings, starts the session in claude. `tests/register.test.ts` (`in the codex mode calls that may not move are untouched: explicit model, fork, workflow agent, teammate, a twin the lead named, another plugin's type`, `a codex mode that the repository settings declare, or settings that cannot be read, start the session in claude`).
- The HUD groups plan steps under deliverables, counts `skipped` as done and shows every running step and agent. It never writes `crew.mode` or the status line. Render reads prepared atoms only, never filesystem or network; observation of agents is separate from routing, effort and confirmation records and never alters a spawn, step (including the `codexLogin` answer) or tool result. The post-result Write/Edit plan observer is separate from the fail-closed guard and refreshes only successful writes under `.crew/plans/`. Pinning tests: `tests/hud-plan.test.ts` (`each known state is counted and skipped is done; running steps retain only id and owner`, `selection orders by file name and hides fully closed and empty plans`), `tests/hud-view.test.ts` (`width-sensitive rows include every running step and agent without truncation`), `tests/register.test.ts` (`HUD observes bypass, routed and twin spawns separately from decision records`, `HUD refreshes plans after successful in-scope Write and never for denies, errors or foreign paths`, `HUD render reads atoms only and yields the band during a survey`).
- The architect audit is the acceptance; a separate reproduction (fresh `crew:developer` or the project's live-test procedure) is only for auth, routing or live checks, and the step closes after it passes. `tests/agents.test.ts` (`independent acceptance is the architect audit, not the developer self-check or a different family`).
- Jev sizes effort only; Claude role defaults and fixed twin models stay unchanged. Any Jev request or config failure explicitly requests `medium`; an agent past its first sent step keeps its existing effort. Effort floor, thresholds and literal tag matching: `tests/routing.test.ts`; fallback and config failures: `tests/register.test.ts`; fixed twins: `tests/native.test.ts` (`the fixed map assigns exactly the five specialist roles to their Codex models`).
- Claude effort stays fixed after a sent step to avoid invalidating the host's prompt cache; reload/eviction and the unmatched-running-agent exception remain possible. Identical concurrent spawns with different efforts or apply policies are ambiguous and keep host effort. Races and ambiguity: `tests/effort.test.ts` (`an agent that is not listed at its first step keeps the default: its effort does not change mid-run`, `documented exception: with nothing pending a step is not recorded, so an agent alike with no entry can take a later entry on its next step`).
- Host fetch cannot be aborted: an in-flight Jev slot outlives its deadline. `tests/jev.test.ts` (`a slot is held until the request settles, so a burst against a hanging Jev never exceeds four real calls`).
- V4 `effortApplied` is known request configuration or `null` when a first step prevented binding and configuration is unknown; `applied.effort` flags a change only for known configuration. Schema: `tests/decisions.test.ts` (`unknown applied configuration is null and not a claimed change from the default`).
- A twin's suffix is request configuration, not observed execution. Outgoing evidence alone populates `ran.effort`: `tests/confirm.test.ts` (`outgoing model suffix evidence wins over the host effort, without inferring effort from a plan`, `unobserved suffix effort confirms only the model and does not invent an effort mismatch`).
- Twin registration checks the URL (any http/https base other than `api.anthropic.com`), not gateway identity or model availability; unavailable fixed models fail at the call. Reload alone has no `session.start`, leaving the registered set empty. `tests/register.test.ts` (`a fresh activation has no -codex section before session.start`).

## Security and privacy

- Codex login (`codexLogin`): crew answers a login twin's `turn.step` without `next`, so nothing of it reaches Anthropic. Every failure is the step's answer, never a throw: a skipped hook would send the request itself. Read `~/.codex/auth.json` under the trusted home only; never refresh, write or log it; send the access token only in `Authorization` to `CODEX_URL`. A repository that sets the option or declares `HOME`, or unreadable settings, turn it off. `tests/register.test.ts` (`a step of the twin on the login is answered by crew: nothing goes to the API, the backend gets the conversation and the token in its header only`, `a repository that sets codexLogin, or declares HOME, keeps the twin off the login: without a gateway none registers`), `tests/key.test.ts`, `tests/codex-login.test.ts`.
- Jev key: the sensitive `jevKey` option only, sent only in `Authorization`. Keep errors/logs to status or reason, without key, response body or prompt. Trust checks: `tests/key.test.ts` (`a jevKey that the repository settings declare turns routing off`, `a HOME that the repository settings declare, or a relative one, is not trusted; the key still counts`); failures: `tests/jev.test.ts` (`failures carry a status or a reason and never the key or the response body`).
- Redact secrets, emails and absolute paths before sending descriptions/prompts to Jev; cap the prompt at 4000 characters. With no trusted home, derive redaction's home from the session directory, not repository-supplied `HOME`. Coverage: `tests/redact.test.ts` and `tests/register.test.ts` (`the prompt reaches Jev redacted and cut: no token, no home path`).
- Decision files store only a description hash, never raw description, prompt, key or path; use the key's trusted home only. FNV-1a is not cryptographic: common descriptions can be guessed. The host has no delete/append, so files are not pruned. `tests/register.test.ts` (`the record holds no prompt, description, key or path`); schema: `tests/decisions.test.ts` (`the record is fixed in shape, has an empty outcome and never the description`).
- HUD screen data is allowlisted: only grammar-valid step IDs, allowed owners and roles, allowed model IDs, sanitized plan basenames and headings reach the band; never display prompts, descriptions, answers, secrets, paths, URLs or agent IDs. Coverage: `tests/hud-plan.test.ts` (`hostile file names and headings are redacted, ASCII-only and bounded`, `scheme URLs, hostnames and paths never survive in names or headings`), `tests/hud-view.test.ts` (`untrusted projection and models never reach display`).
- Write/Edit allowlist: architect Markdown under `.crew/` only, same lane for its twin; unknown `crew:` types and unchecked writes are held. `hooks/agents.ts` holds a role's lane in `LANES` (exhaustive over the specialists, so a role without one fails `tsc`) and derives `CREW_TYPES`; `guard.ts`, routing and the HUD read them, and a new lane needs its rule in `LANE_RULES`. Keep the lane out of the specialist definitions: they are spread into `$.agent.register`, and the host would see the field. Keep `holdUnchecked` fail-closed, never pass through its catch. `tests/guard.test.ts` (`unknown crew types, including removed roles and their twins, are denied on every path`) and the host guard tests in `tests/register.test.ts`.
- Enforcement boundary: Bash writes are unscreened; designer/research source-code boundaries are prompt-only. An agent id absent from the host list is untouched. Browser/MCP access is limited to explicitly named, connected tools.
