# codex-models

Offers OpenAI Codex models (ChatGPT login) in Claude Code through a local proxy. Claude Code reaches it with `ANTHROPIC_BASE_URL`; the proxy sends Codex model ids to the Codex backend and everything else to api.anthropic.com unchanged. `/model` rows come from `modelPicker` in `~/.claude/settings.json`; a subagent reaches Codex through an agent definition (`model: gpt-6-astra`); the crew's `nativeCodex` option registers `crew:<role>-codex` types on top. A plugin cannot set env or model settings, so `install.sh` writes them.

## Layout

- `hooks/register.tsx`: the one hooks module. The `session.start` check (observes only, never blocks the start) and `command.run` for `/codex-models:status`.
- `hooks/status.ts`: pure; the network and timer are injected. Probe, reply reading, notice and report texts.
- `commands/status.md`: only the fallback body of `/codex-models:status`; the `command.run` hook answers it.
- `install.sh`, `uninstall.sh`: macOS LaunchAgent `com.anderson-spider.codex-models`. Both are copied with `install/` to `~/.claude/codex-models/`, so they run with the plugin gone or updated.
- `install/settings.mjs`: pure merge and unmerge of settings.json, status-reply reading, masking. `install/cli.mjs`: the I/O (`version-of`, `precheck`, `preflight`, `merge`, `unmerge`).
- `proxy/`: ccmproxy, entirely our own Go code (module `github.com/anderson-spider/claude-mods/plugins/codex-models/proxy`; the standard library only, `go.mod` has no `require` and `go.sum` is empty but kept for CI's cache path).
  - `cmd/ccmproxy`: `serve`, `login`, `logout`, `status`, `models [--settings-json | --json]`, `env [--shell]`, `config init`, `version`.
  - `internal/config`: the config schema, defaults, refusals, file mode.
  - `internal/proxy`: the loopback listener.
  - `internal/router`: `guard.go` (entry middleware), `router.go` (dispatch), `messages.go` (Messages and `count_tokens`), `request.go` (the request head), `passthrough.go`, `status.go`, `codex.go` (Codex path, error mapping), `keepalive.go` (pings on a silent stream), `models.go`, `body.go` (request decoding).
  - `internal/translate`: Anthropic Messages to Responses and back (`claude_to_codex`, `codex_to_claude`, `assemble`, `sanitize`).
  - `internal/codex`: the ChatGPT login (`oauth`, `login`, `store`, `authfile`, `layout`), the Responses client, the model catalog (`catalog.go`), the Codex rate-limit windows (`limits.go`, `usage.go`).
  - `internal/netx`: the one outbound transport. `internal/httplog`: request logging. `internal/logx`: leveled logger. `internal/tokenize`: the local `count_tokens` estimate. `internal/jsonread`: the JSON reading rules router and translate share. `internal/jsontest`: test-only JSON helpers (gjson-compatible path reads).
  - `contract/`: the black-box contract suite (see Contract suite).
- `types/index.d.ts`, `tsconfig.json`, `tests/`.
- The Go version is pinned once, in the root `mise.toml`; `install.sh` names the same versions (`GO_VERSION`, `NODE_VERSION`) and `tests/scripts/install.test.mjs` checks they agree.

## Proxy invariants

- Listener: one plain HTTP listener on a literal loopback address (127/8 or `::1`) with an explicit port, random at install; `:port`, `0.0.0.0`, `[::]` and names are refused, and the bound socket is checked again. No CA, CONNECT, TLS listener, hosts redirect or DNS resolver.
- Upstream: `upstream` is only `https://api.anthropic.com`; `codex.base_url` must be `https://`. `serve` refuses to start when the upstream resolves to loopback.
- Guard (before the router): the `X-Ccmproxy-Token` header is read and deleted before anything else runs, so no outbound path can copy it; compared by SHA-256 digest in constant time; a miss is 403 `permission_error`, never 401 (a 401 makes Claude Code refresh OAuth and ask for `/login`). `Host` must be the listen address. Only GET, POST and HEAD are served, with or without the secret (OPTIONS, CONNECT, TRACE and the rest are 403). `HEAD /api/hello` (Claude Code's start probe, sent with neither secret nor bearer) is answered locally with an empty 200. No `Access-Control-*` header is ever sent. The secret keeps out other local processes and web pages, not malware running as the user.
- Residual risk: the proxy assumes a single-user Mac. While it is down, another local user can bind its port and would receive the secret header and the Claude OAuth bearer from Claude Code. The LaunchAgent's `KeepAlive` (restart unless it exited cleanly, throttled to 30 s) keeps it holding the port; the proxy side cannot close this.
- `GET /__ccmproxy/status` (behind the secret) answers `{"service":"ccmproxy","version","codexLogin":bool,"models":[ids],"codexLimits":[…]}`. `ccmproxy models --json` prints `[{"id","label","description","behavesAs"}]`. `ccmproxy env --shell json` prints `ANTHROPIC_BASE_URL`, `ANTHROPIC_CUSTOM_HEADERS` (one `X-Ccmproxy-Token` line) and `ENABLE_TOOL_SEARCH=true`. The installer and the hooks read these contracts.
- Transports: `Proxy: nil` on every outbound transport (`netx.DirectTransport`), so `HTTPS_PROXY` and the like are never used; a nil transport never falls back to the environment's proxy.
- Redirects: never followed by the token endpoint client, the Responses backend, the router's `/v1/models` client or the passthrough `ReverseProxy`, since each would resend a token. A 3xx from Codex is an error naming the status; one from Anthropic goes back to Claude Code as it came.
- Errors: a Codex failure maps to Anthropic's error types (400/422 `invalid_request_error`, 403 `permission_error`, 404 `not_found_error`, 413 `request_too_large`, 429 `rate_limit_error`, 529 `overloaded_error`, else `api_error`). A Codex 401 and every login problem (`ErrNotAuthenticated`, `ErrCodexCLILoginExpired`, `ErrLoginExpired`) reach Claude Code as 403 with the fix named, never 401. A stream that ends without its terminal event is an error (an SSE `error` event, or 502 when not streaming), never a truncated success.
- Answers: `message_start.model` is the model the upstream reported in `response.created`, falling back to the resolved id. A `tool_use` block is emitted only once its call is complete, its input in one `input_json_delta` (SSE) or as the block's `input` (JSON); a call cut off by max output tokens, or whose arguments are not a JSON object, is dropped, and `stop_reason` is `max_tokens` whenever the output ran out, even after a finished call; a finished call whose arguments are not a JSON object logs one warning with the tool name and the arguments' byte length, never the arguments. A streamed answer gets a `ping` event after 10 s with nothing written (`sseWriter`, `internal/router/keepalive.go`), only while the message is open (after `message_start`, before `message_stop` or an error), written under the same lock as the frames, and stopped on every exit and when the client goes away.
- Effort precedence: a model-name suffix (`-high`, `:high`) wins; else the request's `output_config.effort` (Claude Code's `/effort`, also sent for an unknown id); else `thinking` (`budget_tokens` by size; `adaptive` or `auto` gives `xhigh`, `disabled` gives `low`); else the model's default. Clamped to the real model's levels.
- `Session_id` is an HMAC-SHA-256 of `metadata.user_id` keyed by the config's `session_salt`, shaped as a v4 UUID.
- Codex login: the proxy's own file under `auth_dir` is the default. `~/.codex/auth.json` is used only with `codex.use_codex_cli_auth: true`, read-only: never refreshed, written or removed (`logout` removes only the proxy's own file); an `auth_file` resolving to it (directly, by symlink, `..` or case) is refused. The proxy's own login is written atomically (temp file, sync, chmod 0600, rename; `auth_dir` 0700) under two exclusive `flock`s, always taken in this order and released in reverse on every path: the legacy `<auth_dir>/codex.lock` (`legacyLockPath`; the one earlier releases took, so an older binary on the same file is excluded; drop it once none can run), then `<credential file>.lock`, beside the file the store writes after resolving symlinks, or only its directory when the file does not exist yet, and making it absolute (`lockPath`, `writeTarget`; default `<auth_dir>/codex.json.lock`, with `auth_file` next to that file), so stores on one file share the lock whatever their `auth_dir` or symlink path (when the two are one file, it is taken once); re-read under the locks before a refresh. A rejected refresh is `ErrLoginExpired`, which answers 403. The login callback answers a non-GET with 405 and a missing or wrong `state` (compared in constant time) with 400, and neither ends the login.
- Logs carry method, path, status, sizes and duration, never a query string, a secret, a token or a prompt. A Codex error is logged as its status and its `error.type`/`error.code` only when identifier-like, never its message or body; the client gets the message with control characters and runs of space collapsed, capped at 300 characters (`translate.CleanMessage`).
- Config (`$CCMPROXY_HOME/config.json`): `listen_http`, `upstream`, `auth_token`, `session_salt`, `auth_dir`, `log_level` and the `codex` block (`base_url`, `user_agent`, `originator`, `models`, `effort_variants`, `model_prefix`, `callback_port`, `auth_file`, `use_codex_cli_auth`). The file is mode 0600 in a 0700 directory and loading refuses a looser one; `serve` refuses to start without `auth_token` or `session_salt`; `config init` keeps every existing value, unknown keys included, and adds only the missing secrets. Removed keys (`listen_proxy`, `listen_tls`, `intercept_hosts`, `proxy_username`, `proxy_password`, `ca_dir`, `dns`) are refused by name; a case variant of one is told to be deleted, not renamed. A key that matches a known key only case-insensitively is refused, naming the known key, and `config init` refuses it too.
- Catalog: mirrors `codex debug models` (visibility `list`). `gpt-daybreak-blue-latest` is offered only through `codex.models`, which then restricts the catalog to the ids it names. Each row has `behavesAs` (a Claude model the installed Claude Code knows; without it the row is not offered).
- `count_tokens` for a Codex model is a local conservative estimate; thinking blocks the proxy issued are stripped from requests that go to Anthropic.
- Request parsing: routing reads the body the way translation does (last duplicate key wins, keys matched case-insensitively). A readable body that is not valid JSON gets a local 400 `ccmproxy: request body is not valid JSON` on `/v1/messages` and `count_tokens`. A content-coding the proxy cannot undo still passes through; valid JSON that is not an object passes through.
- Message stream: `message_start` always comes before any content block.
- Logging and transport: an informational 1xx (except 101) passes through to the client. An outbound error's logged text has the URL's query and userinfo cut, and the model-list failure log carries no query.
- Explicit `auth_file` in the Codex CLI layout: the file ends in one newline and is written with two-space indentation; missing token keys are added in a fixed order; a prior file that is not a JSON object starts from the skeleton; a corrupt explicit `auth_file` is rewritten in the native layout on login.
- Shutdown: one path, in `cmd/ccmproxy`. `serve` stops taking connections, drains for up to 5 s on SIGTERM or SIGINT, then closes what is left and exits 0; a second signal during the drain is ignored.
- `ccmproxy --help`, `-help` and `-h` print the usage and exit 0. `version` prints a `  revision <vcs.revision>` line when the build info has one; a contract build also prints `  build    contract (test injection points on; not for installation)`.
- Status login: a status never waits on a token refresh. `Authenticated()` reads the disk when the store is free and answers the last known login when it is busy.
- Status limits: `codexLimits` is always present, `[]` with no reading, else `[{kind, percentUsed, resetsAt?, windowMinutes, observedAt}]` (`kind` is `five_hour`, `seven_day`, or `window_<minutes>m` for any other length, e.g. `window_60m`). The latest reading per window comes from the `x-codex-*` headers on every Codex answer, a 429 included. A plain status never calls OpenAI. `?refresh=limits` (sent only by crew's quota routing; any other value is a plain status) may read the unofficial `wham/usage` endpoint when there is no reading or the oldest one is more than 5 min old: one request at a time, at most one per 5 min whether it succeeds or not, with the token already held (never a refresh), no redirect followed, and the status waits at most 1 s for it. When the held token is within 5 min of expiry and the proxy is idle, `?refresh=limits` reads nothing until a Codex request refreshes the token.
- Byte-for-byte contracts (the contract suite and the tests pin them; change none without changing its reader):
  - the names `ccmproxy`, `X-Ccmproxy-Token` and `CCMPROXY_HOME`;
  - the `ccmproxy:` prefix of the proxy's own error messages and the literal `unexpected Host header`, which `hooks/status.ts` and `install/settings.mjs` match to tell this proxy's reply from another;
  - the `ccmp1:` marker on a thinking block's signature (`ccmp1:<encrypted_content>`), persisted in transcripts, so an old transcript must still resume;
  - tool names shortened to at most 64 characters, with the same cut and de-duplication;
  - the rejected-refresh latch: a rejected refresh is `ErrLoginExpired` (answered 403) and is not retried until the credential file or the refresh token changes, or a new login is saved; until then an access token that is still valid keeps being served;
  - the legacy lock and the lock order, so an old and a new binary coexist during an upgrade;
  - the four `env` shells (posix, fish, powershell, json) and `env --shell json`, which the installer reads;
  - `-X main.version` and the `vcs.revision` line of `version`;
  - the Codex backend headers, unchanged: a Responses call sets `Content-Type`, `Authorization`, `Accept: text/event-stream`, `Connection: Keep-Alive`, `User-Agent`, `Originator`, `Chatgpt-Account-Id` and `Session_id`. `User-Agent` and `Originator` come from `codex.user_agent` and `codex.originator` (when empty or unset, `Originator` is `codex-tui` and `User-Agent` is the Codex TUI string in `config.go`, `defaultUserAgent`); `Chatgpt-Account-Id` is sent only when the login has an account id. The `wham/usage` read sends `Authorization`, `Accept: application/json`, `User-Agent`, `Originator` and `Chatgpt-Account-Id` (same rule), with no `Session_id`.
- Accepted translation behavior: invalid UTF-8 in a request bound for Codex becomes U+FFFD (the Anthropic passthrough is untouched); an object where the Messages API has an array is not iterated; a tool schema (`parameters`) and an assembled `tool_use.input` are compacted, keeping key order and number spelling, while request `arguments` and streamed `partial_json` stay verbatim. `httplog` sizes use units `Kb`, `Mb`, `Gb` and `Tb` and step to the next unit at 1024 (`1Mb`, not `1024Kb`); the ceiling is `Tb`, and no size panics, 1 PiB and up included.
- Injection points: a test seam exists only in a `contract_on.go` file under `//go:build contract` (`CCMPROXY_CONTRACT_*` variables, hooks), with a `contract_off.go` default that does nothing. Each package with a seam has a default-build test that asserts inertness through the public API, and the default binary holds no `CCMPROXY_CONTRACT` string. `install.sh` builds with `env GOFLAGS=-tags= GOTOOLCHAIN=local` (`GOTOOLCHAIN=local` keeps a `go env -w GOTOOLCHAIN` from swapping the pinned Go; an empty `GOFLAGS` is read as unset and falls back to one saved with `go env -w`; `-tags=` clears any tags).
- macOS and Linux only (the credential lock uses `flock`); `install.sh` is macOS only.

## Installer invariants

- Order: `precheck` (settings readable and mergeable; a foreign `ANTHROPIC_BASE_URL`, a malformed `env`, `modelPicker` or headers refused) before any build, copy, plist or `launchctl`; then build, config init, LaunchAgent, then `preflight` against the running proxy (403 without the secret, 200 on `HEAD /api/hello`, status 200 with it, `service` `ccmproxy`, version equal to the plugin's), and only then the settings write. A proxy that is down or not ours is never pointed at.
- The settings write adds exactly: `env.ANTHROPIC_BASE_URL`, one `X-Ccmproxy-Token` line in `env.ANTHROPIC_CUSTOM_HEADERS` (other lines kept), `env.ENABLE_TOOL_SEARCH=true` (also over a `false` already there; the state keeps the old value and uninstall puts it back), and `modelPicker.options` rows whose description ends with `(codex-models)`. `pluginConfigs` and everything else stay. Picker rows keep `behavesAs` from `models --json`. Written atomically (a temp file created mode 600 beside the symlink-resolved target, then renamed over it, refused if the file changed since it was read), after a timestamped backup beside it (`settings.json.bak-codex-models-<stamp>`); no backup when nothing changes. Each install or uninstall that changes the file leaves a new backup, which can hold the `X-Ccmproxy-Token` line; none is ever removed, `--purge` included.
- Mode 600: settings.json, the state file and every backup are written 0600 (install leaves a 0644 settings.json at 0600, uninstall keeps it there; an unchanged file and the user's earlier backups are restricted too). A file owned by another user is refused before any change (`ownerRefusal`).
- `~/.claude/codex-models/settings-state.json` records what stood there before (no header value) so uninstall takes back only what install added; it keeps a history of base URLs (`baseUrls`, the last 10, written before the settings) and uninstall removes `ANTHROPIC_BASE_URL` when it is any of them, or a loopback URL carrying the `X-Ccmproxy-Token` header; `fileCreated` makes uninstall remove a settings.json that install created once nothing else is left in it. A second install changes nothing and keeps the first state.
- Uninstall order: settings first, then the LaunchAgent; if the settings cannot be put back, the LaunchAgent stays loaded. `--purge` also deletes `~/.claude/codex-models` (login, config, binary, scripts); without it the login and config stay.
- The secret never appears in a process's argv, in output (dry runs mask every `X-Ccmproxy-Token` value), in the plist, in the state file or in a backup's name.
- `install.sh --check` changes nothing; `--dry-run` prints the masked settings diff; `--no-settings` does everything but the settings edit.

## Hooks

- `session.start` probes `GET /__ccmproxy/status` only when the session's `ANTHROPIC_BASE_URL` is `http://` on a loopback host with no path, sending the secret from `ANTHROPIC_CUSTOM_HEADERS`, under a 1.5 s deadline on the host's clock. Any other base URL sends nothing. A failing probe or filesystem never blocks the start.
- A notice names the case (down, timeout, wrong secret, not ccmproxy, stale version, no Codex login, no secret) and `~/.claude/codex-models/uninstall.sh`. `ui.notice` needs a `tool_use` id, so the notice is a transcript `ui.log` line plus a `ui.toast`. A reply body is never quoted, and no secret appears in a notice, log or report.
- `/codex-models:status` reports reachability, identity, version against the plugin's, login, models and which settings are in place, using the session's secret first and ccmproxy's config as fallback.

## Tests

- `claude plugin test plugins/codex-models`: `tests/status.test.ts` (pure), `tests/settings.test.ts` (pure merge), `tests/register.test.ts` (hooks through the test host with a fake `http.fetch`).
- `go -C plugins/codex-models/proxy test ./...` (add `-race`): config, listeners, guard, router, translation, login and store, catalog, limits, transports. No network.
- `go -C plugins/codex-models/proxy test -race -tags contract ./...`: also the contract suite in `proxy/contract/`, which builds the binary with `-tags contract` and drives it as a subprocess against local fakes of Anthropic, Codex and the token endpoint. It imports no proxy package. CI runs it. Under `CI`, the contract test of the `version` revision line fails when the suite binary has no `vcs.revision`. Goldens are re-recorded one test at a time, only those `proxy/contract/README.md` lists as re-recordable.
- `node --test plugins/codex-models/tests/scripts/*.test.mjs`: `install.sh` and `uninstall.sh` against a temporary HOME with a fake `launchctl` and `mise`.
- Also `claude plugin validate plugins/codex-models`, `node scripts/check-consistency.mjs`, `node scripts/check-version-bump.mjs origin/main`, `tsc -p plugins/codex-models/tsconfig.json`.

## Known gaps

- Changing the crew's `nativeCodex` option reloads the crew without a `session.start`, so the `crew:<role>-codex` types are registered only from the next session.

## Unverified live

- A new session lists the Codex rows in `/model` and stays on Claude.
- The `wham/usage` field names (`rate_limit.primary_window` and `secondary_window` with `used_percent`, `limit_window_seconds`, `reset_at` or `reset_after_seconds`) come from a third-party report, not from OpenAI; the parser skips what it cannot read.
- The status during a real token refresh and a real `?refresh=limits` against OpenAI.
- `crew:developer-codex` answers from Codex over several turns: thinking blocks survive across turns (a config flag echoing the requested id is the fallback if not) and the effort is the one Jev sized.
- `crew:tester-codex` writing outside its lane is denied.
- Proxy stopped, wrong secret and another app on the port each give their notice at session start.
- The crew's confirmation of a routed `-codex` spawn accepts the planned id or its dated release (a trailing `-YYYY-MM-DD` or `-YYYYMMDD`), but an id with the effort before the date (`gpt-6-astra-high-2026-05-01`) would read as a mismatch.
- Uninstall restores the settings (semantically equal; a hand-formatted file comes back as 2-space JSON).
